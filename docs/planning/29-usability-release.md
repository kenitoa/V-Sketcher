## 변경한 제품과 보호 경계

제품 안내의 단일 내용은 `packages/user-guide`다. 홈 경로/첫 사용, 앱 도움말과 패키지 `USER-GUIDE.md`가 같은 자료를 쓴다. 한 장 입력 PNG/JPEG의 색상·크기 한도와 분리 PNG 폴더/.2dparts v1.0을 실제 입력 모듈에 맞춘다. WebP/ORA/PSD/PSB를 지원한다고 안내하지 않는다. 프로젝트·정적 PNG·독립 INP를 구분하고 권한/제한을 필요한 주제에 표시한다. 도움말 열기·검색·경로 선택 취소는 프로젝트를 변경하지 않는다. 예제는 별도 ID의 실제 프리미엄 파츠 프로젝트이며 편집 중 저장 확인을 우회하지 않는다.

서명되지 않은 포터블이며 자동 업데이트/설치형/제거 프로그램은 제공하지 않는다. 사용자 자료를 앱 폴더 밖에 두고 이전 버전·변경 전 백업을 보존한다. 제거는 사용자 수동 앱 폴더 삭제다. 개발 검증 helper는 명시적으로 만든 시험 경로에서만 ZIP을 새 폴더에 풀고, 정확한 파일 해시/목록이 일치할 때만 소유 파일을 개별 삭제한다. 변경 파일·추가 자산·링크·바깥 경로는 거부하며 재귀 삭제 명령을 사용하지 않는다.

## 증거와 남은 실제 시험

`evidence/phase29/run-01`의 참여자 등록/응답과 run-01~03의 개발 중 실패를 보존한다. run-04는 안내·실제 패키지/기본 및 작은 창·ZIP 자료 보존 점검이다. 추가 변경 뒤 최종 실행은 새 디렉터리에 남긴다. 개발자 자동 검증은 초보자 성공률이나 실제 센서 성공으로 합산하지 않는다. 사용자 응답은 [자기보고 기록](../../evidence/phase29/run-01/participant-U29-001-result.json)이며 시간/부위 수를 임의로 0으로 채우지 않았다. 후속 과제 요청을 중단하고 재관찰 계획을 남겼다.

실제 깨끗한 Windows와 다른 PC/장치, 세 경로 전체 사용자 과제/정량 시간·보정, 개선 후 재관찰, 30명/관찰창, 제한 배포 피드백이 남아 있다. [AGENTS.md](../../AGENTS.md)의 “Do not publish, push, sign or deploy as part of a local build task.”에 따라 이 로컬 작업에서는 서명·게시·배포를 하지 않는다. 별도 승인 요청을 발생시키지 않고 로컬 준비까지 수행한다. 문의처나 배포 수신자를 임의로 만들지 않는다.

## 최종 로컬 검증 — run-05

[최종 검토](../../evidence/phase29/run-05/review.json), [필수 검사](../../evidence/phase29/run-05/gate.json), [ZIP·업데이트·제거](../../evidence/phase29/run-05/package/package-review.json), [기본 창](../../evidence/phase29/run-05/package/after.json), [1080×720](../../evidence/phase29/run-05/package/repeat.json).

필수 Node 329/Python 36 검사와 타입·Ruff·validator·빌드가 통과했다. 실제 0.21.0 ZIP을 새 시험 폴더에 풀어 기존 설정 UI 검증을 실행하고 저장한 실제 .2dsketch를 0.22.0에서 열었다. 원본 바이트를 보존하며 새 예제는 별도 파일로 저장했다. 같은 프로필로 두 번 실행하고 프리미엄 파츠 예제·11개 도움말·검색/빈 결과·세 경로 취소·초점/Escape·원본 보존·자동 장치 요청 0회를 확인했다. 새 고급 예제 진입에서 프로젝트 초기화 effect가 움직임 단계를 덮던 경쟁을 수정하고 재검증했다.

구 ZIP의 파일 목록/해시는 그대로이며 추가 사용자 파일이 있으면 제거를 거부한다. 두 버전 앱 폴더를 정확한 파일 목록으로 개별 제거한 뒤 실제 프로젝트와 별도 PNG·공유 프로필을 보존했다. 개발 도구 PATH가 없고 worker 의존은 번들 안에 있다. 패키지/ZIP의 시작 문서·안내/지원 자료는 생성 원본과 바이트 비교했고 FlatBuffers 고지도 고정 SHA로 확인했다. 기본/작은 창의 실제 도움말 화면은 [패키지 화면](../../evidence/phase29/run-05/package/packaged-ui/guide-start.png)에 있다.

이는 동일 개발 PC에서의 로컬 시험이다. 새 Windows·최소 사양·정상 실사 얼굴 검출·장기 연속/성능·실제 초보자 완주·정량 성공률·서명/배포 승인은 아니다. 버전 0.21.0→0.22.0의 동일 스키마 호환을 확인했으며 임의 미래 스키마나 이전 앱의 새 형식 읽기를 보증하지 않는다.

재현: `tools\dev.cmd run check` → `tools\dev.cmd run make` → `node scripts/portable-lifecycle-test.mjs` → `node scripts/usability-package-check.mjs --evidence-dir=<새 폴더>`. UI만 따로 볼 때는 test 빌드 뒤 `node scripts/usability-ui-check.mjs --evidence-dir=<새 폴더>`를 사용한다. 기존 증거 폴더를 덮어쓰지 않는다.
