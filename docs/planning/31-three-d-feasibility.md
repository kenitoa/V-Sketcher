# 31. 그림 기반 3D 요구사항·지원 범위·가능성 검증

2026-11-19. T-301~310 / F-3D-001. **별도 연구 시제품이며 제품 구현·3D 출시 승인이 아니다.** 세 2D 제작 경로, 고급 원화, 앱 내 실행·방송과 독립 내보내기, 그림 기반 3D 및 자체 모델 글 기반 생성의 필수 범위를 유지한다. M0 HOLD와 27~30의 미완료 항목도 유지한다.

## 사용자 과제와 입력 조건 — T-301·302

사용자는 AI 버튜버 시스템을 만들어 보았으나 리깅이 복잡했다고 보고했다. 이번 3D 시험에서도 “그림의 얼굴 전체를 인식하고 각 신체 부위별로 따로 움직이지 못한다”고 지적했다. 따라서 얼굴을 포함한 그림 전체를 하나의 물체로 흔드는 결과를 부위 인식·리깅 완료로 세지 않는다.

| 과제 | 기대 결과 | 2D와 다른 확인 사항 |
|---|---|---|
| D31-U01 한 장의 고급 캐릭터 그림에서 출발 | 정면 인상을 보존한 입체 후보를 회전해 보고 추정 영역을 이해 | 측후면·귀·코·머리카락 두께와 가림 안쪽은 원본에 없는 정보 |
| D31-U02 형태·색 보정 | 전문 모델링 지식 없이 너비·깊이·머리 비율·색을 바꾸고 복원/사본 저장 | 보정한 형상과 뼈·표정 영역의 정합성도 필요 |
| D31-U03 부위별 움직임 연결 | 얼굴·눈·입·몸통·양팔이 각각 반응하며 미검출 부위를 구분 | 영상 입력의 관절 검출과 원화의 부위 분리, 망 가중치는 서로 다른 단계 |
| D31-U04 앱 실행·OBS | 투명한 아바타만 방송 화면으로 보내고 중지 시 장치를 해제 | 실제 깊이, 가림 순서, GPU 메모리, 손실 시 기본 자세 복귀 |
| D31-U05 외부 독립 사용 | 원본 앱 없이 형상·재질·뼈·표정을 읽고 사용 조건을 확인 | glTF/GLB와 VRM의 사람형 규약·기본 자세·표정 이름 호환성 |

초기 연구 캐릭터는 기존 PREMIUM-003 Violet, 정면 상반신 1254×1254 RGBA다. 눈·입·의상·머리 장식의 디테일을 유지한 채 비교한다. 기본 화면을 도형으로 바꾸지 않는다. 초기 연구 대상 선정은 전신·다른 화풍·일반 그림 입력의 제품 범위 삭제가 아니다.

입력 목표는 PNG/JPEG, 한 명의 캐릭터, 정면 또는 작은 기울기, 눈·입과 연결할 부위가 확인되는 그림이다. 연구 빌더는 **해시가 일치하는 Violet 참고 그림 한 장만** 처리하며 다른 그림은 `E_3D_ANNOTATION_REQUIRED`로 거절한다. 이를 범용 자동 인식으로 표시하지 않는다. 투명 배경이 없는 그림의 전처리와 여러 인물 선택은 제품 구현 단계에서 기존 세 경로 계약과 연결한다.

옆면·뒷면 자료가 없으면 추정임을 표시한다. 머리카락 뒤·팔 뒤 의상과 입 안을 원본 복원으로 설명하지 않는다. 전신 요구에는 전신 참고, 가린 관절에는 분리 그림/추가 구도, 외형 평가에는 동일 캐릭터의 정면·측면·후면 자료가 필요하다. 손·손가락·다리·발은 현재 그림에 없어 미지원이며 임의로 움직이지 않는다.

## 검증 자료와 권한 — T-303

입력은 [제품 자산 manifest](../../assets/product/manifest.json)의 SHA-256으로 식별한다. [기존 생성 기록](../../experiments/phase04/assets/premium/generation-prompts.md)은 프로젝트에서 생성한 캐릭터이며 타인의 캐릭터나 개인 사진을 사용하지 않았다는 출처 근거다. 이번 입력·중립/눈/입 비교·동작 제어 목록과 파일 해시는 [검증 자료 목록](../../evidence/phase31/corpus-01/manifest.json)에 고정한다. 동작 제어값은 프로젝트 작성 시험 자료다.

범위는 로컬 개발·기술 시험·시각 검토다. 모델/원화의 공개 배포, 재판매, 학습 데이터 편입 승인을 뜻하지 않는다. GLB/VRM에도 로컬 연구 목적과 재배포 제한을 남긴다. 실제 얼굴 영상·마이크 원음은 저장하지 않으며 사람 시험은 파생 제어의 범위·검출 프레임 수·자원 해제 여부만 기록한다.

정면 원화와 기존 표정 그림은 있으나 동일 캐릭터의 실제 측후면 정답·완성 3D 원형은 없다. 생성 결과를 정답에 재사용하지 않는다. 따라서 준비한 것은 **권한과 결손이 명시된 탐색 자료**이고, 3D 외형 출시 평가 자료 전체가 아니다. 출시 전 최소 12캐릭터의 사용 허가·구도·화풍·가림 조건 및 독립 3D/다각도 정답을 확보한다.

[일반 Blender 로드](../../evidence/phase31/learned-02/blender/report.json)와 [광원 없는 정점 색 진단](../../evidence/phase31/learned-02/blender-unlit/report.json)을 구분한다. 후자는 원본 GLB를 수정하지 않은 진단 뷰다. 영상의 선명도·해부 구조·리깅 수용은 미통과다.

[독립 정점 색 진단](../../evidence/phase31/learned-03/blender-unlit/report.json)에서 낮은 해상도의 각짐은 줄었으나 얼굴·눈·의상 색/선의 흐림과 미리깅 상태는 남았다. 두 실행의 로드 시간 차이는 캐시/프로세스 초기화 조건이 통제되지 않았으므로 속도 개선이나 콜드/웜 성능 통과로 세지 않는다. 6축 진단의 원시 파일 방향은 사람형 Y-up 지원 승인이 아니다.

고정 비율로 눈·입을 잘못 배치하고 hips/head만 가중했던 초기 결과는 run-01~04에 보존했다. 새 run-05는 참고 그림 전용 눈·입·어깨/팔꿈치 위치를 명시한 [주석](../../tools/three-d-reference.json)으로 눈·입 변형 위치를 바꾸고 chest·양쪽 위팔/아래팔 가중치를 연결한다. 팔꿈치는 의상 아래 추정이다. 사람용 Face/Pose Landmarker의 **원화 검출은 얼굴 0·몸 0**이므로 이 주석을 자동 검출 성공으로 바꾸지 않는다.

run-05의 실제 정점 변위 검사에서 한 팔을 회전했을 때 해당 팔 정점이 이동하고 반대 팔·얼굴은 0이었다. 공식 three-vrm 로더에서도 같은 결과를 확인했다. 그러나 한 장의 연속 껍질에서 소매·머리카락·몸통 경계가 늘어진다. 독립 가중치 연결 성공과 고급 부위 분리·자연스러운 움직임은 구분하며 후자는 **실패/미해결**이다.

## 보정·실제 입력·출력·외부 구동 — T-306~308

별도 시제품에서 전체 너비 0.8~1.2, 깊이 0.08~0.30, 머리 너비 0.85~1.2, 보라색 농도 0~1, 원래대로 복원, 보정본 GLB/VRM 사본 생성을 시험했다. 바이트 원본을 보존하고 새 파일에 형상·색을 반영하며 glTF validator 오류는 0이었다. 자동 UI 검증은 초보자의 도움 없는 완주 증거가 아니다. 눈/입 위치와 부위 경계의 초보자 직접 보정, undo/재저장 제품 통합은 후속 범위다.

실제 입력은 사용자가 허용한 기본 DirectShow 웹캠과 기본 마이크를 명시적으로 시작할 때만 연다. 얼굴 제어와 함께 Pose Landmarker의 신뢰도·화면 안 존재 조건을 모두 만족한 어깨 기울기·팔 각도만 연결한다. 팔의 첫 신뢰 관측을 중립으로 잡고 부모 대비 회전으로 바꾼다. 손·다리 3D 추적은 구현하지 않았다. 검출이 없으면 기본 자세로 돌아가며 보이지 않는 부위의 운동을 만들어내지 않는다.

[실제 장치 device-03](../../evidence/phase31/device-03/live-summary.json): 약 56초, 입력 667프레임 중 얼굴 43, 몸통용 어깨 466, 양팔 각 0. 마이크 859블록, 최대 RMS 약 0.00183. 입력 수신은 확인했지만 팔 반응과 발화를 포함한 전체 수용 조건은 미통과다. 검출이 없는 이유가 가림/프레임 밖인지 모델 실패인지 구분할 추가 관찰이 필요하다. 영상·원음 미저장, 시험 종료 후 자원 해제를 기록했다.

[실제 OBS live-02](../../evidence/phase31/live-02/obs-live.json)는 별도 소유 OBS 33.0.1에서 1920×1080 투명 WebGL 아바타를 받아 8개 서로 다른 화면을 얻었다. 카메라 실사·마이크 원음은 소스로 보내지 않고 스트리밍/녹화를 시작하지 않았다. 입력·방송 응답 전체 판정은 **false**다. 과거 live-01 실패를 덮어쓰지 않았다. T-190의 2D 브라우저 카메라와 장치 동일성을 비교하지 않았으므로 그 문제를 닫지 않는다.

준비 완료 후 안내한 [재시험 device-04](../../evidence/phase31/device-04/live-summary.json)·[OBS live-03](../../evidence/phase31/live-03/obs-live.json)는 542프레임 모두 얼굴/몸 검출이 없었다. 관절별 진단도 전체 `noPose`여서 화면 밖/가림과 모델 실패를 관절 수준에서 구분할 수 없었다. 발화·동작 수행을 관찰한 근거가 없어 참여자가 지시를 완료했다고 기록하지 않는다. 자원은 해제했고 추가로 장치를 반복 열지 않았다. 이 결과를 기존 0명 검출 문제의 해결이나 T-307 통과로 바꾸지 않는다.

[독립 Blender 4.5.3 결과](../../evidence/phase31/run-05/blender/report.json)는 로컬 GLB를 읽어 19뼈, blinkLeft/blinkRight/aa, 앞·뒤 재질, 내장 이미지를 확인하고 12개 구도/동작을 렌더했다. 앱·프레임 서버를 파일 의존성으로 요구하지 않는다. Blender 보존 검증과 실제 외부 실시간 아바타 실행기의 웹캠 바인딩은 별개다.

VRM은 [VRM 1.0 규격](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/README.md)에 맞춘 메타·사람형 뼈·표정 매핑 후보를 공식 [three-vrm](https://github.com/pixiv/three-vrm) 3.5.5로 읽었다. 라이브러리 로드는 독립 데스크톱 VRM 실행기의 성공으로 세지 않는다. 원화 팔 내림 자세·전신 참조 뼈·실제 피부 가중치의 불일치가 있어 전신 리타기팅과 VRM 출시 호환성은 HOLD다. 이번 채택은 **GLB 탐색 교환 형식**, VRM은 추가 검증 후보로 제한한다.

## 측정 계약 — T-309
