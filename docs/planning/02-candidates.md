목적은 초기 비교 후보와 검증 위험을 좁히는 것이다. 문서 접근 가능성과 실제 파일 생성·로드·장치 입력 성공을 구분한다. 프로그램·라이브러리·모델·사용자 자산의 조건을 각각 확인한다. 여기서 프로그램 자체를 재배포하거나 외부 서비스 약관에 대신 동의하지 않았다.

OBS Browser Source는 로컬 파일 또는 URL을 불러올 수 있고 기본 CSS에서 투명 배경을 설정한다. 이는 우리 출력이 곧바로 정상 수신된다는 증거가 아니다. [공식 Browser Source 설명](https://obsproject.com/kb/browser-source), [OBS COPYING](https://github.com/obsproject/obs-studio/blob/master/COPYING).

Streamlabs의 기술 기반과 라이선스 표기는 [공식 저장소](https://github.com/streamlabs/desktop)에서 확인했다. 두 프로그램을 초기 필수 지원으로 확정하지 않았다.

NDI·Spout·가상 카메라 등은 이번 기본 실험 환경에 설치하지 않았다. 추가 전달 방식이 필요해지면 사양·알파 지원·사용/재배포 조건·설치 부담을 따로 조사한다. 현재 Browser Source나 출력 창 중 하나를 채택한 것도 아니다.

## 2. 외부 2D 아바타 대상·형식 후보 — T-017

| 대상·형식 | 수요·사양·조건 | 기능 범위와 기술 위험 | 후속 판단 |
|---|---|---|---|
| Inochi Session / Inochi2D INP | 외부 활용 필요성은 확인, 이 도구 선호는 미확인. 공개 INP 사양과 BSD-2-Clause 프로젝트 | 모델·리깅 JSON·텍스처를 담는 컨테이너 후보. 매개변수·변형·표정·텍스처 보존 범위와 앱 안정성을 실험해야 함. 사양 문서는 1.0 이전 변경 가능성을 설명함 | **첫 변환 실험 우선 후보**. T-037에서 선택 태그/커밋과 스키마 고정→T-038에서 우리 앱 종료 후 직접 로드·동작. 초기 지원 확정은 DEC-07 |
| VTube Studio / Live2D model3.json + moc3 등 | 이 도구 선호는 미확인. 공식 가져오기 안내·플러그인 API 공개, Cubism 별도 조건 | VTS가 읽는 모델 인덱스·바이너리·텍스처·표정/물리 파일을 실제로 만들어야 함. API로 파라미터를 보내는 것만으로 독립 모델 내보내기를 완료할 수 없음. 우리 구조에서 필요한 바이너리를 생성하는 경로는 아직 미검증 | 표현/사용자 수요 비교 후보. 바이너리 생성·SDK 적용 범위·배포 조건이 확인되기 전 지원 약속 불가 |

INP의 구조·바이트 순서 등은 [공식 INP 사양](https://docs.inochi2d.com/ja/latest/spec/inp/)을 확인했다. [프로젝트 조건](https://github.com/Inochi2D/inochi2d/wiki/Legal-Info)은 코드와 사용자가 만든 모델의 권리 범위를 구분한다. [Inochi Session 원저장소](https://github.com/Inochi2D/inochi-session)는 개발 중임을 안내하므로 이름만으로 출시 안정성을 가정하지 않는다. 조사 시 기본 브랜치는 `v0_8`, 참고 사양 문서 표기는 0.7이므로 실제 실험에서 버전을 반드시 맞춘다.

VTube Studio의 [공식 모델 가져오기 안내](https://github.com/DenchiSoft/VTubeStudio/wiki/Loading-your-own-Models)는 런타임 모델 파일 구성을 설명한다. [공식 API 안내](https://github.com/DenchiSoft/VTubeStudio)는 플러그인 조건과 제어 기능을 설명하며, 이를 Cubism 런타임·모델 생성·배포 조건의 대체 근거로 쓰지 않는다.

[Live2D 공식 SDK 배포 안내](https://www.live2d.com/en/sdk/license/)에는 확장 가능한 앱과 VTuber 추적 소프트웨어에 관한 별도 심사·계약 항목이 있다. 이 제품의 적용 여부·필요 계약을 확인하지 않았으며 모든 개인 프로젝트가 무조건 면제된다고 판단하지 않는다. 비용·SDK 적용 범위는 채택 전 별도 확인한다.

이미지 PNG나 자체 프로젝트 JSON은 외부 움직이는 아바타 대상의 대안으로 세지 않는다. VRM 등 3D 대상은 장기 3D 범위에서 별도 검증한다.

MediaPipe의 기능과 환경은 [Face Landmarker 공식 안내](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker?tab=Python), [Python 환경 안내](https://developers.google.com/edge/mediapipe/solutions/setup_python)를 따랐다. [코드 라이선스](https://github.com/google-ai-edge/mediapipe/blob/master/LICENSE)와 [Face Mesh V2 모델 카드](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20MediaPipe%20Face%20Mesh%20V2.pdf)를 구분해 확인했다. 설치 성공이나 카메라 추적 성공 기록은 아니다.

SAM 2의 기능·설치·체크포인트·별도 구성 조건은 [공식 저장소](https://github.com/facebookresearch/sam2)의 안내를 확인했다. 고급 원화에 대한 성능은 아직 측정하지 않았고, 새로 확보한 HQ-001/HQ-002에서 실패·보정 부담을 평가해야 한다.

OpenCV는 [기하 변환 문서](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)와 [버전별 라이선스](https://opencv.org/license/), Pillow는 [공식 라이선스 안내](https://pillow.readthedocs.io/en/stable/about.html#license)를 확인했다.

## 4. 조사 결론과 채택 전 확인

다음 실험 순서는 `기본 PNG·좌표·부위 표현 → 변형 기준선과 고급 원화 보존 → 사람 얼굴 추적 → OBS 실제 수신 → INP 최소 독립 구동`으로 제안한다. 이 순서는 가능성 검증 우선순위이며 최종 스택 선정이 아니다. VTS/Cubism은 별도 파일 생성·조건 확인이 필요한 비교 대상으로 유지한다.

후속 실험마다 패키지 버전/커밋, 모델·바이너리 해시, 대상 프로그램 버전, 설치·배포 조건, 원본 샘플, 장비 설정과 측정 결과를 [실행 양식](../../experiments/phase02/run-template.json)에 남긴다. 이름이 같은 라이브러리의 현재 기본 브랜치만으로 재현했다고 표시하지 않는다. 모델 설치·장치 입력·방송 연결·외부 대상 구동은 03~04의 별도 실행 과제다.
