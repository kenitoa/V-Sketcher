## 3. 보류 중 가능한 작업과 재검토 절차

1. 위 다섯 항목을 해결하는 격리 실험과 필요한 최소 기반 작업만 별도 수행할 수 있다. 예를 들어 T-052/053/058/060 일부를 재검증용으로 먼저 구현해도 전체 06 또는 제품 기능이 완료된 것은 아니다. 이 예외는 M0→M1 선행 조건을 몰래 해제하지 않는다.
2. 각 run은 새 code/config/asset/model/target hash, 고정 조건, 실제 수치, 증거 위치와 실패를 기록한다. 새 프레임 엔진/패키지를 03/04 검사 결과로 통과시키지 않는다.
3. 모든 OPEN의 성공 조건을 충족한 뒤 이 문서의 상태·DEC·게이트 표와 PRD/Todo를 함께 재검토한다. 기준 변경이 필요하면 원래 기준·이유·사용자 영향·새 검증 계획을 먼저 기록한다.
4. 최소 표본의 M0 PASS를 출시 30명·64파츠 조합·전체 장비·2시간 시험의 PASS로 확대하지 않는다. 치명적 사용자 작업 손실·기본 사용 차단이 남으면 M0 또는 해당 출시 게이트를 계속 보류한다.

## 4. 05 완료와 남은 작업의 구분

T-041~049는 구체 결정·설계·기준·버전/조건과 문서 반영을 마쳤다. T-050은 실제 실패/미측정을 판정하고 M0-R01~05에 반환했다. 따라서 **05 작업은 완료, M0는 HOLD**다. 사용자가 요청하지 않은 제품 스택 설치·본격 기능 구현·전체 06 착수·출시/배포를 이 작업에 포함하지 않았다. 기존 실험/원본은 그대로 보존하고 현재 결정은 별도 문서·기계 판독 기록으로 연결한다.
