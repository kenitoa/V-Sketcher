## 1. 실제 구현과 검증 범위

[engine.py](../../experiments/phase03/engine.py)에 세 가져오기 어댑터, 공통 Project/Part, 알파 합성, 표정 상태·평면 고개 변형, 부위 교체, 눈·입 보정, 저장·재열기를 구현했다. [viewer.py](../../experiments/phase03/viewer.py)는 같은 데이터를 조절하는 Tk 데스크톱 시제품이다. [cli.py](../../experiments/phase03/cli.py)도 같은 어댑터·렌더러를 사용한다.

제품 구현 언어·엔진·지원 형식을 확정한 것은 아니다. 장치 입력·카메라 추적·방송 소스·외부 아바타 내보내기는 이번 작업에 포함하지 않았다. 모든 처리와 파일 보존은 로컬에서 수행했고, 입력 그림을 모델 학습이나 외부 추론 서비스로 전송하지 않았다.

## 3. 변형 후보 비교 — T-023

두 방식 모두 원본 텍스처를 유지하고, 중립에서는 입력 합성과 같은 결과를 낸다. 픽셀 재매핑은 [OpenCV 공식 기하 변환 문서](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)를 참고했다. `weighted`의 몸체 가중치는 이 시제품에서 작성한 방식이다.

| 비교 | rigid: 전체 평면 회전·이동 | weighted: 아래 몸체를 고정하는 가중 재매핑 |
|---|---|---|
| 원화·표현 | 전체가 함께 기울어 원화 질감 보존이 단순함 | 상부 움직임과 하부 고정을 연결. 연결 구간의 늘어짐 가능 |
| 극단값 | 어깨·몸체까지 같이 움직이고 가장자리 잘림 가능 | 몸체는 유지되지만 목 주변 변형·큰 범위의 평면감이 남음 |
| 512 파츠 CPU 중앙값 | 540.647ms/프레임 | 550.142ms/프레임 |
| 1254 고급 원화 CPU 중앙값 | 571.592ms/프레임 | 596.223ms/프레임 |
| 하부 몸체 변경 픽셀 | 파츠 2,503 / 고급 원화 335,470 | 두 경우 모두 0 |
| 외부 변환 가능성 | 이동·회전·상태 파라미터로 대응하는 후보. 실제 대상 지원은 미검증 | 망·제어점 등으로 근사하는 후보. 복합 제어·표현 손실·대상별 오차 미검증 |

각 시간은 워밍업 1회 후 같은 최대 고개 상태를 3회 생성한 실제 CPU 벽시계 중앙값이다. 측정 원자료는 [deformation.json](../../experiments/phase03/results/deformation.json), 시각 비교는 [변형 비교 이미지](../../experiments/phase03/results/deformation-comparison.png)에 있다. 표시 FPS·카메라 지연·방송 성능이 아니며, 이 수치로 30 FPS 목표를 충족했다고 판단하지 않는다. **현재 CPU 구현은 실시간 제품 성능에 부족하며 캐시·배치·GPU 등 최적화가 필요하다.**

이 단계의 미리보기 기본값은 하부 고정이 확인된 weighted다. 최종 DEC-05 선택은 외부 형식과 성능 실험을 포함한 T-039/043/048에서 판단한다.

## 4. 파츠 교체 — T-024

왼눈·앞머리·몸체의 색/크기를 바꾼 별도 변형 자산을 만들고 `replace_part`로 실제 교체했다. [교체 기록](../../experiments/phase03/results/replacements.json)과 `results/swaps/`·`results/projects/swap-*/`에 결과를 남겼다.

- 기존 제어 연결·좌표·겹침 순서·매개변수 값을 유지했다.
- 교체하지 않은 부위 텍스처 해시가 그대로임을 확인했다.
- 교체 후에도 눈·입 반응이 달라지고 저장본이 다시 열렸다.
- 역할·좌우가 맞지 않는 교체는 거부했다.

이 자산은 구조 검증용 변형이며 고급 제품 파츠 라이브러리를 완성한 것으로 세지 않는다.

## 5. 한 장 그림 인식·자동 준비 — T-025/026

### 5.1 실행 방식

MediaPipe Face Landmarker의 정지 이미지 모델과 별도 색상·위치 기준선을 실행했다. [공식 Face Landmarker 설명](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker?tab=Python)의 랜드마크를 사용하며, 사람 얼굴용 도구가 모든 캐릭터 그림을 인식한다고 가정하지 않는다. 모델은 공식 저장 위치의 float16 버전 1, 3,758,596바이트이며 [출처·SHA-256](../../experiments/phase03/models/source.json)을 고정했다.

인식 코드는 입력 픽셀만 읽는다. 원본 분리 파츠·fixture ID·평가 정답 위치를 인식 입력으로 쓰지 않는다. 알려진 절차 그림의 좌표는 **평가에만** 사용했다. 고급 원화는 세부 외형·경계·동적 표현 한계를 별도 검토해 일부 실패로 남겼다.

MediaPipe가 찾은 눈·입 주변은 로컬 픽셀에서 제안 영역을 다듬고, 단일 입력에서 기본 얼굴 패치·닫힌 눈 상태·추정 입 상태를 준비했다. 검사한 중립 얼굴의 완전 불투명 픽셀은 원본과 일치함을 확인했다. 닫힌 눈·입 안·패치 뒤 픽셀은 추정이며, 원래 존재하던 숨은 부위로 취급하지 않는다.

색상·위치 기준선은 가림 입력에서 눈·입을 잘못 제안했다. 따라서 해당 기준선의 불확실한 제안은 자동으로 움직임에 연결하지 않고 위치 확인을 요구한다. 복수 얼굴은 자동 확정하지 않고 대상 선택을 요구한다. 한글 절대 경로에서 모델 읽기가 실패했던 문제는 파일 바이트 전달로 수정했다.

## 6. 가림 보완·제한 비교 — T-027

원본에 없던 눈·입을 정확히 복원할 수 없으므로 `restrict`·`mirror`·`inpaint`를 비교했다. [GrabCut](https://docs.opencv.org/4.x/d8/d83/tutorial_py_grabcut.html)은 배경 분리 기준선으로 사용했고 정교한 머리카락 매팅과 구분했다. 가림 보완의 주변 채움은 OpenCV Telea 인페인팅이며 새 부위 구조를 생성하는 모델이 아니다.

이 비교는 인식 오류와 보완 방법을 분리하기 위해 **운영자 통제 스크립트가 알려진 절차 그림 좌표로 세 부위 위치와 가림 표시를 API에 4회 설정한 뒤** 수행했다. 실제 사용자가 마우스로 4회 보정한 관찰이 아니며 자동 인식 0회 보정 성공으로 계산하지 않는다. 원래 가리지 않은 S-001의 픽셀은 평가용 비교에만 사용했다.

| 입력·방법 | 결과와 보정 부담 | 중립 변경 픽셀 / 숨은 영역 RGB MSE |
|---|---|---|
| 눈 가림 S-004 / restrict | 원본 유지, 숨은 눈 동작 해제. 제한 확인이 필요하며 새 원화 수정 없음 | 0 / 10,636.827 |
| S-004 / mirror | 보이는 반대 눈의 대칭 추정. 눈 모양·하이라이트·가림 경계 확인 필요. 가린 머리카락까지 정교하게 재구성하지 못함 | 1,710 / 4,948.203 |
| S-004 / inpaint | 주변 색으로 채울 뿐 눈 구조를 만들지 못함. 눈을 활성화하려면 새 부위 원화 필요 | 1,559 / 11,101.496 |
| 입 가림 S-005 / restrict | 원본 유지·입 제어 해제 | 0 / 8,145.850 |
| S-005 / mirror | 반대편 입이라는 대응이 없어 입 보완을 하지 않음 | 0 / 8,145.850 |
| S-005 / inpaint | 채움만 제공. 입 모양·입 안을 복구하지 못함 | 537 / 8,103.602 |

MSE는 알려진 절차 그림의 숨은 영역 비교이며 미적 품질 점수가 아니다. 대칭 추정의 수치가 낮아져도 원화의 정답·출시 품질로 승인하지 않는다. 모든 경우 고개 정규화 범위를 ±0.35, 즉 기울기 ±2.1°·좌우 얼굴 폭 약 1.575%로 제한했다. 실제 초보자 보정 시간은 미측정이다.

[원자료·범위·추정 표시](../../experiments/phase03/results/completion.json), [비교 이미지](../../experiments/phase03/results/completion-comparison.png)를 남겼다. 기본값은 원본과 기능 제한을 드러내는 restrict다. 입 가림의 실제 새 원화 생성과 고품질 가닥/피부 보완은 미해결 위험으로 유지한다.

## 7. 간단 보정 시제품 — T-028

Tk 화면에서 눈·입 표시점을 끌어 위치를 바꾸고 영역 크기를 조절한 뒤 같은 동작을 재확인할 수 있다. 가림 표시·해제와 원본 비교·프로젝트 저장도 제공한다.

통제 실험은 입을 +50px, 왼눈을 -20px 잘못 놓은 뒤 제안 위치로 복구했다. 잘못된 위치의 움직임이 달라지고, 원본 및 다른 부위 위치가 유지되며, 복구 상태가 저장·재열기 후 재현됨을 확인했다. 4회 수정은 프로그램으로 실행한 실험 조작이며 초보 사용자 작업량으로 기록하지 않는다. [보정 기록](../../experiments/phase03/results/correction.json), [전후 비교](../../experiments/phase03/results/correction-before-after.png).

실제 Tk 위젯·드래그 좌표 변환·위치/크기·가림 제어·저장·경로 선택·오류 시 기존 작업 유지의 **프로세스 내 통합 검사 17/17**을 통과했다. Computer Use는 네이티브 연결 도우미를 찾지 못했고 재시도·세션 초기화 후에도 복구되지 않아 **직접 OS 마우스 조작·화면 검수는 미수행**이다. 자동 위젯 검사를 그 검수나 초보 사용자 관찰의 대체 성공으로 표현하지 않는다.

**03 종료 조건은 제한된 대표 입력에서 통과했다.** NFR-ART-01 전체 품질, 얼굴 가림·잘림·화풍 일반화, 실제 초보자 보정, 실시간 성능, 외부 표현 호환은 미완료로 남긴다. 실패한 샘플을 지원에서 조용히 삭제하지 않으며 T-042/043/047/048에서 지원 경계·추가 실험·기술 선택을 판단한다. 제품용 자동 준비/쉬운 보정 구현과 사용자 검증에서도 이 위험을 다시 확인한다. 04에서는 별도로 장치·방송·외부 독립 구동의 가능성을 검증한다.
