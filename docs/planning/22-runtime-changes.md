# 22. 실행 중 변경 반영·프로젝트 전환·자원 보호

2026-11-18 · 앱 0.17.0 · 프로젝트 모델 1.9 유지 · T-211~220.

사용자의 22단계 구현 요청에 따라 21의 실행본 기반에 동시 편집을 연결한다. T-190 실제 카메라 재검증과 T-209 실제 전역 키 확인은 미완료로 보존한다. M0 HOLD·5 OPEN과 세 제작 경로·고급 원화·로컬 실행/방송·독립 내보내기·필수 장기 3D/자체 모델 생성을 유지한다.

## 사용과 변경 분류

실행 화면의 **실행 유지·편집하기**로 돌아오면 상단에 실행 캐릭터와 작업본·실행본·저장본 리비전을 표시한다. 편집 미리보기는 작업본, 장치 입력·표정·실행 캐릭터는 실행본을 사용한다. **작업본 N 저장**은 표시된 현재 작업본을 저장하며 실행본을 암묵적으로 바꾸지 않는다.

| 변경 | 현재 반영 정책 |
|---|---|
| 표정 정의/슬롯·입 우선 정책·카메라 채널 설정·기존 움직임 강도/평활·프로젝트 이름 | 검증 후 자동 반영 선택. 연속 조절/저장이 끝나고 안정된 리비전에서 준비하며, 실패 시 수동 재검사 |
| 텍스처·불투명도·위치·망/변형 등 외형 | **변경 검사·준비 → 검사한 실행본 적용**. 준비·취소·실패 동안 기존 실행 유지 |
| 프로젝트/편집 세션·캔버스/원본·매개변수·부위 ID/부모/역할·연결/그룹 구조 | **실행 상태 재시작하여 적용** 확인. 표정·추적 대상을 초기화하고 장치 연결·숨김/기본 자세 상태 유지 |
| 나머지 새 내용 | 자동 반영하지 않고 수동 검증 |

검사 완료 후 더 편집하면 준비된 결과는 오래된 리비전이 된다. 적용을 막거나 서버에서 거부하며, 취소 후 최신 작업본을 다시 검사한다. **준비 취소**는 준비한 실행본만 버리고 작업본 편집을 남긴다. 새 이미지 로드·구조 검증·리비전 확인 실패는 기존 캐릭터를 유지한다. 중지·다시 시작도 프로젝트와 미저장 편집을 보존한다.

프로젝트 열기·최근·새 프로젝트·복제·복구·닫기에는 **실행 유지·편집만 전환 / 검사 후 실행도 전환 / 취소**를 제공한다. 그 뒤 기존 미저장 저장/폐기/취소 처리를 수행한다. 실행 전환은 새 작업본 검사와 GPU 준비가 성공한 뒤 진행하며, 빈 초안/손상 파일이면 기존 캐릭터를 유지한다. 파일 선택 중 실행 소유자가 바뀌면 오래된 전환 의도는 거부한다.

전환을 위한 저장 도중 새 편집이 생기면 프로젝트를 바꾸지 않고 최신 편집을 미저장으로 보존한다. 전환 처리가 진행되는 동안 화면 편집 입력을 잠가 대기 명령이 다른 프로젝트에 적용되는 것을 막는다.

무거운 분석·새 그림/분리 파일 가져오기·텍스처 교체 준비·분리 자료 내보내기는 실행 중 보류한다. 안내에서 실행 화면으로 이동해 중지한 뒤 작업할 수 있다. 기존 부위/표정/수치 편집·검사한 결과 적용·저장·제한된 프로젝트 열기를 지원한다. 실행 중 파일 처리의 압축 파일과 자산 합계 한도는 **64MiB**다. 기본 파츠 카탈로그의 약 36MiB 자산을 지원하도록 정했으며, 큰 파일이나 분석을 중지 없이 지원한다고 광고하지 않는다. 실제 OBS 동시 성능 승인은 후속 검증이다.

[필수 gate와 소스 해시](../../evidence/phase22/verification.json), [전체 개발 앱 회귀](../../evidence/phase22/development-run.json), [release 격리 검사](../../evidence/phase22/package-audit.json), [감사](../../evidence/phase22/audit.json)를 구분한다. Node 20개 그룹을 추가해 **Node 262 + Python 36 = 298개 검사 그룹**을 수행한다. 새 회귀는 실제 세 제작 경로를 준비하고 제어 반영·후보 분리·연타/취소·새 편집 후 오래된 적용 거부·GPU 픽셀 교체·실제 이미지 디코드 실패 주입·프로젝트 유지/전환·작업본 저장을 확인한다.

오디오/비디오는 합성 MediaStream이며 실제 AudioWorklet과 로컬 추론기를 사용한다. 편집기 장치 중지·편집 프로젝트 변경·실행본 재시작에도 두 스트림과 소유자는 유지되고, 중지하면 스트림과 실행 렌더러를 해제한다. 카메라/마이크 원본을 저장하지 않는다. 실제 사람·물리 USB 분리·장치 호환성·OS 전역 키·OBS·외부 아바타 파일·장시간 성능은 이 검증의 통과 범위가 아니다.

첫 시험에서 기본 파츠 자산이 32MiB 초기 한도를 넘는 것을 확인해 64MiB 지원 조건으로 정리했다. 실패 기록을 보존한 뒤 새 실행으로 검증한다. 작은 창의 편집기 초점 때문에 화면이 아래로 스크롤된 캡처는 별도 보존하며 최종 캡처는 실행/작업본 영역을 보도록 정렬한다.

재현은 별도 작업공간에서 `node scripts/verify-runtime-changes.mjs`, release 생성 후 `node scripts/runtime-changes-package-check.mjs --evidence-dir=<새 폴더>`를 사용한다. 현재 근거를 덮어쓰지 말고 새 실행으로 남긴다. 같은 Windows의 OS·드라이버·시스템 DLL이 유지된 격리 실행이며 새 PC/VM을 대신하지 않는다. [트랜잭션·소유권 계약](../architecture/runtime-changes.md).
