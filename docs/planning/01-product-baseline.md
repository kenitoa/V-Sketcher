## 1. 문서 간 대조와 해석 기준 — T-001

미정인 지원 수준 때문에 필수 경로 자체를 삭제하지 않는다. Windows와 OBS Studio는 UR-001의 실제 경험에 따른 **우선 검증 후보**이며, 지원 확정·현재 호환·유일한 지원 대상이라는 뜻이 아니다.

## 2. 초보 사용자의 대표 상황 — T-002

아래는 PRD 3~4절과 UR-001에서 도출한 조사 가설이다. UR-001 참여자는 구현 경험자이므로 초보자 일반의 행동을 확인했다고 해석하지 않는다.

| 상황 ID / 입력 경로 | 시작 상태와 목표 | 예상되는 어려움 | 필요한 제품 행동 | 검증 질문 |
|---|---|---|---|---|
| U-P / 파츠 | 그림·제작 도구 경험 없이 자기 외형을 만들고 방송에 사용 | 첫 선택·어울리는 조합·겹침·색 변경·이후 연결 순서를 모름 | 기본 캐릭터→호환 파츠→즉시 외형/움직임 확인→공통 저장·실행 | 전문 용어 설명 없이 조합·교체·복원을 할 수 있는가? |
| U-I / 한 장 그림 | 사용 가능한 그림의 인상을 유지하며 움직임·방송으로 연결 | 눈·입 분리, 가려진 영역, 리깅, 잘못된 자동 결과 수정 | 자동 준비 우선→불확실한 눈·입만 안내→수정 전후 동작 확인 | 사전 부위 분리 없이 첫 움직임에 도달하고 쉬운 보정으로 개선하는가? |
| U-L / 분리 그림 | 나뉜 부위를 활용해 표정·움직임을 구성 | 이름·좌우·좌표·순서·누락, 기존 제작 지식의 부족 | 구조 보존→역할 제안→미확인 항목 안내→공통 움직임 | 레이어 용어를 몰라도 눈·입 역할과 순서를 확인할 수 있는가? |
| U-R / 재사용·외부 활용 | 저장본을 다시 실행하거나 다른 도구에서 사용 | 자산 누락·재설정·형식 손실·앱 의존성 | 저장·재개, 손실 사전 검사, 동반 리소스 포함, 외부 직접 로드 안내 | 같은 캐릭터를 복구·재실행하고 외부에서도 독립 구동하는가? |

## 3. 첫 사용 종단 간 시나리오 — T-005

### 3.1 세 경로의 진입

| 시나리오 | 사용자 행동 | 공통 흐름 진입 전 확인 | 연결 |
|---|---|---|---|
| E2E-P | 파츠로 만들기→기본 캐릭터 선택→눈·입·머리·의상 교체→색·크기 조절 | 외형과 겹침 확인, 움직임 연결 유지 또는 수정 안내 | AC-01, FT-01 |
| E2E-I | 내 그림 선택→파일 검사→캐릭터 선택→자동 준비→눈·입·추정 영역 확인·보정 | 사전 수동 분리·전문 리깅 없이 기본 반응 확인 | AC-02/03, FT-02~04 |
| E2E-L | 분리 그림 선택→구조 확인→역할·좌우·순서 제안 확인→누락 수정 | 지원 구조 보존, 가능한 움직임과 제한 구분 | AC-04, FT-05 |

### 3.2 모든 경로에 적용하는 행동과 확인 결과

| 순서 | 사용자 행동 | 확인 가능한 결과 / 실패 시 행동 | 연결 |
|---|---|---|---|
| 1 | 위 경로 중 하나로 외형·기본 구조를 준비 | 같은 편집·프로젝트 체계로 진입. 실패는 이유·대체 경로 안내, 원본 보존 | FR-INPUT-01/02, FT-01~05 |
| 2 | 이름·저장 위치를 정해 프로젝트 저장 | 저장 성공과 마지막 정상 상태 확인. 오류 시 다른 위치·재시도, 기존 저장본 보존 | AC-08/14, FT-09/17 |
| 3 | 예제 또는 수동 제어로 눈·입·제한된 고개를 시험하고 표정을 저장 | 카메라 없이 기본 움직임 확인. 틀린 부위만 보정·재확인 후 저장 갱신 | AC-03/05, FT-03/06 |
| 4 | 카메라·마이크 선택→중립 자세 맞추기→입 입력 모드·감도 확인 | 추적·음성 반응 구분. 장치 불가 시 이유·재선택·가능한 대체 동작 안내 | AC-06/07, FT-07/08 |
| 5 | 실행 화면에서 시작하고 표정 전환·중립 복귀를 사용 | 저장 캐릭터가 입력에 반응. 추적 누락 후 안전한 복구 확인 | FR-RUN-01, FT-06~08 |
| 6 | 방송에 사용하기→지원 대상·출력 선택→안내에 따라 방송 소스 추가 | 앱의 출력 준비 상태를 확인. 대상 미수신이면 연결 완료로 표시하지 않음 | AC-09, FT-11 |
| 7 | 실제 방송 프로그램 미리보기에서 캐릭터·투명 배경·움직임·표정을 확인 | 편집 UI·카메라 원본이 없는지 확인. OBS Studio는 우선 실험 후보. 공개 송출 불필요 | AC-09/15, FT-11/21 |
| 8 | 프로젝트 저장→앱 종료→재열기→바로 실행→방송 화면 재확인 | 외형·표정·움직임 재현. 다른 기기의 장치는 재선택 가능 | AC-08/15, FT-09/10/21 |

저장은 전체 과정에서 가능하다. 첫 자동 움직임이 2번의 첫 저장보다 앞서 표시되어도 되며, 이를 숨기거나 사용자의 저장을 기다리게 할 필요는 없다. 첫 움직임 측정은 실제 최초 확인 시점에 끝낸다. 수정 이후에는 최신 리비전을 다시 저장한다.

개발자가 대신 조작하면 무도움 완주로 기록하지 않는다. 같은 공통 흐름을 세 경로에서 각각 검증하며 한 경로의 성공으로 나머지를 통과 처리하지 않는다.

## 4. 결과물별 외부 활용 — T-006

| 목적 / 시나리오 | 시작 조건 | 사용자 행동과 결과 | 필수 확인 / 종료 | 필요하지 않은 조건 |
|---|---|---|---|---|
| 정지 이미지 / OUT-I | 외형 준비 | 표정·크기·배경 선택→이미지 저장 | 저장 파일을 열어 선택 외형·투명도 확인. AC-13, F-EXP-001 | 움직임 준비, 카메라·마이크, 실행·방송 연결 |
| 재편집·재실행 / OUT-P | 편집 가능한 프로젝트 | 프로젝트 저장→종료→다시 열기 | 원본·구조·표정·움직임 재현, 누락 리소스 처리. AC-08, F-PRJ-002~005 | 외부 대상 형식 선정, 방송 연결 |
| 외부 아바타 / OUT-A | 외부 대상 필수 구조 준비 | 대상·버전 선택→호환 검사→누락 수정/손실 확인→파일·리소스 저장→우리 앱 종료→대상에서 직접 로드 | 실제 표시·기본 움직임·표정 확인. 파일 생성과 외부 확인을 별도 기록. AC-11/12, F-EXP-002~005 | 우리 앱 실시간 실행, 카메라·마이크의 연결 |
| 앱에서 방송 / OUT-B | 유효한 실행본과 출력 | 우리 앱 실행→방송 출력→방송 프로그램 수신 확인 | 투명 배경·움직임·UI 제외 확인. AC-09, F-BRD-001/002 | 외부 아바타용 파일 생성 |

외부 대상 자체가 움직임 시험에 요구하는 입력 조건은 별도 기록한다. 내보내기 준비 단계에 우리 앱의 장치 연결을 강제하지 않는다. OUT-B와 OUT-A는 각각 검증해야 한다.

## 5. 초기 2D와 장기 기능의 경계 — T-007

초기 2D는 세 제작 경로, 공통 편집·저장·복구, 눈·입·고개·표정·음성·카메라, 앱 실행, 실제 방송, 이미지 저장, 외부 아바타 내보내기까지 포함한다. 3D와 자체 모델 생성은 전체 제품의 필수 장기 범위로 유지하고 초기 2D 출시 완료와 분리한다. 장기 기능의 선후는 연구·자원에 따라 조정하며 3D 구현을 자체 모델 개발의 기술적 필수 선행 조건으로 두지 않는다.

초기 출시 차단 조건은 PRD AC-01~15와 Function 22.1절을 따른다.

- 세 경로 중 하나라도 공개 지원 범위 안에서 공통 편집·저장·재개·실행·방송·외부 구동으로 이어지지 않는다.
- 한 장 그림의 첫 움직임에 사용자 사전 분리나 전문 리깅이 필수이며 간단 보정으로 완주할 수 없다.
- 실제 방송 대상에서 투명 배경·움직임·표정을 확인하지 못하거나 편집 UI·카메라 원본·개인정보가 의도치 않게 노출된다.
- 최소 하나의 검증된 외부 아바타 대상에서 우리 앱 없이 직접 로드·구동할 수 없다.
- 원본·마지막 정상 저장본 손상, 프로젝트 간 결과 혼입 등 중대한 데이터 오류가 남아 있다.
- 확정된 기준 장비·성능·연속 실행·복구·초보자 완주 기준을 통과하지 못한다. 현재 수치·표본·대상 버전은 검증 대기다.

장기 완료는 3D의 입체 제작·다각도 보정·실행·방송·외부 구동과 자체 모델 제작 범위 충족·생성 결과 검토·공통 제작·실제 사용 연결을 각각 입증해야 한다.
