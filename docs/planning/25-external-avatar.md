# 25. 외부 아바타 생성·독립 구동·재내보내기

2026-11-18 · 앱 0.20.0 · 모델 1.9 유지 · T-241~250 완료.

세 제작 경로와 고급 원화를 유지한 단일 INP 결과를 만든다. 카메라·마이크·2DSketcher·프레임 서버 없이 공식 **Inochi Session 0.8.7 / SDK 0.8.6**에서 읽는 파일이다. PNG 저장·우리 프로젝트 저장·내부 미리보기와 외부 아바타 파일/실제 구동을 구분한다. T-190/T-209 미완료·M0 HOLD/5 OPEN·장기 3D/자체 모델 필수 범위는 유지한다.

## 사용 흐름과 결과

**이미지 저장·외부 대상 → 외부 아바타 대상·사전검사**에서 대상 이름 연결을 검토하고 프로젝트에 설정을 기억한다. 현재 입력/옵션/검사 버전의 경고를 확인한 뒤 **INP 변환·미리보기 준비**를 누른다. 다섯 입력 슬라이더·동작 재생·저장 표정으로 실제 생성한 INP의 키점/텍스처 해석 결과를 확인한다. 이것은 앱의 변환 미리보기이며 외부 실행 증거로 표시하지 않는다. 변환 결과와 근사 범위를 확인해야 **이 INP 저장**을 사용할 수 있다.

INP 하나에 망·내장 PNG·매개변수·기본값·표정 애니메이션·사용자 검토 경고·입력 리비전/내용 지문·대상/변환 버전·출처/제한·안내를 포함한다. 동반 텍스처 폴더가 필요 없다. 파일 이름 기본값은 입력 리비전과 해시 일부를 포함한다. 각 저장은 새 결과 ID를 만들고 과거 외부 확인을 승계하지 않는다. 저장 결과와 확인 이력의 경로는 PC별 비공개 저장소에만 보관하며 프로젝트나 일반 로그에 절대 경로를 쓰지 않는다. 저장 메타데이터만 바뀐 경우와 내용 리비전 변경을 구분하여, 같은 내용의 저장/재열기가 외부 확인을 불필요하게 무효화하지 않게 한다.

공식 대상에서 File → Open으로 INP를 연 뒤 캐릭터를 클릭해 선택하면 Animations 패널에 내장 동작과 표정이 나타난다. 자동 순환을 중지하고 개별 표정을 재생할 수 있다. 실제 장치 입력은 대상 프로그램에서 별도로 연결한다.

파일 위치·결과 새로 확인·이동한 같은 파일 연결·실제 구동한 대상 버전 기록을 제공한다. 파일이 없거나 해시가 다르면 확인할 수 없다. 이전 입력/변환 버전의 확인은 과거 기록으로 남고 현재 확인으로 쓰지 않는다. **사용자 외부 확인**, 개발 자동 시험의 **공식 대상 창 캡처**, **파일 저장 성공**은 별개다.

## 제한 프로필과 보존

검사 **1.1.0**, 변환 **0.3.0**이다. 24단계에서 미검증으로 차단했던 표현 중 다음을 제품 변환으로 구현한다.

- 원래 삼각망·가중치·기준점·최소/최대 변위를 사용한다. 고개 좌우와 가중 회전의 가산 변위를 각각 변환하며 전체 아바타의 평면 이동/회전으로 대체하지 않는다. 물리 매개변수 범위·비대칭 중립점·저장 기본 자세를 유지하고 65개 이상 키점 사이에서 대상의 선형 보간을 사용한다.
- 눈·입의 원래 불투명도 교차는 그 순서와 곡선을 유지한다. 픽셀 보간은 65개 실제 RGBA 중간 그림을 구워 가장 가까운 상태를 선택한다. 입력 양자화 차이 약 1/128을 경고하며, 투명 픽셀 합성을 잘못된 opacity 교차로 대체하지 않는다.
- 색상 조절과 sRGB·straight alpha를 별도 premultiplied PNG에 굽는다. 투명 여백을 정리하고 8px 투명 여유·2의 거듭제곱 크기의 mip 체인과 UV를 함께 변환한다. 필터/색상 경계의 샘플링 차이는 경고와 픽셀 비교 대상으로 둔다. 원본 자산을 변경하지 않는다.
- 저장 표정은 대상의 독립 애니메이션으로 옮기고 원래 값/잠금/전환/해제 정책도 보고서에 보존한다. 대상 입력과의 잠금/해제 우선순위는 Session 애니메이션 정책을 쓰며 로컬 카메라/마이크·OS 키 설정을 자동 이전하지 않는다. 이 차이는 경고 확인 대상이다.
- `ExpressionValue.partIds`는 18단계 구현에서 검토한 영향 부위의 참조 앵커다. 현재 연결과 일치하면 전체 매개변수 표정으로 변환한다. 변경/누락된 앵커는 조용히 제외하지 않고 표정 복구가 필요하다고 차단한다. 과거 24단계의 보수적인 일괄 차단을 이 실제 의미에 맞게 구체화했다.
- 가산 연결로 보존할 수 없는 교차 변환, 연결되지 않은 제어/손상 참조, 다섯 공통 제어 밖 사용자 매개변수는 차단한다. 핵심 제어를 버려서 통과시키지 않는다. 미지원 다른 Inochi 버전·VRM·moc3·VTube Studio는 추가하지 않는다.

입력 64부위/128자산/4096px, 합계 RGBA 256MiB의 기존 어댑터 한도를 유지한다. 생성 결과는 최대 512개 내장 텍스처·RGBA 256MiB·INP 256MiB이며 넘으면 축소/누락 없이 중단한다. 이는 대상 SDK 고유 한도가 아니라 현재 제품 어댑터의 조건이다. 4096px 경계까지 불투명한 그림 등 투명 테두리까지 한도를 넘는 경우도 명시적으로 중단한다.

## 고정 입력과 파일 확정

사전검사와 일치하는 프로젝트/실행 입력본·리비전·내용 지문·옵션·버전·경고 확인을 메인에서 검증한 뒤 프로젝트와 자산 바이트를 별도로 고정한다. 방송/입력 처리를 보호하기 위해 무거운 INP 변환·쓰기는 실행 중 보류하고 중지 후 작업본 기준으로 준비한다. 처리 중 최신 편집을 섞지 않는다. 준비 후 입력이 바뀌면 재검사·재변환이 필요하다. 쓰기 시작 뒤 편집이 더 생기면 성공한 이전 입력 파일과 새 편집을 구분해 표시한다.

임시 INP를 같은 볼륨에 `wx`로 쓰고 fsync·다시 읽기·헤더/섹션/PNG CRC·디코드 크기/예산·노드/텍스처/매개변수/망 바인딩 참조·해시를 검사한다. 살아 있는 writer와 외부 파일 변경을 잠금/해시 CAS로 구분한 뒤 rename으로 확정한다. 실패/취소는 자기 임시 파일만 정리하고 이전 정상 결과와 무관한 파일을 유지한다. UNC·링크·지원 밖 경로를 차단한다. 이력 저장 실패는 이미 성공한 파일 저장과 별도로 표시한다.

## 검증과 남는 경계

신규 Node 20개는 실제 파일/오류 경계·경합·취소·원본 불변·변환/참조·고정 입력·이력/확인·이동·재내보내기를 검사한다. 세 실제 경로에서 최초/수정 후 INP 각 1개와 원본/변환 7상태씩을 비교한다. 독립 Pillow/NumPy 검사는 보이는 영역 합집합에서 premultiplied RGBA 오차 4/255 이내 픽셀 97.5% 이상, 평균 1.5/255 이하를 기준으로 한다.

첫 UI 실행은 기능 흐름을 통과했지만 WebGL 프레임 제출 후 캡처가 빈 버퍼를 읽어 픽셀 비교에 실패했다. 당시 결과를 보존하고, 명시적 재그리기 직후 캡처한 새 실행에서 21상태가 같은 기준을 통과했다. 수정 후 결과까지 42상태로 확장해 최종 검증한다.

독립 대상 시험은 앱/worker 종료 뒤 파일을 한글·공백 경로로 이동해 공식 실행 파일에서 연다. 대상 기본 카메라 0.5와 원본 캔버스 좌표의 고정 투영으로 눈·입·고개·표정의 기준 영상과 창 캡처를 비교한다. 앱에서 대상 매개변수를 보내지 않고 파일에 내장된 대상 애니메이션만 사용한다. 별도 OBS는 대상 창 PNG만 캡처하며 녹화/송출·사용자 장면을 변경하지 않는다. Windows 조작 도구는 `native pipe unavailable / os error 2`로 실패하여 공식 CLI와 기존 OBS WebSocket 방식으로 검증한다.

외부 비교의 초기 실패는 작은 미리보기 확대/필터 차이와, 1254px 캔버스의 627px 뷰포트를 정수 좌표로 반올림한 반 픽셀 이동에서 발생했다. 실패 기록을 보존하고 같은 1024px/mipmap·고정 0.5 픽셀 배율 투영으로 다시 비교한다. 오차 기준(평균 RGB 4/255 이하·96% 이상 픽셀 12/255 이내·7개 상태 모두 최근접 분류 관측)은 낮추지 않았다. 취소 직후 정리 완료 전 새 준비가 허용된 문제도 수정해 완료 응답 전 재조작을 막았다.

실제 카메라/마이크를 대상의 추적기로 연결하는 시험·외부 입력과 표정 우선순위의 모든 조합·다른 Session 버전·장시간 성능·깨끗한 별도 Windows·M0-R04 승인은 이 단계의 자동 동작/표정 구동과 구분한다. 같은 PC의 기본/1080×720 release 실행과 필수 로컬 검사·기존 전체 회귀도 따로 남긴다. 최종 필수 검사·전체 회귀·공식 대상 6회·동일 PC release 2회와 완료 감사를 통과한 범위로 체크했다.
