# 26~31 잔여 20개 작업의 실행·기록·판정

2026-11-19. 추가 허락 질문 없이 남은 작업을 수행할 수 있도록 공통 진입점, 항목별 측정 양식, 오프라인 관찰 화면, Windows 시험 실행 파일을 구현했다. 이 준비 자체를 실제 추적·초보자·장시간·출시 완료로 세지 않는다. 현재 검증 대상은 0.22.4이며 Todo는 40/60 완료다. 세 제작 경로·프리미엄 원화·로컬 실행/방송·독립 내보내기·필수 3D/자체 모델 범위와 실제 통과 전 M0 HOLD를 유지한다.

## 공통 실행

저장소 루트에서 실행한다. 기존 결과는 덮어쓰지 않고 매번 새 폴더를 만든다.

```text
tools\complete.cmd plan
tools\complete.cmd kit
tools\complete.cmd local
tools\complete.cmd review <실제 결과 JSON 폴더>
```

| 명령 | 결과 |
|---|---|
| `plan` | 20개 작업·선행 관계·측정 방법과 실제 필드가 있는 빈 JSON 양식을 `evidence/completion26-31/plan-*`에 생성 |
| `kit` | 후보/이전 ZIP, 해시 manifest, `Observation.html`, `Run-CleanWindows.exe/.cmd`, 관찰/출시 기준과 양식을 `.local/completion26-31/kit-*`에 생성 |
| `local` | 필수 `tools\dev.cmd run check`와 오프라인 관찰 화면의 실제 Electron 자동 검사를 순서대로 실행. 원시 개발 로그는 `.local/`에만 보관 |
| `review` | 실제 제출 기록의 후보/출처·측정·관찰창·파일 해시·개인정보·선행 관계를 검토. 종료 코드 0=20개 모두 통과, 2=미완료/무효 기록 있음, 1=도구/입력 오류 |

`kit`은 ZIP 복사와 후속 실행을 위한 여유 공간을 확인한 후 진행한다. 완성 키트는 Node/Python/컴파일러 설치 없이 다른 Windows에서 사용할 수 있다. 시험 실행 파일은 Windows 기본 .NET Framework 4.8을 사용하며 PowerShell·네트워크·관리자 권한·실행 정책 변경 기능이 없다. 보호 기능이 실행을 막으면 실패로 기록한다. 개발 PC에서 컴파일 도구를 사용한 사실을 새 PC의 제품 실행 의존성으로 섞지 않는다.

## 관찰 화면 사용

키트의 `Observation.html`을 연다. 익명 ID, 첫 제작 경로, 해당 참여자의 동의/초보자 자격과 관찰 근거를 기록한다. 참여자가 실제 앱을 조작하고 관찰자가 첫 결과·첫 움직임·저장 재열기·OBS·앱 종료 후 독립 구동 시점과 보정/막힘/힌트를 기록한다. 도움말은 사용 가능하며 힌트·대리 클릭은 별도로 남긴다.

타이머 구간은 서로 중복되지 않는다. 최초 도달 시간을 덮어쓰지 않으며 성공/막힘/중단으로 종료한다. JSON은 사용자가 이 기기에 저장하며 자동 업로드·영상/원음 수집·이름/연락처 입력은 없다. 기존 JSON을 불러와 재관찰을 추가할 수 있지만 원래 시작/도달/종료 시간은 유지한다. 미래 날짜, 중복 참여자, 다른 후보, 자기보고·개발자·모의 기록은 출시 직접 관찰 표본을 채우지 않는다. 기록은 관찰자의 증언이며 참여자 신원을 독립 인증하지 않는다.

U29-001의 기존 자기보고는 보존한다. 새 관찰은 U29-002 이후를 사용한다. 경로별 첫 사용 집합을 사전에 고정하고 같은 사람의 두 번째 경로를 새로운 초보자로 세지 않는다. 과제 실패자는 분모에 남기며 첫 움직임 이후 받은 힌트는 그보다 앞선 독립 도달 시점을 지우지 않는다.

## Windows 시험과 현재 환경의 구분

키트의 `Run-CleanWindows.cmd`는 동봉 EXE만 실행한다. 후보 ZIP·실행 파일 해시와 안전한 ZIP 경계를 확인하고 고유한 짧은 TEMP 폴더에 압축을 푼다. 전체 패키지 self-check 후 같은 시험 프로필을 새 프로세스에서 다시 열어 작은 창 설정 검사를 수행한다. frozen worker와 sandbox/contextIsolation·Node 비노출·외부 네트워크 차단·정상 종료를 확인한다. 원시 과정 로그와 시험 프로필은 소유한 TEMP 폴더에만 남기며 결과 JSON에는 ID·허용된 집계만 쓴다.

`--inventory-only`는 실행 전 해시/환경 확인만 수행한다. 현재 개발 PC에서 성공해도 `cleanWindowsVerified:false`, `updateVerified:false`를 유지한다. 진짜 새 OS 준비 자료와 이전 버전 프로젝트 사본을 새 버전에서 저장/재열기한 관찰을 연결해야 T-288을 완료할 수 있다. 서명 존재와 신뢰 검증도 구분하며 서명되지 않은 현재 빌드를 승인된 공개 배포본으로 바꾸지 않는다.

## 기록의 재현성과 현재 판정

판정 입력은 `format: 2dsketcher-completion/1`, 현재 후보의 버전/SHA-256, 실제 출처·시각·검토 역할, 해당 측정값과 원본 자료의 상대 경로/해시를 가져야 한다. 첨부 자료는 저장소 `evidence/` 안의 실제 파일이어야 하며 링크로 밖을 참조하거나 해시가 다르면 거부한다. 공개 결과에는 입력 파일명 대신 익명 기록 번호와 SHA-256을 남긴다. 원시 매체·개인 경로·장치 ID·연락처·토큰이 들어간 자료는 가져오지 않는다.

도구는 Todo를 자동으로 고치거나 실제 사람·경과 시간·외부 배포 사건을 만들어내지 않는다. 모든 항목의 자료와 선행 조건이 통과했을 때 실제 완료 근거로 검토한다. 현재는 실행 준비이며 [이전 실제 완료 근거](../../evidence/remediation26-31/review-02/review.json)의 40/60 상태를 유지한다. 구현이 필요한 추적/원화/3D 결함과 외부 관찰 조건은 작업표에서 계속 열린다.
