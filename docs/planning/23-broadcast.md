# 23. 방송용 출력·연결 안내·복구

2026-11-18 · 앱 0.18.0 · 프로젝트 모델 1.9 유지 · T-221~230.

DEC-06의 Windows용 OBS Studio 33.0.1 Browser Source와 로컬 공유 WebGL2 경로를 제품에 연결한다. 세 제작 경로·고급 원화·로컬 실행/방송·독립 아바타 내보내기·필수 장기 3D/자체 모델을 보존한다. 실제 카메라 T-190와 실제 OS 전역 키 T-209는 여전히 미완료다. 이번 앱 초점의 키 주입 시험으로 그 두 작업이나 M0 HOLD/5 OPEN을 완료 처리하지 않는다.

## 사용 순서

1. 캐릭터 실행을 시작하고 실행 화면 아래의 **방송 출력 → 출력 준비**를 누른다. OFF·준비 중·출력 준비·출력 실패를 구분한다. 출력 준비는 외부 수신 확인이 아니다.
2. **OBS 연결 주소 복사**로 PC별 읽기 주소를 복사한다. OBS의 소스 + → 브라우저에서 로컬 파일을 끄고 URL에 붙인다. 너비·높이를 현재 앱 출력과 맞추고 사용자 지정 프레임을 선택한다. 최초 설정은 1920×1080/30FPS, 다른 크기는 1280×720, 앱 렌더 프레임은 15/30FPS다.
3. 기본 투명 CSS를 유지한다. 보이지 않을 때 소스 종료와 장면 활성 시 새로고침을 끄는 조건으로 검증한다. 실제 소스 범위 미리보기는 편집기 확대와 독립이며, 자체 미리보기의 어두운 창 바탕은 외부 소스에 전달하지 않는다.
4. 밝고 어두운 배경 위에서 가장자리·움직임·표정을 확인한다. 앱 전용 키는 앱에 초점을 둬서 사용한다. PC 전역 키는 별도 허용/등록/실제 검증이 필요하다. **OBS 미리보기 사용자 확인 기록**은 대상 33.0.1·설정 버전·실행본 ID·시각·네 확인 항목을 PC 설정에 기록한다.
5. 크기·배치·잘림·프레임 적용은 출력 페이지를 다시 준비할 수 있다. OBS 크기도 맞추고 외부 확인을 다시 한다. **직전 설정 복원**은 설정을 되돌리며 확인 버전은 새로 발급한다. 기존 확인은 과거 기록으로만 남긴다.
6. 앱을 먼저 켜고 출력을 준비한다. OBS가 먼저 오류 페이지를 열었다면 현재 페이지 캐시 새로고침을 누른다. 이미 열린 페이지는 서버 재연결을 재시도하며, 새로 켜진 OBS의 오류 페이지까지 앱이 임의로 제어하지 않는다.

안내의 브라우저 속성·투명 CSS·소스 새로고침은 [OBS 공식 Browser Source 문서](https://obsproject.com/kb/browser-source)를 따른다. 실제 연결 버전은 아래 로컬 검증 근거의 OBS 33.0.1이다. 제품에는 OBS 설치 파일·WebSocket 암호·실험용 제어 도구를 동봉하지 않는다. 선택적 자동 설정 어댑터는 이번 구현 범위에 넣지 않았으며 기본 수동 연결을 제공한다.

## 보호와 복구

- 전송은 `127.0.0.1` 전용 HTTP와 읽기 capability를 사용한다. 기기별 포트·주소는 정상 앱 재실행에 재사용한다. 프로젝트·공유 파일·앱 일반 로그·상태 IPC에는 토큰을 넣지 않는다. 사용자가 추가한 OBS 소스에는 연결 주소가 저장된다.
- 서버는 실행본의 검증된 그림 자산과 공통 장면·정규화된 제어값만 제공한다. 카메라 원본·PCM·원본 파일 경로·편집 문서·알림·체크무늬를 전달하지 않는다. 페이지는 같은 렌더러와 셰이더를 쓰는 캐릭터 canvas만 포함한다.
- 메인 편집기의 외부 네트워크 차단을 유지한다. 앱 출력 미리보기는 별도 sandbox/contextIsolation 세션에서 현재 읽기 주소만 허용하고 모든 장치 권한·새 창을 거부한다.
- 출력 생산 프레임이 1초 넘게 없거나 수신 fetch가 실패하면 투명 화면으로 전환한다. 카메라/마이크 입력 손실은 20단계의 기본 동작 복귀 계약을 재사용한다. 출력 중지·실행 중지는 카메라 영상/편집 화면으로 대체하지 않는다.
- 실행 중 편집과 저장은 작업본, 방송은 실행본을 사용한다. 실행본을 교체하면 자산을 별도로 고정해 이전 grant 해제와 경합하지 않는다. 서버는 현재와 직전 자산 한 묶음만 보관하며 출력 중지에 해제한다.
- 페이지 렌더 응답은 앱 미리보기나 다른 읽기 클라이언트일 수도 있다. 이 ACK를 OBS 미리보기 자동 확인으로 표시하지 않는다. 외부 화면을 관찰하지 못할 때 미표시/불투명/잘림/정지/부하의 점검 순서를 안내한다.
- **출력 다시 연결**은 같은 주소의 서버·페이지를 재준비한다. 실행과 저장은 유지한다. 포트 점유 실패는 별도 오류로 표시하고 점유 해소 후 재시도한다. **기존 주소 폐기·새 주소 발급** 후에는 OBS URL을 다시 붙이고 확인해야 한다.

Node 275 + Python 36 = **311개 검사 그룹**이며 신규 방송 그룹은 13개다. 배포본은 개발 도구 PATH를 제거한 새 설정의 기본/1080×720 검사이며 깨끗한 별도 Windows PC 시험은 아니다.

실제 OBS 검증은 기존 포터블 프로그램을 새 폴더로 복사해 별도 설정/장면에서 실행하고 공식 [obs-websocket RPC1](https://raw.githubusercontent.com/obsproject/obs-websocket/master/docs/generated/protocol.md)의 소스/장면 캡처로 판정한다. 세 경로 출력 UI 시험 뒤의 고급 분리 그림 실행본을 실제 OBS에서 사용했으며, 세 경로 각각의 앱 출력 페이지 검사와 구분한다. 사용자 기존 장면을 변경하거나 공개 송출·녹화를 시작하지 않는다. 원화만 담긴 PNG를 저장하며 실제 카메라·음성·데스크톱 영상을 캡처하지 않는다. 키는 앱에 초점을 둔 Electron 키 주입으로 실제 OBS 결과를 확인한다. 물리 키·다른 앱 초점의 OS 전역 전달과 구분한다.

첫 UI 시험은 주소 재발급 뒤 자체 미리보기가 이전 주소만 허용해 차단된 결과다. 현재 출력 읽기 주소만 허용하도록 수정하고 새 시험에서 통과했다. 초기 알파 비교는 OBS RGBA 캡처를 straight-alpha PNG로 가정해 실패했다. 실패 이미지는 보존하고, 관측된 선형 premultiplied source-over/sRGB 변환으로 새 시험을 진행한다. 배경 픽셀 일치와 전체 픽셀 99% 이상 RGB 오차 2 이내를 요구한다. 첫 크기 변경 대기·파일 응답 읽기·이전 실패의 미적용 작업본이 남은 시험도 새 실행으로 구분한다. 실제 결과를 과거 실험의 성공으로 덮어쓰지 않는다.

이 검증은 방송 연결 기능의 같은 PC 근거다. 실제 사람/장치 호환성·USB 분리·OS 전역 키·장시간 30FPS/지연·독립 아바타 파일·공개 출시 승인은 별도다. M0 HOLD/5 OPEN과 필수 장기 범위를 유지한다. [구현 계약](../architecture/broadcast.md).
