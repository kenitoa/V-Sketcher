# 27. 초기 2D 전체 경로와 수용 기준 통합 검증

2026-11-18 · 앱 0.21.0 · 공통 모델 1.9 · M0 HOLD 유지.

## 검증 범위

26단계의 작업 트리 상태를 그대로 대상으로 새 실행을 추가한다. 과거 실험·자산·결과는 수정하거나 이번 실행 결과로 재분류하지 않는다. `tools\dev.cmd run check`와 실제 Electron/GPU/worker 회귀, 세 경로의 방송 페이지·PNG·INP·설정 검증을 순서대로 실행한다. 배포 포장은 변경하지 않는다.

재현 명령은 `.local\toolchain\node-v24.22.3-win-x64\node.exe scripts/verify-integration.mjs`다. 매 실행은 `evidence/phase27/run-<시각>/`을 새로 만들며, `--output-dir=evidence/phase27/<새 이름>`으로 지정할 수도 있다. 실패한 실행은 보존하고 재시도 시 다른 디렉터리를 쓴다. 단계 실패·소스 변경은 전체 자동 검증을 실패시키며, 정상 로그에는 원시 오류나 개인 경로를 복사하지 않는다.

## 수용 기준과 미해결 조건

`coverage.json`은 기능별 AC·FT·자동 결과 섹션을 모두 연결한다. 이 대응표의 `inventoryPassed`는 ID·연결 누락이 없다는 뜻이며 해당 기능의 사용자 수용 통과 표시가 아니다.

- AC-06 / FT-07: T-190 실제 사람의 정상 얼굴 추적·중립 보정·재보정 취소 확인이 아직 필요하다.
- AC-07 / FT-08: 실제 사람 음성·소음 구간, 물리 USB 분리/재연결과 복수 얼굴 환경 관찰이 필요하다.
- AC-09 / FT-11: 실제 OBS 수신 증거를 세 경로에 연결해야 한다. 내부 수신 페이지 ACK로 대체하지 않는다.
- AC-10 / FT-12: T-274/276 기준 시간 연속 실행·프레임 분포·입력에서 OBS까지 지연이 필요하다. 제출 FPS는 전체 지연 측정이 아니다.
- AC-11 / FT-13: 이번 출력물을 우리 앱/worker 종료 후 공식 실행기가 직접 로드하는 새 근거를 연결한다. 내보내기 UI의 사용자 확인 버튼을 실제 외부 구동 관찰로 세지 않는다.
- AC-14 / FT-17: T-271/272의 현실 저장 실패·비정상 종료 검증은 제어된 정책 시험과 별도다.
- AC-15 / FT-21: T-281/282 초보자가 개발자 대리 조작 없이 완주하는 관찰이 필요하다.
- T-209 실제 OS 전역 키, M0-R01~05, 독립 ART 평가, 별도 깨끗한 Windows 및 필수 장기 3D·자체 모델 생성은 계속 미완료다.

26단계 종료 검토(T-260)도 아직 미완료이므로 27단계의 엄격한 종료 조건을 자동 해제하지 않는다. 완료된 자동 검증·문서 대응 작업과 단계 전체의 통과 상태를 따로 기록한다.

## 실패·수정·재검증 이력

- `obs/`와 `obs-02/`의 실패를 보존했다. Windows가 명령 파일을 읽는 순간 교체하면 `EPERM`이 발생했다. 새 `tools/integration-obs-check.mjs`는 이 오류만 25ms 간격·최대 40회로 제한 재시도한다. 새 `obs-03/`에서 세 경로·9화면과 실제 앱 종료까지 통과했다. 제품 코드·보안 정책은 변경하지 않았다.
- `external/`의 대상 창 미발견과 `external-02/`의 3회 통과 후 OBS 요청 실패를 보존했다. 실제 대상 창 캡처가 가능하도록 실행하고, 새 시험 전용 소스·제한된 OBS 요청 재시도를 적용한 `external-03/`에서 6회를 통과했다. 이전 부분 성공을 6회 성공으로 재분류하지 않았다.
- [INT27-CAM-01](../../evidence/phase27/run-1794981764746/camera-path-comparison.json)은 미해결이다. 얼굴 검출 기준을 낮춰 성공으로 만들지 않았다. 명시적 웹캠 선택과 브라우저 영상 경로를 비교한 뒤 정상 추적·중립 보정·취소·복구를 재검증해야 한다. 정상 카메라 미확인을 세 경로 종단 통과로 숨기지 않는다.
- 실제 장치 두 번째 시도 `live-02/`도 장치 연결·시험 시작 전 종료되어 `E_LIVE_CANCELLED`를 남겼다. 창 표시와 사용자 참여 의사는 정상 추적·발화 측정의 성공 근거로 세지 않았다. 두 번 모두 영상·원음 파일은 저장하지 않았다.
- 시험 프로필·실행 로그는 무시되는 `.local/phase27-private-run-1794981764746/`로 분리했다. 공개 검토 대상 JSON의 개인 경로 검사도 통과했다. 앞으로의 실행기는 처음부터 `.local`에서 시험하고 허용된 JSON/PNG/INP만 결과 폴더에 복사한다. 실제 통과 당시 제어기 바이트는 `controller-tested.mjs`로 보존했으며, 이후 경로 분리 수정은 제품 동작 변경이 아니다.

## 재검증 도구와 범위

- `scripts/integration-coverage.py --output-dir=evidence/phase27/<새 폴더>`: 52개 기능·15 AC·초기 21 FT 연결 점검.
- `scripts/verify-integration.mjs --output-dir=evidence/phase27/<새 폴더>`: 필수 로컬 게이트와 실제 앱·출력·설정 자동 회귀. 기존 폴더 재사용은 거부한다.
- `tools/integration-obs-check.mjs <새 결과 폴더>` 및 `tools/integration-obs-pixels.py --directory=<그 폴더>`: 격리 OBS에 세 경로를 준비하고 실제 화면·알파·상태 차이를 확인한다. 로컬 시험 전용 OBS·비공개 연결 설정이 먼저 필요하다.
- `tools/integration-external-check.mjs <run 폴더>`: 검증된 공식 실행기와 격리 OBS를 사용한다. 현재 PC의 비공개 시험 경로를 전제로 하며 깨끗한 Windows 재현·배포 승인 도구가 아니다.
- `scripts/integration-review.py --run=<run 폴더>`: 새 결과·외부 대상 근거를 읽어 완료/미완료와 해시를 고정한다. 실제 장치·초보자·성능·선형 종단 검증을 자동으로 통과시키지 않는다.

소스 변경 없이 통과한 자동 결과와 이후 사람 관찰 결과를 구분한다. 새 도구의 Python 정적 검사·JavaScript 구문 검사도 별도로 수행했다. 패키징 코드는 변경하지 않았으므로 이번 결과는 기존 배포본의 새 검증으로 해석하지 않는다.
