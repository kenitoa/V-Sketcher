# 21. 실행 준비·바로 실행·빠른 조작

2026-11-18 · 앱 0.16.0 · 프로젝트 모델 1.9 유지 · T-201~210.

**현재 상태:** T-201~208·T-210의 구현/자동 검증을 완료했으며 **T-209는 실제 OS 전역 입력 확인 대기**다. 21단계 전체 완료로 표시하지 않는다. Windows 조작 도구의 네이티브 파이프 연결이 실패했고, 별도 시험 창은 실제 키 콜백이 관측되지 않아 20분 뒤 종료·등록 해제했다. 사용자 입력이 확인되면 새 실행으로 T-209를 마무리한다.

**실행 준비**에서 수동·자동 눈 깜빡임·카메라·마이크·카메라+마이크 중 하나를 선택한다. 수동·자동 모드는 장치를 열지 않는다. 외형·파일·참조·매개변수·진행 작업과 해당 모드의 장치를 검사한다. 차단은 수정 후 시작하며, 경고는 제한 이유를 표시한다. 필요한 장치가 없으면 수동 모드로 바꾸거나 **장치 없이 제한 실행**을 명시적으로 선택한다. 문제 위치로 이동해 수정하고 다시 **실행 준비**를 연다.

최근 목록의 **바로 실행**은 미저장 처리 뒤 저장 프로젝트를 열고 마지막 PC 실행 모드로 검사한다. 준비되면 시작하며, 장치가 없거나 수정할 문제가 있으면 준비 화면에 머문다. 세 제작 경로를 다시 만들 필요는 없다.

실행본에는 검증한 리비전·프로젝트 해시·독립 파일 참조를 보관한다. 실행 화면에 작업본과 실행본 리비전을 표시하며, 실행 중 편집은 잠근다. 동시 편집·변경 반영·프로젝트 전환은 22단계 범위다. 중지하면 실행본·렌더러·장치·등록한 전역 키를 정리하고 미저장 편집과 저장본은 유지한다. 시작 실패도 부분 실행을 정리한 뒤 재시도 또는 장치 없는 실행을 제공한다.

| 조작 | 결과 |
|---|---|
| 기본 자세 고정 | 작성된 기본 자세로 고정/해제. 선택한 저장 표정은 유지 |
| 표정 해제 | 저장 표정 해제. 기본 자세 고정은 별도 유지 |
| 캐릭터 숨김 | 투명하게 표시/복귀. 입력·실행은 유지 |
| 중립 재보정 | 선택한 카메라 얼굴의 중립 후보 측정·적용/취소 |
| 실행 중지 | 렌더링·장치·전역 등록 해제. 프로젝트 보존 |

단축키는 **빠른 조작 키 설정**에서 사용 여부·조합·앱 전용/전역을 선택한다. 기본은 앱 전용이며 전역은 PC에서 명시적으로 허용한다. `Control+Alt+Shift`와 숫자 또는 `F1~F11`만 허용한다. 사용 중 조합 중복·예약 키·실제 OS 등록 실패를 구분한다. 충돌 키는 다른 조합으로 바꿔야 한다. 등록되지 않은 키를 성공으로 표시하거나 다른 앱의 등록을 해제하지 않는다. 상태는 현재 실행 모드와 프로젝트 표정 슬롯도 반영한다.

기본 자세/숨김은 누를 때마다 토글, 표정 슬롯/해제/중립/중지는 단발 명령이다. 앱 전용은 주 실행 창 안에서만 동작한다. 글 입력·한글 조합·키 설정·중첩 대화상자·반복 키 입력은 보호한다. 전역 키는 다른 앱에서도 실행 중에만 동작하며 키 설정과 앱의 기본 저장 확인 대화상자에서는 초점 밖에서도 일시 보류한다. 프로젝트에는 표정 슬롯만, PC에는 실행 모드·키 조합·전역 허용을 저장한다.

## 검증과 범위

[필수 gate와 소스 해시](../../evidence/phase21/verification.json), [전체 개발 앱 회귀](../../evidence/phase21/development-run.json), [같은 PC의 release 격리 검사](../../evidence/phase21/package-audit.json), [완료 대기 감사](../../evidence/phase21/pending-review.json)를 구분한다. 17개 실행 관련 Node 그룹을 추가했으며 총 Node 242 + Python 36 = **278개 검사 그룹**을 수행한다. 대기 감사의 `implementationChecksPassed`와 전체 단계의 `phaseComplete`를 구분한다.

실행 UI는 실제 세 제작 경로를 준비해 고급 원화 GPU 표시·투명 숨김·표정/기본 자세 분리·앱 키/IME/텍스트/키 설정 보호·각 경로 4회 시작·중지·미저장 보존·장치 없음 대체·문제 위치·최근 바로 실행을 검증한다. 합성 오디오를 실제 AudioWorklet로 실행본에 전달하고 권한 거절 뒤 정리·수동 재시작을 확인한다. 자동 시험의 OS 전역 입력·실물 장치는 **NOT_RUN**으로 남긴다. [별도 전역 키 시험](../../evidence/phase21/live-global-keys-timedout-01.json)은 실제 OS 등록·주 창 밖 시험 창의 초점·종료 후 소유 키 해제를 확인했으나, 실제 키 콜백은 관측되지 않았다. 이것을 전역 입력 통과로 세지 않는다. [조작 도구 연결 실패](../../evidence/phase21/computer-use-status.json)와 앞선 실패 기록도 보존한다.

첫 픽셀 검사는 WebGL 버퍼를 읽는 시점 문제로 실패해 실제 그린 직후의 측정으로 바꿨다. 전체 회귀에서 표정 해제 직후 상태가 다음 프레임까지 늦는 문제를 고쳐 조작 즉시 평가하도록 했다. 다음 회귀의 화면 준비 전 선택 문제는 시험 코드가 실제 화면 반영과 닫힘을 기다리게 수정했다. 실패·취소 기록을 덮지 않고 최종 필수 gate·전체 회귀·격리 release로 다시 검증한다.

포터블 release는 한글·공백 경로·새 프로필 2개·Windows 시스템만 남긴 PATH에서 기본/1080×720 크기를 확인한다. 같은 PC의 OS·드라이버·시스템 DLL은 유지된다. 별도 PC/VM·USB 물리 분리·실제 사람의 카메라/음성 장면·OBS 출력·독립 아바타 내보내기·장시간 성능 승인으로 확대하지 않는다. [T-190 실패](../../evidence/phase19/live-summary.json), M0 HOLD·5 OPEN과 필수 세 경로·고급 아트·로컬 실행/방송·독립 내보내기·장기 3D/자체 모델 생성은 유지한다.

재현은 근거를 보존한 별도 작업공간에서 `node scripts/verify-execution.mjs`, release 패키지 생성 뒤 `node scripts/execution-package-check.mjs --evidence-dir=<새 결과 폴더>`로 수행한다. 현재 대기 감사는 `python scripts/execution-pending-audit.py --todo-from-index`이며 실제 키 확인 전 T-209를 완료하지 않는다. `execution-audit.py`의 전체 완료 감사는 실제 OS 입력 통과 이후 수행한다. 기존 근거를 덮어쓰지 말고 새 실행 기록을 사용한다.
