# 19. 카메라 연결·중립 보정·추적 매핑

2026-11-18 · 앱 0.14.0 · 공통 모델 1.9 · T-181~190.

## 사용

세 제작 경로에서 캐릭터를 준비하고 **카메라·추적 보정**을 연다. 카메라를 골라 **선택한 카메라 연결**을 누른다. 권한 전 목록이 비어 있으면 기본 카메라 연결 후 목록을 확인한다. 장치 열기·영상 수신·얼굴 수·선택 대상 추적 상태를 구분해서 확인한다. 영상이 온다고 얼굴이 검출된 것은 아니다.

**사용자용 카메라 영상 표시**는 원본을 이 화면에서만 보여 준다. 미러 표시는 캐릭터 방향/저장 매핑을 바꾸지 않는다. 복수 얼굴은 화면의 번호와 위치를 보고 선택한다. 겹침·대상을 오래 놓침에는 직접 재선택하며 다른 얼굴로 자동 갈아타지 않는다. 카메라를 정면에 두고 얼굴이 충분히 크게 보이도록 거리·조명을 조절한다.

정면에서 눈을 뜨고 입을 편하게 다문 뒤 **중립 다시 맞추기**를 누른다. 안정된 표본이 모이면 **새 기준 적용**을 누른다. 취소/실패는 기존 정상 기준을 바꾸지 않는다. 매핑에서 부위별 사용/방향/범위/강도/부드러움/중립 여유를 바꾸고 저장한다. 장치 기준은 이 PC에, 매핑은 프로젝트에 보관한다. 다른 프로젝트/카메라로 바꾸어도 원화와 표정 구조를 유지한다.

창을 닫으면 연결된 추적은 유지한다. 주 화면의 카메라 상태/중지 버튼 또는 이 화면의 **카메라 중지**로 끝낸다. 프로젝트/세션을 바꾸거나 앱을 닫으면 장치·추적 프로세스와 일시 입력을 해제한다. 자동 재연결·마이크·복합 손실 복구는 20단계 후속이다.

필수 로컬 gate의 **241개 그룹(Node 205 + Python 36)**과 전체 개발 앱 회귀가 통과했다. 세 실제 제작 경로의 합성 영상·실제 worker 추론·기준 적용/취소·모의 어두운 입력·정책 저장/undo/redo·복사/재열기를 검증했다. 실제 두 원화 얼굴의 모델 검출과 대상 순서/겹침/교대 검사를 포함한다. 이것을 실제 두 사람 검증이라고 부르지 않는다. [소스 해시·자동 검사](../../evidence/phase19/verification.json), [전체 개발 앱 결과](../../evidence/phase19/development-run.json).

같은 PC의 한글·공백 경로에서 개발 도구를 PATH에서 제거한 release를 새 프로필로 2회 실행했다. 기본 창과 1080×720 창에서 세 경로·동결 worker의 실제 로컬 추론·보정·저장 왕복·샌드박스/격리/외부 네트워크 차단을 확인했다. 물리 장치는 열지 않았다. OS/DLL/드라이버는 같은 Windows이므로 별도 깨끗한 PC 검증이라고 부르지 않는다. [패키지 감사](../../evidence/phase19/package-audit.json), [작은 창](../../evidence/phase19/release-tracking-compact.png), [문서·증거 감사](../../evidence/phase19/audit.json).

[첫 전체 회귀의 카메라 실패](../../evidence/phase19/development-failed-01.json)도 보존한다. 앞선 편집 검사 이후 대상을 놓친 상태에서 자동 절차가 재선택 없이 보정을 기다렸다. 대상 유지 제한은 바꾸지 않고, 시험에서 얼굴 위치를 명시적으로 다시 선택하고 제한된 횟수와 대기 시간 안에 안정 보정을 재시도하도록 수정했다. 이 절차도 안정된 실제 모델 표본을 얻지 못하면 실패한다.

## 실제 입력 기록

첫 물리 카메라 실행은 영상 수신에는 성공했으나 정상 구간도 화면 평균이 낮았고 얼굴 검출·중립 보정을 통과하지 못했다. 사용자는 얼굴/캐릭터 움직임을 보았고 두 사람·카메라 앞 가림을 수행했다고 확인했다. 관찰을 계측 통과로 바꾸지 않고 [원래 결과](../../evidence/phase19/live-run-01.json)와 [사용자 관찰](../../evidence/phase19/live-run-01-observation.json)을 보존한다.

재시험은 카메라/밝은 정면 얼굴/대상 번호를 확인하는 준비 단계를 추가했다. 배경이 어두워도 얼굴은 밝을 수 있으므로 보정 밝기는 선택 얼굴 영역을 사용한다. 사용자는 시작 버튼과 얼굴 표시·밝은 조명을 다시 확인했다. HD Webcam을 명시적으로 선택한 재시험에서도 분석 입력은 화면 평균 약 26/255·얼굴 0명으로 계측되어 안정된 정면 기준을 만들지 못했다. 영상 재생과 분석 입력 차이를 줄이기 위해 사용자 미리보기를 분석과 동일한 메모리 캔버스로 변경했다. [동일 캔버스 재시험](../../evidence/phase19/live-run-05.json)도 120초 준비 구간에서 안정된 얼굴을 확보하지 못했고, [마지막 집계](../../evidence/phase19/live-run-05-last-progress.json)는 영상 수신·밝기 25.54/255·얼굴 0명이다. 카메라 열기 실패와 얼굴 미확보를 구분하며 이 실행은 실제 장면 측정 시작 전 종료됐다.

별도 DirectShow 진단도 70프레임에서 원시 모델 얼굴 검출 0건이었다. 이 진단의 카메라 인덱스 0을 브라우저 장치와 동일하다고 단정하지 않으며, 진단의 `passed`는 영상 읽기 완료만 뜻한다. [종합 상태](../../evidence/phase19/live-summary.json), [진단 범위](../../evidence/phase19/directshow-diagnostic-scope.json). 재시험의 실제 계측과 사용자 확인 후 T-190을 완료 처리한다. 시작하지 않은 준비 단계나 합성 입력은 실제 정상/복수 사람 시험의 통과 근거로 사용하지 않는다.

## 종료와 한계

현재 실제 환경 재시험이 남아 있으며 19단계 전체 완료로 표시하지 않는다. **M0 HOLD·5개 OPEN**을 유지한다. 실제 영상은 파일/기본 로그/프로젝트에 보관하지 않는다. 두 사람의 신원 인식, 칠흑/강한 역광/심한 가림에서의 추적 보증, 물리 조도·성능/장시간·마이크/방송·독립 아바타 내보내기·전체 M3 승인도 하지 않는다. 세 제작 경로·고급 원화·앱 실행/방송·독립 내보내기·필수 장기 3D/자체 모델 생성 범위를 유지한다.

재현은 `node scripts/verify-tracking.mjs`로 필수 gate와 전체 개발 앱 검사를 실행한다. 새 worker를 빌드한 release 패키지에서 `node scripts/tracking-package-check.mjs --evidence-dir=evidence/phase19`를 실행한다. 실제 카메라 시험은 사용자가 준비한 구간에 별도로 실행하며 자동 회귀에서는 하드웨어를 열지 않는다. [실행 계약](../architecture/camera-tracking.md).
