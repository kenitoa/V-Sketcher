# 용량·메모리 정리와 성능 보존

2026-11-19. 실제 작업 폴더 약 190GiB를 약 10GB 수준으로 줄이되 세 제작 경로, 프리미엄 원화, 로컬 실행/방송, 독립 내보내기와 장기 필수 기능을 유지한다. 메모리 최적화를 우선하고 기존 `apps/`, `packages/`, `worker/`, `scripts/`, `tools/` 구조를 유지한다.

## 기준과 변경

- 정리 전 유효 측정은 `evidence/cleanup/run-01/before-02.json`이다. 전체 논리 크기 205,845,654,544바이트, 191.709GiB다. 디렉터리 링크는 따라가지 않는다. 첫 `before.json`의 Windows 파일 ID 집계는 잘못되었으므로 중복 제거 크기의 근거로 사용하지 않는다.
- 용량의 대부분은 반복 시험의 프로젝트 ZIP, 포터블 실행 사본과 예전 연구 환경이었다. 코드나 원화 품질을 낮춰서 줄이지 않는다. 공개 `experiments/`와 기존 `evidence/`의 코드·자산·결과는 변경하지 않는다.
- 오래된 비공개 재실행 자료는 `.local/replay-store-01/`에 내용 해시로 중복 제거하여 보관한다. ZIP 내부의 압축된 원시 바이트 경계를 이용하며 ZIP을 다시 인코딩하지 않는다. 파일마다 재구성 SHA-256과 원본 SHA-256을 확인한 후 그 파일만 제거한다. 변경된 파일·활성 프로세스·연결 경로는 보존한다. 보관본도 최종 폴더 크기에 포함한다.
- 렌더러는 처음 선택 검사에 필요한 텍스처의 알파만 1바이트/픽셀로 보관한다. 선택 검사마다 만들던 캔버스/컨텍스트를 없애고, GPU 업로드 후 디코딩 이미지를 해제한다. 이미지 디코딩은 두 개까지만 미리 진행하고 GPU 알파 추출의 RGBA 읽기를 한 번에 1MiB 이내로 제한한다. 매 프레임 그래픽 위치 조회와 행렬·정렬 배열도 재사용한다. GPU 텍스처·원화 해상도·움직임 계산은 유지한다.
- 현재 직접 관리하는 JS/TS/TSX/Python/CSS/HTML 코드를 일관되게 정리한다. 프로그램 AST가 달라지는 자동 변경은 반영하지 않는다. JSX의 실제 문자열 자식과 객체 키 표기는 정규화하여 비교한다. 원본은 `format-*/source-before.zip`에 남긴다. 외부 의존성·생성 코드·실험 소스는 대상에서 제외한다. [Prettier 설치 지침](https://prettier.io/docs/install), [Ruff formatter](https://docs.astral.sh/ruff/formatter/)를 사용한다.

## 재증가 방지와 복원

22개 테스트 파일은 `tests/temp.ts`의 고유한 시스템 임시 영역을 사용한다. 각 프로세스의 테스트가 끝나면 소유권 표식을 확인한 뒤 그 실행이 만든 영역만 정리한다. 경로 이탈·표식 변경·외부 junction 대상 보존을 실제 파일 시험으로 확인한다. 제품 설치본·GPU·렌더러 비교의 임시 실행 사본도 시스템 임시 폴더에서 실행하고 정리한다. 측정 결과와 필요한 최소 화면만 저장소에 남긴다.

```text
tools\cache.cmd restore <보관 그룹>
.venv-product\Scripts\python.exe -I scripts\research-restore.py
```

`restore`는 보관본을 먼저 전부 검증하고, 기존 목적지를 덮어쓰지 않으며, 복구에 필요한 공간과 512MiB 여유를 확인한다. `research-restore.py`는 선택적 오프라인 연구용 Torch 환경·학습 가중치·Blender를 네트워크 없이 원래 바이트로 복구한다. 현재 제품 worker와 실제 3D 추적/뷰어의 실행 의존성은 상시 유지한다. 연구 도구를 처음 다시 실행할 때는 복구 시간과 확장 공간이 필요하다. 모델 양자화·정확도 축소는 하지 않는다.

`tools\three-d-learned.cmd`는 Torch/가중치를 복구한 뒤 기존 실험을 실행하는 진입점이다. 큰 가중치의 해시 검사도 파일 전체를 메모리에 올리지 않고 스트림으로 처리한다. 이전 포터블 후보·OBS/독립 대상 개발용 사본은 해당 보관 그룹을 복구하면 원래 경로에서 다시 시험할 수 있다.

## 검증과 판정 경계

최적화 전 실제 소스를 `.local/cleanup-baseline-01/`에 고정했다. 같은 프리미엄 장면을 여섯 개 새 Electron 프로세스에서 before/after/after/before/before/after 순으로 비교한다. 여섯 포즈의 전체 픽셀 SHA-256, 여섯 포즈에 대한 3,750개 선택 결과, GPU 완료까지의 draw 시간과 15초 30Hz 루프, 생성자/로딩/준비 완료 시간, 실행 중 및 최대 renderer working set을 기록한다. 예비 시험의 disposal 이후 메모리는 실행 중 메모리 절감의 근거로 사용하지 않는다. 다른 GPU 시험과 겹친 실행도 최종 성능 판정에서 제외한다.

[최종 렌더러 비교](../../evidence/cleanup/bench-final-04/comparison.json)는 모든 기준을 통과했다. 최대 renderer working set은 188,712→140,672KiB(약 25.5% 감소), 실행 중 중앙값은 167,640→129,524KiB, 준비 완료 중앙값은 292.2→209.6ms, draw p95는 1.3→0.8ms다. 여섯 포즈의 픽셀과 3,750개 선택 결과는 일치하고 약 30FPS를 유지했다. 전체 앱/장치/OBS의 출시 성능 수치로 확대 해석하지 않는다. 이전 실패·예비 실행은 보존하고 최종 근거로 사용하지 않는다.

직접 관리하는 코드의 불필요한 import 48개는 실제 고정 TypeScript 7.0.2 컴파일 결과의 프로그램 구조가 동일할 때만 제거했다. `noUnusedLocals`/`noUnusedParameters`와 Python 미사용 import 검사를 필수 게이트에 추가했다. 최종 필수 검사는 Node 359개와 Python 58개, 총 417개가 통과했고 새 GPU 자원 생성·해제 12회도 통과했다. 정리 도구의 추가 방어 처리는 해당 15개 검사를 다시 통과했다.

[대형 가중치 해시 비교](../../evidence/cleanup/hash-01/comparison.json)는 같은 1,677,246,742바이트 입력을 네 개 새 프로세스에서 교차 검사했다. 해시는 모두 같고 최대 working set은 1,622.96→23.39MiB였다. 추론이나 가중치 정밀도를 변경한 결과가 아니다.

417개 필수 검사를 통과한 뒤에도 설치본의 실제 실행에서 입력 복구 문제가 드러났다. 브라우저의 `requestAnimationFrame` 인자는 직전 프레임의 시각이며 콜백 실행 시점과 다를 수 있다([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)). 실시간 입력 합성은 콜백을 소비하는 현재 시각을 사용하고 오디오 시각은 수신 시각보다 미래가 되지 않도록 바꿨다. [개발 앱 회귀](../../evidence/cleanup/input-clock-01/report.json)는 페인트 시각을 100ms 늦춘 조건에서도 세 경로를 통과했고 표정 해제 후 입력 복귀는 62.5/64.3/69ms였다. 오래된 입력·중복·직접 전달된 미래 제어 패킷의 거부는 유지한다. 이 수정은 0.22.4 후보에 포함되며 설치본 검증은 별도로 판정한다.

[Git 저장 방식 정리](../../evidence/cleanup/git-storage-01/storage.json)로 저장량은 1,209,193,606→679,902,020바이트가 되었다. 모든 객체·참조·인덱스와 추적 파일의 작업 상태가 그대로인지 확인했다. 이력이나 미참조 객체를 가지치기하지 않았다.

필수 게이트는 `tools\dev.cmd run check`다. 설치본은 변경 버전마다 별도 동결하여 개발 도구 없는 PATH의 설정 검사 두 번, 전체 포터블 회귀와 같은 프로필 재시작을 검증한다. 동결 ZIP은 덮어쓰지 않는다. 실패한 실행을 다른 결과로 바꾸지 않고 새 실행을 남긴다.

실제 장치·OBS·2시간·독립 지연 계측·실제 초보자·새 Windows·출시 후 사건은 별도 수용 조건이다. 이 정리와 자동 시험으로 26~31의 남은 20개, 추적/원화 결함 또는 M0의 다섯 OPEN을 완료 처리하지 않는다. [20개 작업 실행 도구](./26-31-completion.md)로 실제 근거를 판정한다. 현재 M0/출시는 HOLD다.
