## DEC-01. Windows와 배포 — T-041

**채택:** 초기 제품은 **Windows 11 x64 데스크톱 앱**, 첫 배포 단위는 **포터블 ZIP 안의 단일 진입 EXE와 동반 런타임/리소스 폴더**다. 일반 사용자는 Python·Node·명령줄·개발 도구를 설치하지 않는다. 사용자별 설정·복구는 `%LOCALAPPDATA%/2DSketcher/`에, 사용자 프로젝트는 선택한 저장 위치에 둔다. EXE 폴더가 읽기 전용이어도 프로젝트·설정 처리가 가능해야 한다. 설치형·자동 업데이트·스토어 배포는 첫 배포에 포함하지 않는다. 서명과 새 PC 실행 시험을 공개 배포의 선행 조건으로 둔다.

| 구분 | 범위 / 근거 |
|---|---|
| 현재 실제 검증 장비 | Windows 11 Pro 10.0.26300, i5-13420H, 32GB급 RAM(실측 31.71GiB), RTX 4050 Laptop 6GB + Intel UHD. HD Webcam 640×480·내장 마이크 배열 |
| 제품 성능 판정 기준 장비 | 위 PC의 전원 연결·성능 설정 고정. OBS 33.0.1, 1캐릭터, 1920×1080 투명 아바타 출력, 1280×720/30FPS 로컬 x264 기록 조건을 고정한다. 성능 목표는 [별도 게이트](./05-release-gates.md) 참조 |
| Windows 버전 정책 | Windows 11 x64 중 제조사 보안 지원 중인 정식 배포 버전만 출시 검증 대상으로 삼는다. 실제 통과한 OS 빌드·GPU 드라이버를 릴리스 지원표에 명시. 26300 한 대의 성공을 모든 Windows 11 버전 지원으로 일반화하지 않음 |

| 장치 | 첫 검증은 UVC 웹캠 640×480/30 및 Windows 기본 입력 마이크. 출시 전 서로 다른 웹캠 2종·내장/USB 또는 헤드셋 마이크 2종 시험. 과거 헤드셋 경험을 이번 실측으로 세지 않음 |

**이유:** 실제 사용 환경과 04의 장치·외부 구동 근거가 Windows에 있다. 포터블 EXE는 현재 `.ps1` 실행 제한과 개발 환경 의존을 사용자 흐름에서 제거한다. Electron의 다른 OS 실행 가능성은 제품 지원 약속으로 옮기지 않는다. 다른 PC의 포장 실행과 GPU/worker 연결은 M0-R01/R05 및 T-060에서 재검증한다.

## DEC-02. 한 장 그림 — T-042

**채택 입력:** PNG(RGB/RGBA 8bit), JPEG(RGB 8bit). EXIF 방향을 정규화하고 편집용 색은 sRGB, 내부 원본 참조는 가져온 바이트 그대로 보존한다. ICC 변환 실패·CMYK·16bit/HDR·애니메이션 GIF/APNG·SVG/WebP·실행 가능한 문서는 첫 입력 형식에서 제외하고 변환 안내를 제공한다. 지원하지 않는 확장자를 이름만 바꿔 읽지 않는다.

| 항목 | 구현·지원 목표 | 현재 증거 / 남은 조건 |
|---|---|---|
| 크기 | 한 변 256~4096px, 총 16,777,216픽셀 이하. 원본 전체 디코드·작업 메모리 예산을 먼저 검사 | 03 한도는 4,194,304픽셀이고 주 실측은 512/1254px. **4096px는 새 구현 한도 결정이며 검증 완료가 아님** |
| 기본 구도 | 캐릭터 한 명, 정면 또는 작은 기울기, 두 눈·입·머리·상반신이 확인되고 주요 부위가 잘리지 않은 입력 | 대표 표본의 기술 연결은 확인. 모든 화풍에서 자동 인식 성공을 보장하지 않음 |
| 배경 | 투명 PNG 우선. 단색/복잡 배경 RGB도 입력은 받되 분리·영역 확인이 필요하면 안내 | 배경 제거 실패를 자동 리깅 성공으로 표시하지 않음. JPEG는 원본 보존 후 편집용 PNG 파생 |
| 분석 해상도 | 분석용 파생을 최대 1024px로 만들고 원본↔분석 좌표 변환을 보존. 렌더 텍스처는 별도 GPU 예산 안에서 원본 세부를 유지 | 분석 축소와 출력 축소를 같은 처리로 보지 않음. 고급 얼굴·가닥·의상 디테일 손실은 품질 게이트 |
| 복수 인물 / 가림 | 인물 선택·부위 보정 또는 제한된 움직임으로 진행. 모르는 눈·입은 자동 연결하지 않고 상태를 설명 | 완전 가림·옆/뒤 모습·극단 왜곡·부위 누락의 완전 자동화를 최초 보증에서 제외. 지원 밖 입력도 실패 분모에 기록 |
| 자동 보완 | 보이는 원본과 추정 영역을 구분하고, 보완은 별도 파생 자산으로 저장. 사용자가 보완을 끄거나 다시 지정 가능 | 04의 추가 표정 생성·수동 ROI를 ‘그림 한 장 자동 준비 완료’로 세지 않음 |

PNG/JPEG 읽기 지원과 **자동 움직임 준비의 지원 조건**을 분리한다. 이번 인식 18건의 7성공·7부분 실패·4실패 때문에 ‘모든 그림 자동 리깅’을 지원 문구로 사용하지 않는다. 기술적으로 읽히지만 준비를 끝낼 수 없는 입력에는 이유·원본 보존·다른 경로/보정 안내를 제공한다. M0-R02/R03의 고급 입력·초보자 검증을 통과한 조건만 실제 지원표에 올린다.

## DEC-03. 분리 그림 — T-042

**채택:** 투명 PNG 폴더 가져오기와 앱이 읽고 쓰는 `.2dparts` ZIP 묶음을 최초 형식으로 삼는다. PSD/PSB의 직접 레이어 디코딩은 최초 범위에서 제외한다. 분리 그림 경로 자체는 필수이며, 별도 전문 도구나 JSON 수기 작성을 사용자 시작 조건으로 만들지 않는다.

- 공통 캔버스 PNG 폴더는 순서·역할 제안을 보여 주고 사용자가 눈·입·머리·몸체를 확인한다. 파일명은 힌트이며 확정 역할·좌우를 덮어쓰지 않는다.
- 잘린 PNG는 원점 좌표가 필요하다. `.2dparts`의 `manifest.json` 또는 앱 배치 화면에서 위치를 정한다. 원점이 없는 잘린 부위를 조용히 중앙에 놓고 성공으로 처리하지 않는다.
- 묶음 v1은 `schemaVersion`, `canvas {width,height}`, `layers [{id,path,origin,z,role,side,opacity,group}]`, 선택 `groups`와 자산 해시를 가진다. 단위는 원본 캔버스 px, 좌상단 원점, +x 오른쪽/+y 아래. 좌우는 캐릭터 기준, 그리기 순서는 z 오름차순과 안정된 ID 순서다.
- 1~64부위, 최대 1024개 엔트리, ZIP 파일 256MiB·압축 해제 합계 512MiB 한도. PNG별 DEC-02 크기 한도와 합산 디코드/GPU 메모리 예산도 별도로 적용한다. ZIP 엔트리 수·이름·비압축 크기를 **해제 전에** 검사한다.
- 허용 내용은 선언한 JSON/PNG 자원뿐이다. 절대 경로·`..`·역슬래시 원래 엔트리·드라이브 경로·대소문자 충돌·심볼릭 링크·암호화·중복 ID·참조 누락을 거부한다. 원본 이름은 메타데이터로 남기고 내부 저장 참조는 해시 기반 상대 경로다.
- 최초 합성은 normal source-over와 계층 opacity를 지원한다. 다른 혼합 모드·조정 레이어·그룹 변환은 임의로 평탄화하지 않는다. 사전 변환·손실 동의가 없으면 가져오기 차단 또는 필요한 수정 안내로 돌린다.

03의 공통/잘린 원점 재현과 이름/역할·그룹 opacity 검증을 근거로 선택했다. 05의 ZIP 정책 실험에서 Windows의 파일명 정규화가 원래 역슬래시를 숨길 수 있음을 확인해 원래 엔트리 이름까지 검사하도록 고쳤다. 실제 PSD 지원이나 제품 ZIP 보안 검증 완료로 해석하지 않는다.

## DEC-04. 최초 고급 파츠 구성 — T-043

**채택 아트 목표:** 하나의 일관된 고급 2D 스타일 계열을 먼저 완성한다. 얼굴/피부 계열 2, 앞·뒤가 맞는 머리 세트 2, 좌우 눈 세트 2, 입 세트 2, 상반신 의상 2, 장식 있음/없음 2를 제공하는 **64개 유효 기본 조합**을 출시 검증 대상으로 정한다. 이는 제작 수량 결정이며 이미 제작한 자산 수가 아니다. 조합 간 공통 좌표·연결점·중립 크기·가림 규칙을 지킨다. 이름만 다른 동일 그림을 선택지 수로 세지 않는다.

눈은 좌우별 open/half/closed, 입은 closed/open/smile을 최소 상태로 갖춘다. 앞/뒤 머리는 맞는 한 세트로 먼저 교체하며 개별 조합 확대는 호환 검증 뒤 진행한다. 색·크기 조절은 원화의 질감·얼굴 인상이 무너지지 않는 검증 범위만 노출한다. 64개 모두의 중립·기본 움직임·겹침·투명 경계와 저장/교체/외부 사용을 검사한다. 사용자가 보는 기본값에는 절차 도형을 쓰지 않는다.

현재 PREMIUM-003은 고급 원화/표정의 품질 기준 자료이지 위 파츠 라이브러리가 아니다. 04의 전체 초상+눈/입 패치 4부위를 완전 분리된 고급 파츠로 세지 않는다. M0에는 서로 다른 고급 조합 최소 2개로 핵심 표현 가능성을 먼저 재검증하고, 64개 전체는 출시 게이트다. 부족한 제작 자원을 이유로 도형 라이브러리로 바꾸지 않는다.

## DEC-05. 움직임·공통 표현 — T-043

**채택 계약:** 다섯 의미 제어 `eye_left/right` 0~1(중립 1), `mouth` 0~1(중립 0), `head_yaw/roll` -1~1(중립 0)을 유지한다. `head_yaw`는 작은 2D 좌우 변형이며 실제 3D 옆면 복원이 아니다. 최초 정상 범위는 고개 기울기 ±6°, 좌우 이동/변형은 얼굴 폭의 ±4.5%다. 가림 입력은 최대 0.35 배율, 불확실한 자동 입 보완은 최대 0.65로 시작해 보정 확인 전 확대하지 않는다. 준비된 입 그림이 있는 파츠는 검증 후 전체 0~1을 쓴다.

원화 텍스처와 공통 삼각망·가중치·매개변수 곡선을 저장하고 **GPU에서 변형·합성**한다. 몸체 고정과 상부 움직임을 분리한다. 고급 원화 전체를 매 프레임 CPU로 변형→PNG 인코딩→OBS로 보내는 경로는 제품 실행 엔진으로 채택하지 않는다. 04의 빠른 전체 초상 ±3° 이동과 INP ±8°의 차이를 공통 의미가 같다는 이유로 방치하지 않는다. 내부/외부의 같은 제어 격자에서 시각·좌표 비교를 통과해야 한다.

추적은 최초 유효 얼굴의 중립 보정, 축별 방향·gain, 입력 유효성·범위 검사, 독립된 시간 기반 손실 감시를 갖춘다. 얼굴 손실 300ms 후 중립으로 완화하고, 입력 스레드 대기가 평활화를 건너뛰게 하지 않는다. 복귀는 04의 갱신 dt/변화량 제한을 출발점으로 삼되 실제 표시 주기의 연속성으로 재검증한다. 눈의 임계 전환/단순 압축·입 crossfade를 최종 품질로 고정하지 않는다.

입 소유자는 카메라 또는 마이크 중 사용자가 선택한 하나다. 음량을 얼굴 jawOpen과 더하지 않는다. 초기 마이크는 소음 보정+RMS gate/gain 후보를 유지하되 고정 `.015`를 제품 기본값으로 확정하지 않는다. VAD 필요성·약한 발화·큰 소음 반응은 M0-R02의 추가 검증으로 돌린다. 수동 표정은 지정한 제어만 덮어쓰고 해제하면 최신 입력으로 완화 복귀한다. 중립/눈 감기/미소를 최초 기본 표정으로 정한다.

## DEC-06. 방송 — T-044

**최초 대상:** Windows의 **OBS Studio 33.0.1 Browser Source**, 추가 플러그인 없이 로컬 URL의 투명 WebGL2 캔버스를 읽는다. 04는 실제 OBS PNG/canvas 수신·알파·녹화 인코딩을 검증했고, 05는 그 전달 방식을 유지하면서 **소스 안에서 텍스처를 한 번 올리고 제어값만 받아 렌더하는 구조**를 선택했다. 새 WebGL2 출력의 실제 OBS 성능·색·연결 복구는 아직 검증하지 않았다.

앱 미리보기와 방송 페이지는 같은 `scene-core`·셰이더·자산 계약을 사용한다. 편집 UI를 화면 캡처하지 않는다. 최초 출력은 1920×1080 RGBA/30FPS이며 자원 예산을 초과하면 원화 품질을 조용히 낮추지 않고 진단/지원 조건을 안내한다. 60FPS·다중 캐릭터·가상 카메라·Spout/NDI·다른 방송 앱은 첫 호환 보증에서 제외한다.

로컬 서버는 loopback 전용, 방송 읽기 권한만 가진 기기별 출력 프로필을 쓴다. 포트와 읽기 토큰은 기기 설정에 보관해 정상 재실행 후 저장된 OBS 소스를 재사용한다. 토큰은 프로젝트·공유 파일·로그에 넣지 않고 회전/재연결 경로를 제공한다. 카메라 프레임·원음·편집 명령·임의 파일 경로를 소스에 노출하지 않는다. 렌더 heartbeat 손실 때 캐릭터 정지 화면을 계속 정상으로 표시하지 않고 중립/투명 상태로 전환한다. OBS가 먼저 시작돼 오류 페이지를 잡은 경우의 새로고침·재연결을 안내/선택 연결 도구로 처리한다.

기본 연결은 사용자가 OBS에 브라우저 소스를 추가하는 안내다. 자동 설정은 **선택적 공식 OBS WebSocket 5.7.6/RPC1 어댑터**로 한정하며, 사용자의 기존 장면·녹화·방송을 임의 변경하지 않는다. URL 소스 준비·페이지 소비 ACK·OBS 미리보기 확인·실제 녹화/송출은 별개 상태로 표시한다. OBS/Inochi 실행기를 제품에 동봉하지 않고 공식 설치 경로를 안내한다.

## DEC-07. 첫 외부 형식 — T-044

**채택:** **INP, 공식 Inochi Session v0.8.7 / SDK v0.8.6 스키마 기준**을 최초 외부 대상과 호환 프로필로 정한다. 파일에 텍스처·부위·다섯 기본 움직임·최소 기본 표정/동작을 포함하고 앱/프레임 서버 없이 로드·사용할 수 있어야 한다. 단순 PNG·우리 프로젝트·실시간 제어 API 호출은 이 기능의 대체물이 아니다.

04의 독립 내장 애니메이션은 실제 확인된 범위다. 제품 프로필에서는 공통 망/곡선·연결 정보를 변환하고, straight-alpha→대상 premultiplied alpha, 원점·z·정수 UUID·단위를 명시한다. 외부에서 보존/근사/손실/차단을 부위·제어별로 검사한다. 핵심 눈·입·고개/표정이 사라지면 내보내기 완료로 표시하지 않는다. 제한 프로필을 제공할 경우 변경된 움직임을 먼저 미리 보여 주고 동의를 받아 별도 결과로 내보낸다.

추적 장치 설정은 자동 이전을 약속하지 않는다. 다만 최초 외부 활용 흐름에서 대상의 장치 바인딩/기본 동작 사용을 실제 확인하는 안내와 시험을 포함한다. 현재는 외부 웹캠/마이크 라이브 바인딩과 내부/외부 망 표현 동등성이 미검증이므로 M0-R04로 돌린다. 개발 브랜치 GUID 스키마나 다른 Session 버전을 검증 없이 지원표에 추가하지 않는다. Live2D moc3·VTube Studio·VRM은 최초 2D 호환 대상에서 제외하며 각각 별도 기술/사용 조건/실행 검증이 필요하다.

## DEC-08. 프로젝트 저장·복구 — T-045

**채택:** `.2dsketch` v1은 ZIP 기반 자급 묶음이다. `project.json`·`manifest.json`·해시로 참조하는 원본/파생 자원·표정/망/바인딩·출처를 포함한다. manifest는 엔트리 경로·바이트 수·SHA-256을 기록한다. 편집 파일은 특정 외부 형식과 분리하고 외부 결과/상태만 연결한다. 절대 개인 경로나 설치 폴더에 의존해 재개하지 않는다. 원본 자산 바이트는 불변이다. 실제 product schema 작성/이전 코드는 T-061 이후 작업이며 03 폴더 형식을 이름만 바꿔 새 제품 파일로 취급하지 않는다.

1. 저장 시작 때 project ID·revision·내용 스냅샷을 고정한다. 한 파일은 한 writer만 소유한다. 저장 중 새 편집이 생기면 저장 성공 후에도 새 편집은 미저장으로 남긴다.
2. 같은 볼륨에 임시 파일 작성→flush/fsync→다시 열어 참조/해시 검사→이전 정상본을 검증된 백업으로 보관→atomic replace 순서로 교체한다. 임시/백업 실패이면 정상본을 교체하지 않는다. 네트워크 드라이브·클라우드 동기화 폴더의 원자성은 최초 보증에서 제외한다.
3. 수동 저장의 이전 정상본 5개와 자동 복구 스냅샷 5개를 각각 보관한다. 정상본과 최신 복구본은 삭제 대상에서 제외한다. 프로젝트당 복구 공간 한도 2GiB에서 오래된 중복 자원을 먼저 정리하고, 최신본 하나도 못 쓰면 이전 복구본을 지킨 채 저장 위치/공간 안내를 한다.
4. 자동 복구는 편집 뒤 유휴 15초 또는 마지막 복구 후 60초 중 먼저 도달한 때 직렬화한다. 실행/입력 스레드를 막지 않으며 동일 리비전은 중복 저장하지 않는다. 자동 복구를 사용자의 명시 저장으로 표시하지 않는다.
5. 손상된 정상 파일을 조용히 덮어쓰지 않는다. 마지막 유효 백업/복구의 시각·revision·출처를 보여 주고 새 파일로 복구한다. 해시 실패·누락·파일명 충돌은 다른 상황으로 안내한다.
6. 새 major는 쓰기/마이그레이션을 막고 호환 안내한다. 더 높은 minor는 원본·모르는 필드를 보존한 읽기 전용으로 연다. 지원 버전의 이전은 복사본에서 수행하고 검증 성공 후 새 정상본으로 저장한다. 앱/뷰어/worker/셰이더 프로토콜 버전은 schemaVersion과 구분한다.

[정책 실험 31개](../../experiments/phase05/results/policy-verification.json)는 flush/백업/교체 전후 실패, ZIP 경로·해시·상한·버전, writer 충돌과 정상본/백업의 관계를 확인했다. **실제 디스크 가득 참·전원 차단·백신·동기화 폴더·제품 UI 통합 시험은 아니다.** Windows/파일 시스템의 전원 상실 내구성까지 원자 교체 한 번으로 보장하지 않는다. T-061~110/T-060의 실제 통합·배포 시험이 필요하다.

## DEC-09. 동시 편집·작업 — T-046

모든 작업은 `projectId / inputRevision / jobId / cancellationGeneration / protocolVersion`을 가진다. 화면의 현재 project/revision과 일치하고 취소되지 않은 결과만 적용한다. 오래된 결과·다른 프로젝트·중복 완료를 버리되 현재 정상 편집·실행·파일을 보존한다. 분석은 한 프로젝트당 한 개의 무거운 작업만 허용하고 사용자가 다시 시작하면 이전 작업을 취소 상태로 만든다. worker 종료 후 돌아온 지연 응답도 적용하지 않는다.

| 실행 중 동작 | 채택 정책 |
|---|---|
| 색·표정·검증된 수치 조정 | 새 리비전으로 편집, 텍스처/제어 스냅샷을 준비해 한 프레임 경계에서 완전히 적용 |
| 파츠 구조·망·원본 교체·재분석 | 현재 실행 스냅샷 유지. 준비/검사 후 ‘실행에 적용’에서 교체. 중간 구조를 실행에 노출하지 않음 |
| 저장/내보내기 | 시작 리비전의 불변 스냅샷 사용. 이후 편집은 결과물 메타데이터/이전 리비전 표시로 구분 |
| 프로젝트 전환 | 기존 작업의 적용 권한을 회수. 실행 중 캐릭터를 유지/전환할 의도를 명시하고 교차 프로젝트 결과 혼입 금지 |
| worker 실패/재시작 | 마지막 정상 캐릭터 유지, 입력/작업 상태 구분, 재시작 뒤 새 작업 ID/중립 보정. 무한 자동 재시도 금지 |

정책 모델에서 교차 프로젝트·오래된 리비전·취소/중복 응답 거부, frame boundary 적용, 저장 중 편집의 dirty 유지, export snapshot을 확인했다. 실제 Electron/Python IPC와 UI 경합은 후속 통합 시험이다.

## DEC-10. 처리 위치·데이터 이동 — T-046

**초기 2D는 로컬 처리로 확정**한다. 파일 분석·망/표정 준비·저장·MediaPipe 추적·마이크 RMS·렌더·OBS 전달·INP 생성에 서버 계정이나 인터넷을 필수로 두지 않는다. 모델과 기본 아트를 배포 패키지에 버전/해시와 함께 포함한다. 카메라 프레임과 마이크 PCM은 기본 메모리 처리 후 폐기하고 기본 로그에 저장하지 않는다. 진단은 시간/오류/집계 수치를 중심으로 하며 원본 그림·원음·영상·개인 경로·토큰을 기본 전송/기록하지 않는다.

Electron main이 파일/장치/worker/로컬 출력 권한을 소유한다. UI에는 제한된 preload API, Python worker에는 stdin/stdout의 크기 제한·버전이 있는 명령/결과 프로토콜을 둔다. OBS에는 제어값과 해당 아바타 자산만 전달한다. 임의 원본 경로를 URL로 읽는 API를 만들지 않는다. 장치 미리보기는 사용자 선택의 앱 내부 표시이며 방송 소스에 포함하지 않는다.

업데이트/외부 도구 안내의 네트워크 이동은 사용자가 요청한 공식 경로로 한정한다. 자동 업로드·원격 분석·사용자 자료의 학습 편입·텔레메트리를 기본으로 넣지 않는다. 3D·자체 모델 생성의 로컬/자체 서버 결정은 장기 DEC로 남기되, 새 네트워크 처리는 목적·자료·보관/삭제·동의를 별도 정의한다. 개발용 ImageGen 자산 제작을 제품 외부 생성 API 기능으로 바꾸지 않는다.

## DEC-11. 수치·표본·출시 기준 — T-047

[05 출시·M0 게이트](./05-release-gates.md)의 수치·장비·입력/동작·시간 구간·반복/표본·실패 처리 규칙을 **v1.0 판정 계약**으로 채택한다. 기존 10분/20분·30FPS·200ms·2시간의 제안을 계획 값으로 확정하되 현재 충족했다고 표시하지 않는다. 세 경로별 수치를 합계로 숨기지 않고 단순 fixture와 고급 원화를 별도 집계한다. 60FPS는 추가 목표이며 최초 통과 조건이 아니다.

현재 고급 캐릭터+카메라+OBS 인코딩의 14.08 고유 FPS는 FAIL, 센서→OBS 전체 지연·2시간·초보자 출시 표본은 NOT_RUN이다. 렌더 프레임/인코더 프레임/브라우저 ACK를 다른 지표로 정의한다. 품질·원화 인상·초보자 완주를 FPS로 대신하지 않는다. 결과가 없으면 통과가 아니며, 실패 뒤 범위를 줄여 합격을 만드는 대신 변경 기록과 재검증을 요구한다.

## DEC-12. 단축키 — T-046

기본은 **앱 안에서만** 적용한다. 텍스트 입력·IME 조합·모달 창에서는 문자/공통 편집 키를 동작으로 가로채지 않는다. 화면 버튼(표정·중립·추적 일시정지·재보정)을 항상 제공한다. 전역 단축키는 사용자가 켜고 조합을 선택하는 부가 설정이며 기기 설정에 보관한다.

Electron `globalShortcut`을 1차 OS 연결로 선택한다. 등록 성공을 실제 반환값과 등록 조회로 확인하고, 충돌/예약/권한 실패는 미등록으로 표시하며 다른 앱의 키를 빼앗거나 전역 hook으로 우회하지 않는다. F12/Windows 예약 조합은 기본 추천에서 제외한다. 추천 후보는 `Ctrl+Alt+Shift+F8` 중립, `...+F9` 추적 일시정지, `...+1~3` 표정이며 실제 등록·OBS 초점 시험 전 자동 등록하지 않는다. 앱 종료·설정 해제 때 등록을 해제한다. 실패해도 로컬 키/버튼으로 같은 기능을 사용할 수 있어야 한다.

이번에는 사용자 전역 키를 등록하거나 키를 전송하지 않았다. [Microsoft RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)와 [Electron globalShortcut](https://www.electronjs.org/docs/latest/api/global-shortcut)의 실패·등록 정책을 근거로 채택했으며, 실제 충돌/타 앱 초점 동작은 T-046 정책의 후속 통합 시험이다.

**DEC-03 구현 명료화 — 2026-11-17, 16단계:** DEC-02의 한 장 초상 최소 256px는 그대로 유지한다. 잘린 눈/입·빈 레이어는 각 변 1~4096px PNG로 허용하고 전체 캔버스는 256~4096px로 제한한다. 최대 파일/픽셀 한도와 합산 디코드 RGBA 256MiB·GPU 예산은 별도 적용하며 자동 축소하지 않는다. 계층 opacity는 03 실험과 같은 pass-through 방식으로 각 레이어에 조상 opacity를 곱한다. isolated PSD 그룹 합성은 지원하지 않는다. `.2dparts`의 부모/숨김/표정 대체 참조 등 세부 계약과 저장 범위는 [분리 PNG 1.0 계약](../architecture/split-image.md)을 따른다. 자료 묶음 저장은 독립 아바타 내보내기 완료가 아니다. 기존 실험과 M0 HOLD·5개 OPEN은 유지한다.
