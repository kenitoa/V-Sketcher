# 26~31 미완료 항목 일괄 보완

2026-11-19. 요청 시 미체크 34개를 대상으로 구현·실행·고장 시험·묶음 검증·종료 판단을 추가 확인 질문 없이 진행했다. 의사결정 권한은 실제 관찰 결과와 구분한다. 미관찰 사용자, 발화/몸동작, 경과 시간, 새 Windows, 배포 후 사건을 만들어 기록하지 않는다. 기존 기준·M0 HOLD·필수 세 제작 경로·고급 원화·앱 실행/방송·독립 내보내기·장기 3D/자체 모델을 유지한다.

현재 작업의 새 근거는 `evidence/remediation26-31/`다. 이전 phase26~31 결과는 그대로 보존하며 재시험은 새 폴더에 남겼다. 이전 0.22.0 후보 검사는 새 결함 수정으로 0.22.1이 필요해 중단했고, 기존 고정 ZIP을 수정하지 않는다.

## 새로 수정한 데이터 보존 결함

첫 필수 검사에서 T087의 복구 목록 교체가 실제 Windows `EPERM`으로 실패했다. 어떤 프로그램이 파일을 점유했는지는 확인하지 않았다. `ProjectCatalog.persist`가 준비된 목록을 `catalog.json`으로 교체할 때 `EPERM/EACCES/EBUSY`만 최대 6회, 총 대기 350ms로 재시도하도록 수정했다. 기존 정상 파일을 지우고 교체하는 우회는 없다. ENOSPC와 다른 오류는 즉시 반환하며 영구 실패 시 원래 목록은 보존하고 소유 임시 목록만 정리한다. 보안 설정·백신·실행 정책은 바꾸지 않았다.

새 3개 회귀는 실제 이전/준비 파일의 바이트를 확인하면서 일시 점유 뒤 성공·영구 점유의 유한 종료·공간 부족의 즉시 반환을 검증한다. 이 검사를 필수 실행 목록에 등록했다. 0.22.1의 필수 게이트는 Node 341 + Python 43 = **384개**다. 저장 형식 1.9와 이전 파일 호환 정책을 유지한다. 새 버전 패키지와 이전 고정 ZIP의 구분은 패키지 근거에 고정한다.

## 실제 부족한 파일시스템 — T-271

[실제 ENOSPC 9건](../../evidence/remediation26-31/space-03/space.json)은 Windows Node에서 제품 `atomicBundle`·`ProjectCatalog` API를 호출한다. 프로젝트 전용 WSL2 안의 32MiB tmpfs를 로컬 WSL 파일시스템 연결로 접근해 실제 OS ENOSPC를 얻었다. 오류 주입으로 바꾸지 않았으며 새 저장·기존 교체·자동 복구를 각 3회 시험했다. 기존 정상본/이전 복구본 해시 보존, 미완료 새 파일 비공개, 공간 해제 후 재시도, 별도 Windows 위치 저장·재열기를 확인했다.

이는 저장 백엔드가 실제 공간 부족을 처리하는 근거다. WSL 경로를 사용자 프로젝트 저장 위치로 지원한다는 뜻이 아니며, UI/ProjectSession의 UNC 차단 정책을 해제하지 않았다. 기존 NTFS 읽기 전용·잘못된 경로·제품 저장 오류 주입의 근거와 함께 판단한다. NTFS 전원 상실·모든 저장 매체·깨끗한 Windows 승인으로 확대하지 않는다.

첫 시도에서 WSL 프로세스 종료 후 tmpfs 마운트가 유지되지 않아 시험을 중단했다. 두 번째 실행은 소유 keeper가 마운트를 유지하고 `stat -f`로 tmpfs임을 확인한 다음에만 채운다. 반복당 채우기는 64MiB로 제한되며 일반 Windows 볼륨을 채우지 않는다. 다른 프로젝트의 고장 난 Docker WSL 등록을 고치거나 삭제하지 않았다. 프로젝트용 배포판만 별도 생성했다.

## 설정과 실제 장치 해제 — T-251~259 / T-275 부분

현재 제품의 환경 UI를 새 프로필에서 재실행했다. 장치/저장/복구/키와 프로젝트 설정의 분리, 사용 금지의 선행 검사, 로컬 처리·보관/삭제 설명, 분리된 동의·학습 미제공, 제출 지표와 미측정 전체 지연의 구분, 수동 품질/복원과 원화 불변, 자동 품질 미제공 안내, 최소 진단의 검토·저장, 출처/지원표를 확인한다. 0.22.1 포터블의 기본/작은 창 재시험은 별도 패키지 보고서로 연결한다.

[60회 실제 MediaStream 연결/해제](../../evidence/remediation26-31/media-02/media.json)는 제품 `CameraRuntime`·`MicrophoneRuntime`를 그대로 번들링해 수행했다. 각 시작/프로젝트 세대 변경/중지 뒤 트랙 0·오디오 컨텍스트 없음, 실제 장치 재열기를 확인했다. 개발용과 배포본 worker 각각 30회다. Electron이 보고한 프로세스 작업 집합 합의 6~15회 중앙값 875,884KiB와 마지막 10회 중앙값 886,936KiB 차이는 약 10.8MiB다. 해당 CPU 필드는 Electron 보고값의 합이며 릴리스 기준의 독립 정규화 계측으로 승인하지 않는다. GPU 전용 resident 사용량이나 2시간 누수 검증이 아니다.

[추가 소스 분류 6회](../../evidence/remediation26-31/media-03/media.json)와 [0.22.1 배포 worker 연결 6회](../../evidence/remediation26-31/media-04/media.json)를 합해 실제 MediaStream 연결/해제는 72회다. 추가 분류 12회는 메모리에 있는 장치 표시 이름을 정규식으로 분류해 모두 `hardware-like`를 얻었다. 원시 이름·장치 ID는 기록하지 않았다. 이는 표시 이름에 따른 분류이며 물리 장치 신원/호환성 인증이 아니다. 보고서의 `framesWithDetectedFace`는 마지막 처리 프레임의 얼굴 수이며 전체 프레임 중 검출된 횟수가 아니다. 해당 표본은 모두 0이었고 사람 존재 여부나 고개/눈/입·발화 성공을 추정하지 않는다.

별도의 양성 대조는 [NASA 공개 영역 사진](https://scikit-image.org/docs/0.24.x/api/skimage.data.html#skimage.data.astronaut)을 canvas MediaStream으로 전달했다. 개발/배포 worker 모두 얼굴 1·2·0명 전환을 제품 카메라 코드와 IPC를 통해 검출했다. 원본 출처·해시를 고정하고 참여자 영상과 구분한다. 이 사진은 개발 시험 전용이며 기본 아바타나 포터블에 넣지 않는다. T-190·INT27-CAM-01·실제 사람 시험을 양성 대조로 닫지 않는다.

T-275의 호스트/실제 장치 반복 근거는 늘었으나 장시간 결합 GPU·비정상 종료 임시 파일 누적·물리 분리/연결 조건은 별도다. 단순 핸들 종료를 USB 분리로 기록하지 않는다.

## 같은 프로젝트의 선형 종단 검증 — T-262~265

새 도구는 앱의 실제 파츠·한 장·분리 그림 제작 UI가 생성·저장한 프로젝트를 같은 앱에서 연다. 동일 projectId와 원화 해시를 유지하며 투명도/허용된 위치 보정, 분리 그림의 제어된 역할 오분류/수정, 저장·닫기·재열기, 실행, PNG/INP, OBS의 중립/표정/움직임을 검증한다. 같은 프로젝트를 다시 수정해 버전 2를 만들고 이전 결과의 STALE과 새 결과 해시를 구분한다. 라이브러리 파츠는 금지된 좌표 직접 변경 대신 허용된 투명도 변경을 쓰고 명령 성공·실제 리비전 증가를 검사한다. INP가 실행 중 변환을 보류하는 정책을 따르기 위해 중지→변환→같은 리비전 재실행 순서를 사용한다.

제품 종료·worker 종료 뒤 공식 Inochi Session 0.8.7에서 새 INP 6개를 이동된 한글/공백 경로로 독립 실행하고 실제 OBS 창 캡처를 독립 픽셀 기준과 대조한다. 이 연결의 성공 여부는 새 선형 보고서가 결정한다. 예제 제어를 실제 얼굴/발화나 초보자의 자력 완주로 세지 않는다. 첫 도구의 구조화 복제 오류, 시험 저장 경로 소진, 실행 중 INP 보류를 잘못 다룬 실패는 각각 별도 실행에 남긴다.

이전 선형 검토는 최종 화면 검수에서 빈 OBS 캡처와 시험 도구의 절대 위치 변경이 확인되어 [철회](../../evidence/remediation26-31/review-01/superseded.json)했다. 재검증은 방송 소스의 최신 리비전과 `RENDERING` 상태를 기다리고, 각 캡처의 비어 있지 않은 아바타·투명 배경을 확인한다. 위치 보정은 기존 위치에서 상대 이동하며 원화 정렬을 눈으로도 확인한다. 실패한 실행이나 이전 원본 ZIP을 덮어쓰지 않는다.

## 자동 시험으로 대신하지 않은 잔여 조건

[최종 중립 화면 검수](../../evidence/remediation26-31/linear-08/visual-review.json)는 세 경로·두 버전의 아바타 표시와 머리/몸통 정렬을 확인한다. 한 장 그림의 눈·입 주변 사각 패치 경계는 여전히 보인다. 이 연결 시험은 해당 화질 문제나 실제 얼굴/신체 추적을 승인하지 않으며 T-190/T-209·M0 HOLD를 유지한다.
