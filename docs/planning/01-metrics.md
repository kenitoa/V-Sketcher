## 1. 측정 단위와 관찰 규칙

아래는 첫 제품 사용성 평가에 적용할 측정 계약이다. 실제 제품 사용자 계측은 미구현이며 수기 양식을 사용한다. [05 게이트 v1.0](./05-release-gates.md)이 수치·장비·반복·출시 초보자 30명(첫 경로 각 10명)을 확정했다. 03/04의 기술 실험·장치 입력 참여를 이 사용자 성과 지표로 세지 않는다.

| 단위 | 정의 |
|---|---|
| 사용자 | 조사에 동의한 익명 참여자 ID. 실제 계정·연락처 불필요 |
| 주 경로 | 파츠 / 한 장 그림 / 분리 그림. 세 경로를 별도 보고하고 전체 합계만으로 실패 경로를 숨기지 않음 |
| 시작 프로젝트 | 사용자가 경로를 선택해 새 제작을 시작한 프로젝트 ID. 입력 검사 실패·분석 실패·중도 포기도 분모에 포함 |
| 시도 | 사용자 의도에 따른 분석·내보내기 작업 1회. 중복 클릭은 같은 시도, 실패 후 명시적 재시도는 새 시도 |
| 리비전 | 해당 관찰·저장·출력·내보내기가 기반한 편집 상태. 변경 후 과거 결과의 성공을 재사용하지 않음 |
| 첫 사용 관찰창 | 사용자별 최초 제작 시작부터 7일(168시간). 그 안에 시작한 프로젝트·시도를 첫 사용 집합에 포함. 종료일이 지나지 않은 참여자는 ‘관찰 중’으로 분리 |
| 세션 | 제품 과제를 시작해 종료·이탈할 때까지. 과제 관찰은 회당 최대 60분으로 계획하고 시간 제한 종료를 실패 사유와 함께 기록 |
| 반복 사용 관찰창 | 최초 정상 프로젝트 저장 후 14일(336시간). 첫 세션 종료 후의 별도 세션만 반복으로 인정 |
| 시간 | 시작·종료는 ISO 8601 시각(+09:00 등 오프셋 포함), 구간 길이는 가능하면 단조 시계/스톱워치로 기록 |

이 관찰 기간·세션 제한은 이번 측정 설계의 운영값이며 성능 목표나 제품 시간 제한이 아니다. 변경 시 측정 계획 버전을 올리고 기존 관측값과 섞지 않는다. 조사 모집 6명은 정성 탐색 목표이며 출시 검증 표본은 T-047/DEC-11에서 따로 확정한다.

실제 방송·외부 구동 확인의 증거 수준은 `직접 관찰 / 동의받은 결과 자료 / 사용자 자기보고 / 미확인`으로 남긴다. 수신을 자동 확인할 수 없으면 제품이 자동 검증한 것으로 표현하지 않는다. 자기보고 포함 결과와 직접 확인 결과를 분리한다.

## 2. 핵심 지표와 산식 — T-008

| 지표 | 분모 / 측정 시작 | 분자 / 측정 종료 | 산식·보고 규칙 |
|---|---|---|---|
| M-01 첫 움직임 도달률 | 사용자별 첫 사용 관찰창이 종료된 참여자가 그 창 안에 시작한 프로젝트 전체. 시작: 각 프로젝트의 제작 경로 선택 | 같은 사용자 관찰창 안에 준비된 캐릭터의 지원 동작을 미리보기에서 처음 확인한 프로젝트. 종료: 움직임을 관찰하거나 사용자가 확인한 시각 | 도달 프로젝트 / 시작 프로젝트. 정지 이미지 표시·분석 완료만으로 세지 않음. 눈·입·고개 중 실제 확인 종류와 나머지 미완성 여부도 기록 |
| M-02 방송 연결 완료율 | 최초 7일 관찰창이 종료된 제작 시작 사용자 전체. 시작: 사용자의 첫 제작 시작 | 그 창 안에 실제 대상 방송 미리보기에서 캐릭터·투명도·기본 움직임·표정·UI 제외를 확인한 사용자 | 완료 사용자 / 제작 시작 사용자. 여러 프로젝트 성공이어도 사용자는 1명. 방송 의도 사용자 하위 비율을 추가 보고하되 전체 분모는 유지 |
| M-03 외부 파일 생성 성공률 | 7일 첫 사용 관찰창 안에 시작한 외부 아바타 내보내기 시도 전체. 시작: 대상·리비전을 고정하고 내보내기를 요청 | 요청 시작 후 7일 안에 파일·필수 동반 리소스의 쓰기와 읽기 검사를 완료한 시도 | 생성 성공 시도 / 전체 시도. 검사 차단·취소·오류 포함. 최종 결과 관찰창 미종료 시도는 별도 대기 표시 |
| M-04 외부 독립 구동 확인율 | M-03과 동일한 시도 집합. 시작: 해당 내보내기 요청 | 요청 시작 후 7일 안에 우리 앱을 종료한 상태에서 같은 결과물을 대상이 직접 로드하고 기본 움직임·표정을 확인한 시도 | 독립 구동 확인 시도 / 전체 시도. 추가로 확인 시도 / 파일 생성 성공 시도를 함께 보고. 파일 생성만 완료하면 M-03만 성공 |
| M-05 자동 처리 후 보정량 | 자동 분석·기본 준비 결과를 사용자에게 제시한 프로젝트 전체. 시작: 최초 자동 결과 제시 | 해당 결과의 지원 동작 확인과 보정 종료 선언, 포기, 첫 사용 관찰창 종료 중 먼저 도달한 시점 | 프로젝트별 고유 보정 부위 수·보정 행동 수·능동 작업 시간·재분석 횟수. 보정 없음은 0, 결과 미제시는 측정 불가로 따로 보고 |
| M-06 반복 사용률 | 최초 정상 저장 후 14일 관찰창이 종료된 사용자 전체. 시작: 첫 정상 저장 시각 | 위 관찰창 안에서 첫 세션 종료 이후 최초 저장한 프로젝트를 다시 열어 실행하거나 수정 후 저장한 사용자 | 반복 사용자 / 첫 정상 저장 사용자. 재열기만 하고 종료한 경우는 별도 지표, 자동 복구·단순 앱 실행은 반복 성공 아님 |

첫 움직임은 도달 장벽을 보는 지표이며 AC-05 전체 동작·품질 통과와 별개다. 지원 동작 한 가지를 처음 확인했다고 눈·입·고개 전체 품질을 통과한 것으로 보지 않는다. M-04의 대상 앱이 필요로 하는 움직임 시험 입력은 환경에 기록한다.

M-06에서 복제본 사용은 ‘같은 프로젝트 반복’에 포함하지 않고 파생 재사용으로 별도 집계한다. 동일 프로젝트 ID가 불확실하면 임의로 연결하지 않는다.

## 3. 시간과 보정 행동의 구체 정의

| 측정값 | 시작·종료와 처리 규칙 |
|---|---|
| 첫 움직임 소요 시간 | M-01 시작→최초 움직임 확인. 성공 프로젝트의 중앙값·범위·표본 수와 실패/미도달 수를 함께 보고 |
| 첫 방송 소요 시간 | 사용자의 첫 제작 시작→M-02 전체 확인. 여러 세션이면 첫 시작부터의 경과 시간과 실제 과제 수행 시간 합계를 따로 보고 |
| 내보내기 처리 시간 | 요청→쓰기·읽기 검사 완료. 대상 선택·손실 수정의 사용자 작업 시간과 대상 로드 확인 시간은 별도 |
| 능동 작업 시간 | 선택·판단·편집·검색·문제 해결에 사용한 시간. 드래그 연속 조작을 한 행동으로 묶음 |
| 자동 처리 대기 | 처리 요청→결과 준비 중 실제 대기 구간의 합. 처리 중 편집하면 겹친 시간은 능동 작업으로 우선 분류하고 이중 합산하지 않음 |
| 외부 준비 시간 | 앱·방송/외부 도구 설치·다운로드·권한 설정. 본 과제 시간과 별도 기록하고 설치 포함 총시간도 함께 보고 |
| 쉬는 시간·세션 간 공백 | 능동·대기 합계에서 제외하되 전체 경과 시간에는 포함. 이탈 후 돌아오면 공백과 사유 기록 |
| 보정 부위 수 | 실제 수정한 고유 부위 ID 수. 눈 위치를 세 번 고쳐도 부위 수는 1 |
| 보정 행동 수 | 위치·영역·역할·순서·범위 등의 의미 있는 적용 1회를 한 행동으로 기록. 되돌리기·재수정은 별도 행동, 프레임별 슬라이더 변화는 중복 집계하지 않음 |
| 재분석 | 동일 프로젝트에서 명시적으로 다시 시작한 분석 수. 자동 결과를 받은 뒤 재분석해도 최초 결과 제시 기준의 총 보정 부담을 초기화하지 않음 |

첫 움직임 중앙값 10분·첫 방송 중앙값 20분은 01의 가설에서 05의 검증 목표로 채택했다. 현재 측정된 성과가 아니다. 비교할 때 사전 설치 환경의 세션 내 능동+대기 시간을 사용하고, 설치 포함 시간·세션 간 공백도 별도 공개한다. 진행자 설명·도움 시간은 과제 수행 중이면 포함한다. 시간 제한 종료·실패를 10분/20분 또는 0초의 성공값으로 대체하지 않는다. 7일 이내 여러 세션 완주자는 경과 시간과 합산 과제 시간을 보고하되 단일 세션 표본과 분리한다.

30FPS 능력/실제 30Hz 소스, 지연 p95 200ms, 방송 동시 2시간의 판정은 T-047에서 [05의 장비·표본·구간 계약](./05-release-gates.md)으로 구체화했다. 렌더/소프트웨어 지연/독립 실동작 지연을 구분하고 현재 성능 충족을 선언하지 않는다. 기존 640px CPU 경로는 미달, 새 제품 GPU 경로·2시간은 미측정이다.

## 4. 실패·도움·지원 밖 입력

- 종료 상태는 `완료 / 포기 / 오류 / 시간 제한 / 관찰 중 / 미확인`으로 기록한다. 조사 동의 철회 자료는 삭제하고 삭제 건수만 허용 범위에서 남긴다.
- 분모에서 취소·오류·지원 밖 입력을 조용히 제외하지 않는다. 전체 시작 집합과 지원 조건 충족 하위 집합을 함께 보고한다. 지원 범위가 결정되기 전에는 ‘지원 여부 미정’으로 둔다.
- 도움은 `없음 / 일반 안내 / 과제별 힌트 / 진행자 대리 조작`으로 기록한다. 무도움 성공은 도움 없는 완료, 안내만으로 완료는 대리 조작 없는 완료로 별도 집계한다.
- 대리 조작으로 기술 동작은 확인할 수 있어도 AC-15의 사용자 완주로 세지 않는다. 가상 데이터·개발자 리허설은 실제 사용자 지표에서 제외한다.
- 사용자 확인이 없거나 관찰창 종료 시 연결이 확인되지 않으면 완료 분자에 넣지 않는다. 연락 두절은 ‘미확인’으로 분모와 함께 보고한다.
- 프로젝트 변경으로 호환 검사가 오래되면 같은 내보내기 성공 기록으로 새 리비전을 통과시키지 않는다. 대상·리비전·결과물 ID별 연결을 보존한다.
- 표본이 0이면 비율은 `측정 없음`이다. 경로별 n/N과 결과 유형·도움·환경을 함께 남기고 작은 정성 표본을 전체 사용자 성공률로 일반화하지 않는다.

## 5. 수기 기록 계약과 요약 양식

최소 이벤트는 `제작 시작 / 자동 결과 제시 / 보정 적용 / 재분석 / 첫 움직임 확인 / 프로젝트 저장 / 세션 종료 / 재열기 / 실행 시작 / 방송 출력 준비 / 방송 수신 확인 / 내보내기 요청 / 파일 검사 완료 / 외부 구동 확인 / 실패·포기·도움`이다. 이벤트 이름은 기록용 정의이며 구현 API를 강제하지 않는다.

| 필드 | 내용 |
|---|---|
| 연결 키 | 조사·계획 버전, 익명 사용자 ID, 프로젝트 ID, 경로, 리비전, 시도 ID, 결과물 ID |
| 시간·상태 | 이벤트, 시각, 구간 길이, 능동/대기/설치/공백, 종료 상태·이유 |
| 실행 조건 | 빌드·구성 버전, 입력 샘플 ID·지원 여부, OS·장비·장치, 방송/외부 대상·버전·방식 |
| 증거·도움 | 직접 관찰/자료/자기보고/미확인, 근거 위치, 진행자 개입 수준 |
| 부담·품질 | 보정 부위·행동·재분석 수, 원화 인상·경계·눈·입·고개 문제와 재현 조건 |

원본 영상·음성·개인 경로를 지표 기록의 필수값으로 수집하지 않는다. 조사 동의·보관은 [조사 계획](./01-user-research.md)을 따른다.

보고서는 `계획 버전 / 경로 / 환경 / 동의 참여·시작·관찰 완료·철회 수 / 각 지표 n/N / 시간 중앙값과 실패 수 / 도움 수준 / 근거 수준 / 반복 사용 관찰창 / 미확인·제한 / 후속 DEC`를 포함한다. 현재 값은 모두 **미측정**이다.
