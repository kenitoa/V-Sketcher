# 20. 마이크 반응·추적 손실·장치 재연결

2026-11-18 · 앱 0.15.0 · 공통 모델 1.9 유지 · T-191~200.

사용자가 20단계 작업을 명시적으로 요청하여 19단계 T-190의 실제 카메라 미완료를 보존한 채 입력 복구를 구현한다. 이 선행 상태를 자동 검사로 완료 처리하지 않는다. M0 HOLD·5개 OPEN도 유지한다.

## 사용

캐릭터를 준비한 뒤 **마이크·입력 복구**에서 마이크를 선택하고 **선택 마이크 연결·재연결**을 누른다. 입력 대기·수신·유효 무음·지연·중단을 구분한다. 조용한 상태에서 **소음 기준 측정 → 새 기준 적용** 후 감도·세기·추가 소음 여유·부드러움을 조절한다. 측정 취소/실패는 이전 기준을 바꾸지 않는다. 소리 크기만 분석하므로 말과 큰 소음을 구별하지 않는다.

입 우선 모드와 다른 유효 입 입력의 사용 여부는 프로젝트 설정이다. 고정 표정과 편집 시험이 먼저 적용된다. 카메라가 끊겨도 유효 마이크를, 마이크가 끊겨도 유효 카메라 고개/눈을 유지한다. 입력이 없으면 500ms에 걸쳐 기본 동작으로, 복구되면 250ms에 걸쳐 최신 값으로 돌아간다. [정확한 시간·저장·수명 계약](../architecture/input-recovery.md).

자동 재연결은 하지 않는다. 장치를 다시 고르고 연결 버튼을 누른다. 카메라의 선택/재연결/중립 보정은 별도 버튼으로 기존 화면에 연결한다. 캐릭터를 다시 만들 필요가 없다. 대화상자를 닫아도 연결은 유지하며 주 화면의 각 장치 중지 버튼은 해당 장치만 정리한다. 프로젝트/세션 전환은 모두 정리한다.

## 작업과 확인

| 작업 | 결과/근거 대상 |
|---|---|
| T-191 | audio-only 권한·목록·선택·레벨, 새 0레벨과 연결/읽기 실패 분리 |
| T-192 | 조용한 구간 후보 검토/적용·취소·감도/세기/여유/시간 평활 |
| T-193 | 입 단일 소유자·유효 무음·모드/대체·표정 고정 우선 |
| T-194 | 콜백 없이 표시 시각으로 만료·입 기본 동작 복귀 |
| T-195 | 카메라 300ms 유지·500ms 완화, 대상 소유권과 별도 처리 |
| T-196 | track 종료/수신 중단/카메라 검출 손실에서 다른 장치 유지 |
| T-197 | 250ms 최신 입력 복귀·공통 표시 시계·원본 비교 중 제어 지속 |
| T-198 | 이전 오디오 종료 대기·수동 재연결·PC 기준 재사용·외형/표정/저장 보존 |
| T-199 | 자동 재연결 미제공 결정, 목록 갱신과 연결 시도 분리, 중지·수동 경로 |
| T-200 | 세 경로의 합성 소음/가림·track ended·콜백 정지·표정 전환 복합 시나리오 |

새 Node 20개 그룹을 추가하며 필수 gate는 Node 225+Python 36, **261개 그룹**과 전체 개발 앱 회귀가 통과했다. 실제 worklet 코드의 RMS/무음/반대 위상/0출력·소음 기준·범위·절대 시각 손실/복구·표정/다른 입력·장치 파일 손상·세 경로 구조 보존을 검사한다.

[필수 gate·소스 해시](../../evidence/phase20/verification.json)와 [전체 개발 앱 결과](../../evidence/phase20/development-run.json)를 보존한다. 같은 PC에서 개발 도구 경로를 제거한 release의 새 프로필 2회·기본/1080×720 창 검사도 통과했다. [패키지 감사](../../evidence/phase20/package-audit.json), [작은 창](../../evidence/phase20/release-input-recovery-compact.png). 고급 원화의 준비 완료를 기다린 실제 미리보기 캡처를 확인했다.

앱 자동 UI는 세 실제 제작 경로의 캐릭터에 합성 oscillator와 canvas MediaStream을 사용한다. 실제 AudioWorklet과 로컬 얼굴 모델을 거치고, 가림·track ended 이벤트·수신 AudioContext suspend·수동 재연결·표정 고정/해제·저장 왕복을 확인한다. 실제 USB 분리·사람의 세 음성 구간은 이 자동 결과에 포함하지 않는다. 원본 비교를 지원하지 않는 파츠 경로의 비교 시험은 NOT_APPLICABLE로 기록한다.

## 실제 장치와 지원 한계

실제 마이크의 레벨 수신·중지·재연결 결과는 별도로 기록한다. 사람의 조용히/말하기/소음 구간이 확인되지 않은 레벨 관찰을 음성 품질 통과로 부르지 않는다. 물리 USB 분리, 실제 카메라 정상/복수 얼굴/가림의 새 통과는 주장하지 않는다. T-190 실제 카메라 재검증과 서로 다른 장치 호환성·M0-R02의 약한 발화/큰 소음 품질은 남는다.

Windows 기본 마이크 입력을 연 [첫 실행](../../evidence/phase20/live-microphone-01.json)은 읽기 중단으로 실패했다. 오디오 엔진이 실제로 콜백을 전달한 시점의 현재 AudioContext 시각으로 한 번 기준을 맞추도록 보완한 [재실행](../../evidence/phase20/live-microphone-02.json)은 레벨 151표본·중지·재연결 후 76표본을 수신하고 프로젝트를 보존했다. 원음·영상 저장이나 오디오 재생은 하지 않았다. 조용히/말하기/소음 지시 없이 받은 표본이므로 세 구간 시험으로 해석하지 않는다. [현재 실제 확인 범위](../../evidence/phase20/live-microphone-summary.json).

초기 자동 실행 중 읽기 중단·종료 정리·합성 장치 ID/원본 비교 준비의 문제가 드러난 실행도 별도 실패 파일로 보존한다. 합성 재연결은 같은 장치 ID와 새 MediaStream을 주도록 구성하며, 원본 비교 버튼이 없는 경로에 지원하지 않는 조작을 요구하지 않는다. 통과 결과로 실패 기록을 덮어쓰지 않는다.

[첫 전체 회귀의 실패](../../evidence/phase20/development-failed-01.json)는 마지막 추적기의 20초 준비 시간 초과다. 준비 시간 제한을 늘리지 않고 기존 수동 연결 버튼을 최대 3회 누르는 명시적 시험 경로를 추가했다. 최종 전체 회귀는 세 경로 모두 추가 시작 재시도 0회로 통과했다. 이 한 실행을 모든 PC의 시작 시간 보증으로 확대하지 않는다.

## 재현

`node scripts/verify-input-recovery.mjs`로 필수 gate와 전체 개발 앱 회귀를 실행한다. release 패키지의 `node scripts/input-recovery-package-check.mjs --evidence-dir=evidence/phase20`는 같은 PC의 한글·공백 경로·개발 도구 없는 PATH·새 프로필·기본/1080×720 창에서 두 번 확인한다. OS/DLL/드라이버를 제거한 별도 Windows 검증은 아니다. [소스/문서/증거 감사](../../evidence/phase20/audit.json)는 실제 하드웨어 승인과 구분한다.

세 제작 경로·고급 원화·로컬 실행/방송·독립 내보내기·장기 필수 3D/자체 모델 생성을 유지한다. 이번 단계로 실행/방송/내보내기·전체 M3·M0를 완료 처리하지 않는다.
