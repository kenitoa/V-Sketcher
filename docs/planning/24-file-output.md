# 24. 이미지 저장·외부 대상·호환성 검사

2026-11-18 · 앱 0.19.0 · 프로젝트 모델 1.9 유지 · T-231~240.

정지 PNG 저장과 외부 아바타 대상의 사전검사를 구현한다. 세 제작 경로·고급 원화·로컬 실행/방송·독립 아바타 내보내기·필수 장기 3D/자체 모델을 유지한다. **실제 INP 파일 생성·독립 구동은 25단계 T-241~250**이며 사전검사 통과나 정지 PNG로 완료 처리하지 않는다. T-190/T-209와 M0 HOLD/5 OPEN을 유지한다.

## 정지 이미지

작업실의 **이미지 저장·외부 대상 → 정지 PNG 저장**에서 작업본 또는 현재 실행본을 선택한다. 기본 자세·저장 표정을 고르며, 실행본에서는 현재 입력을 한 프레임으로 고정할 수 있다. 카메라·마이크·움직임 구조가 없어도 그림이 있으면 저장한다. PNG RGBA 8bit/sRGB, 64~4096px/한 변·최대 16,777,216픽셀, 투명 또는 단색 배경, 크기·가로/세로 위치·잘림을 지원한다.

**미리보기 준비 → 이 미리보기 PNG 저장**을 사용한다. 미리보기는 저장할 PNG 자체이며 두 결과의 바이트/SHA-256이 같다. 체크무늬는 앱의 바탕이고 PNG에는 없다. 입력이나 설정이 바뀌면 미리보기를 다시 준비한다. 저장 위치 선택 중 입력이 바뀐 경우도 메인에서 거부한다. 쓰기 시작 후의 더 최신 편집은 고정된 저장 이미지와 구분한다.

실행 중에는 2,073,600픽셀 이하로 렌더링하며 큰 출력은 실행 중지 후 준비한다. 압축 자산 입력은 실행 중 64MiB/중지 시 256MiB, 사용 그림의 합산 디코드 RGBA는 256MiB 조건이다. 한도를 넘으면 이유와 중지/설정 변경 대안을 표시하고 품질을 조용히 낮추지 않는다. 실제 방송 성능 승인이나 최대 크기의 모든 그림 보증은 아니다.

저장은 네이티브 PNG 파일 선택 후 같은 볼륨의 임시 파일→fsync→다시 읽기/검증→기존 파일 해시 확인→rename으로 확정한다. 공통 파일 잠금은 살아 있는 쓰기 작업과 죽은 프로세스의 오래된 잠금을 구분한다. 실패·취소는 이전 정상 파일을 유지하고 자기 임시 파일만 정리한다. UNC·링크 대상/부모 등 지원 범위 밖 경로는 차단한다.

## 외부 대상과 검사

| 대상 | 상태 |
|---|---|
| Inochi Session 0.8.7 / SDK 0.8.6, INP | 사전검사 지원. 포맷 및 04의 제한된 실험 구동 근거가 있으며 제품 변환/독립 구동은 25단계 검증 필요 |
| 다른 Inochi 버전 | 실험·미검증, 현재 선택 불가 |
| VRM / Live2D moc3 / VTube Studio | 초기 2D 대상 미지원 |

검사 버전은 **1.0.0**, 변환 검토 규약 버전은 **0.2.0**이다. 대상의 정수 UUID·매개변수 min/max/defaults·binding과 대소문자 이름 조회는 [SDK 0.8.6 parameter 소스](https://raw.githubusercontent.com/Inochi2D/inochi2d/v0.8.6/source/inochi2d/core/param/package.d), 내장 텍스처/섹션은 [INP 포맷 소스](https://raw.githubusercontent.com/Inochi2D/inochi2d/v0.8.6/source/inochi2d/fmt/package.d)를 기준으로 한다. 대상 프로그램은 [공식 Session 0.8.7](https://github.com/Inochi2D/inochi-session/releases/tag/v0.8.7)에 고정한다. 프로그램이나 SDK를 제품에 동봉/실행하지 않는다.

대상 이름 연결을 검토하고 **프로젝트에 대상 설정 기억**을 누른 뒤 프로젝트를 저장하면 다시 열어도 재사용한다. 스키마에 이미 있던 `exportProfiles`를 사용하므로 모델 버전은 올리지 않는다. 미지원 대상이나 임의 형식을 선택해 통과시킬 수 없다.

- 부위·계층·참조·필수 눈/입/고개 제어와 부위 연결·범위·표정 값/범위·누락 자산/해시를 검사한다.
- 초기 어댑터의 64부위·128텍스처·4096px/그림·RGBA 합계 256MiB를 검사한다. 이 수치는 SDK 고유 한도가 아니라 현재 어댑터의 지원 조건이다.
- 부위 이름·정수 UUID·중심 원점·반대 z·내장 파일 이름·PNG/premultiplied alpha 변환 규약을 별도 사본으로 정리한다. 원본의 이름·좌표·자산·표정을 수정하지 않는다.
- 현재 고급 모델의 결합/가중 고개 변형, smoothstep 곡선, 픽셀 상태 보간, 색상 굽기, 부위 한정 표정은 대상 보존 검증이 필요하다. 필요한 변환을 생략하거나 평면 이동/opacity 교차로 조용히 대체하지 않고 **BLOCKED**로 표시한다. 이 항목의 실제 변환과 극단 입력 비교는 25단계의 필수 작업으로 남긴다.
- 리소스/참조/필수 제어 손상은 차단, 이름/텍스처 인코딩·표정/입력 이전 정책은 해당 경고로 표시한다. 수정 위치로 가기에서 부위·매개변수·연결·표정 화면을 연다.

**변환 검토 사본**은 모든 부위(숨김 포함)의 원래 이름/ID·표시/opacity·부모 관계와 중심 좌표/정수 UUID/z, 매개변수/연결·표정 정책·텍스처 이름/인코딩 작업 규약을 담는다. 사본의 원화/중립 좌표를 앱에서 확인할 수 있다. 텍스처 인코딩이나 INP 바이너리가 이미 만들어진 것처럼 표시하지 않으며 차단된 변형의 외부 실행 미리보기라고 하지 않는다.

PASS/WARNING/BLOCKED와 오래된 검사 STALE을 구분한다. 입력본 ID/리비전/내용 지문·대상/연결 설정·검사/변환 버전·경고 집합을 묶는다. 옵션이나 입력이 바뀌면 재검사하며 메인도 이전 결과/옵션의 재사용을 거부한다. 경고 확인은 해당 범위에만 유효하고 다음 검사에서 초기화된다. BLOCKED를 경고 확인으로 해제할 수 없다. 사전검사 PASS는 외부 파일 생성/실제 구동 확인이 아니다.

[필수 검사와 소스 해시](../../evidence/phase24/verification.json), [전체 기존 앱 회귀](../../evidence/phase24/development-run.json), [세 경로 파일 UI](../../evidence/phase24/file-output-development-run.json), [독립 PNG 픽셀 검사](../../evidence/phase24/pixel-quality.json), [같은 PC release 2회](../../evidence/phase24/package-audit.json), [완료 감사](../../evidence/phase24/audit.json)를 분리한다. 신규 Node 20개를 포함한 **Node 295 + Python 36 = 331개 검사 그룹**과 실제 PNG 14종을 검증한다. 투명/배경 포함/표정/배치 4종×세 경로, 실행 입력 고정 1종, 무동작 그림 1종이다. 별도 Pillow 디코드에서 SHA/크기/알파·배경 합성 RGB 오차 2 이내 비율 99.5% 이상·표정/배치 변화를 확인한다.

첫 UI 캡처에서 공통 대화상자의 너비 제한으로 미리보기가 작아진 결과를 보존하고, 전용 너비/폼 스타일을 적용한 새 기본/1080×720 실행으로 확인한다. 배포본은 개발 도구가 없는 PATH·한글/공백 경로·새 설정 두 번이며 같은 Windows의 OS/DLL/드라이버는 유지한다. 깨끗한 별도 PC·외부 아바타 파일·실제 장치/OS 전역 키·M0/출시 승인을 뜻하지 않는다.

첫 전체 회귀에서 기존 입력 복구 시험의 표정 해제 후 마이크 소유권 확인이 한 번 실패했다. [실패 보고](../../evidence/phase24/full-regression-failed-01.json)와 [당시 화면](../../evidence/phase24/full-regression-failed-01.png)을 보존한다. 코드·대기 시간·시험 조건을 바꾸지 않은 새 프로필의 전체 회귀는 통과했다. 단일 실패의 원인은 확정하지 않았으며 성공 결과로 덮어쓰지 않는다.

이전 키 시험에 대한 사용자의 “두 키를 모두 눌렀고 창이 자동으로 닫힘” 보고는 [새 관찰 기록](../../evidence/phase24/key-user-attestation.json)에 추가했다. 기존 세 수집 기록은 실패/콜백 미계측으로 보존한다. 앱 밖 초점·로컬 F8 억제·전역 콜백을 함께 입증하는 새 성공 계측은 없으므로 T-209를 완료로 바꾸지 않는다. [구현 계약](../architecture/file-output.md).
