## 1. 확인할 질문과 모집 계획 — T-003

첫 조사는 현재의 제작·방송 준비 과정을 확인한다. 제품이 없는 현재 시점에 2DSketcher 사용성·완주율을 측정한 것으로 기록하지 않는다. 동작 가능한 시제품이 생기면 별도 제품 과제 관찰을 진행한다.

| 조사 질문 | 확인할 행동·자료 | 연결 |
|---|---|---|
| RQ-01 어느 단계에서 시작하지 못하거나 포기하는가? | 최근 시도의 순서, 마지막 완료 단계, 막힌 화면·행동·대안 | PRD 3.1절, PD-01, DEC-11 |
| RQ-02 세 입력 경로별 준비 수준은 어떤가? | 사용 가능한 파츠/한 장/분리 자료, 형식·크기·투명도·좌표·역할 지식 | PD-03~05, DEC-02~04 |
| RQ-03 자동 결과가 틀렸을 때 무엇을 고칠 수 있는가? | 눈·입·순서 오류 인식, 이해 가능한 설명, 직접 수정 가능 범위 | FR-IMG-03, FR-LAYER-01 |

참여 조건은 버추얼 캐릭터 제작·방송을 원하며 최근 시도나 준비 경험을 설명할 수 있는 사람이다. 제작을 시작하지 못한 사람도 포함하고 이유·보유 자료만 기록한다. 그림 실력과 레이어·리깅·방송 도구 숙련도는 각각 확인한다.

초기 탐색 모집 목표는 6명, 세 입력 상황별 주 경로 2명씩으로 둔다. 각 경로에 제작 도구 초보자 1명 이상을 포함하고, 가능하면 방송 초보와 경험자를 함께 모집한다. 한 사람이 여러 경로를 보유해도 주 경로 기준으로 중복 집계하지 않는다. 이는 정성 탐색 계획이며 통계적 대표성이나 출시 표본 충족을 뜻하지 않는다. UR-001은 구현 경험자의 별도 근거로 보관하며 초보자 모집 인원을 충족한 것으로 세지 않는다. 모집 연락은 별도 실행 시 수행한다.

## 2. 동의와 자산 취급

진행자는 조사 시작 전에 목적, 질문·관찰 항목, 예정 시간(약 40~60분), 기록 방식과 보관 기간을 설명한다. 거절·중단·무응답은 가능하고, 중단 이후 관찰을 계속하지 않는다. 아래 항목은 각각 선택받는다.

- 텍스트 답변·익명 관찰 메모의 제품 기획 활용.
- 화면 공유 관찰. 계정·개인 파일·송출 키가 나오면 공유를 멈추거나 가린다.
- 화면 녹화·스크린샷·음성 녹음은 각각 별도 동의 시에만 수행. 기본은 메모만 작성.
- 원본 자산 사본 제공과 기술 실험 활용은 조사 참여와 별도로 동의. 원본 제공 없이 말이나 화면으로 설명할 수 있다.
- 외부 공개와 모델 학습 활용은 이 조사 동의에 포함하지 않는다. 학습 자료에 자동 편입하지 않는다.

신규 참여자에게는 다음 안내 후 동의 범위·시각·기록자를 남긴다: “제작·방송 준비에서 어려운 점을 파악하려고 합니다. 익명 메모만 기본 기록하며, 원본 파일이나 녹화는 필수가 아닙니다. 답하지 않거나 언제든 중단할 수 있습니다. 자료는 이 프로젝트의 조사·검증에만 사용하고, 외부 공개나 모델 학습에는 별도 동의 없이 쓰지 않습니다.”

원본 수집 시 자산 ID·출처·권한 설명·허용 목적·보관 위치·삭제 예정일을 기록한다. 원본은 읽기용으로 보관하고 실험은 사본으로 한다. 공개 배포 자산과 조사 전용 자산을 구분한다. 개인 경로·연락처·송출 키를 저장소에 넣지 않는다. 제공 권한이 불확실하면 사본을 수집하지 않고 대체 샘플을 사용한다.

이 조사 운영 계획에서는 녹화·음성·원본 사본을 정리 완료 후 30일 이내 삭제하고, 익명 분석 메모는 조사 종료 후 90일 이내 재검토하여 불필요한 내용을 삭제한다. 참여자에게 실제 삭제일과 접근 담당을 사전에 알리고, 철회 요청은 연결 가능한 자료부터 삭제해 반영한다. 이 기간은 제품 전체의 보관 정책을 확정한 것이 아니다. 공개 저장소에 자료를 옮기기 전에는 별도 공개 동의·비식별 처리가 필요하다.

UR-001은 아래 동의 절차를 사전에 수행한 인터뷰가 아니다. 사용자가 이번 작업의 근거 수집 질문에 자발적으로 제공한 텍스트를 프로젝트 기획 근거로 최소 요약했다. 녹화·원본 수집·외부 공개·학습 활용 동의가 있다고 해석하지 않는다.

## 3. 진행 순서와 질문

| 단계 | 진행과 질문 | 기록 |
|---|---|---|
| 시작 / 5분 | 목적·동의 확인. 그림 도구·리깅·방송 경험을 따로 질문 | 익명 참여자 ID, 동의 범위, 주 입력 경로, 숙련도 |

| 자료·환경 / 5~10분 | “무슨 파일로 시작했나요?” “PC·OS·카메라·마이크·방송/아바타 앱은 무엇이었나요?” | 모르는 항목은 미확인. 확장자·버전·장비 모델 추정 금지 |
| 현재 흐름 관찰 / 15~20분 | 동의한 범위에서 기존 과정을 재현. “여기서 하려던 일은 무엇인가요?” “다음 행동은 어떻게 찾았나요?” | 단계·멈춤·오류·검색·다른 앱 전환·도움·포기·재시도 |
| 결과·재사용 / 5~10분 | “실제 방송 화면에서 확인했나요?” “외부 도구에서는 무엇을 유지해야 하나요?” “다시 열 때 무엇을 반복하나요?” | 방송/파일 생성/외부 구동의 확인 수준을 분리 |
| 마침 / 5분 | 요약을 읽어 사실 오류 확인. 자료 활용·삭제 범위 재확인 | 확인·정정·추가 질문·후속 검증 |

“리깅이 어렵죠?”처럼 답을 유도하지 않는다. 먼저 자유 응답을 받고, 미확인 항목을 추가로 질문한다. 실제 관찰이 불가능하면 자기보고로 표시한다. 요청한 60분 안에 종료하지 못한 과제는 성공 시간에 넣지 않고 중단 시점·이유를 남긴다.

시제품 관찰에서는 E2E-P/I/L 중 주 경로→저장·재개→움직임→실행·실제 방송 확인과 OUT-A 외부 독립 구동을 각각 부여한다. 진행자가 조작하지 않고 도움 개입과 이탈을 기록한다. 관찰 도중 핵심 흐름을 바꾸면 새 계획 버전으로 나눈다.

## 4. 관찰 기록 양식

사용자 보고 `SR`, 진행자 직접 관찰 `OBS`, 파일·측정 결과 `ART`, 해석·가설 `HYP`를 구분한다. 해석마다 원자료 위치를 연결하고 미확인 항목을 공란 대신 명시한다.

| 기록 필드 | 적을 내용 |
|---|---|
| 세션 | 조사 ID, 일시·시간대, 기록자, 계획 버전, 자기보고/직접 관찰 |
| 참여·동의 | 익명 ID, 주 경로, 숙련도, 메모/화면/녹화/원본별 동의, 보관·삭제일 |
| 입력 | 자산 ID, 파츠/한 장/분리, 형식·크기·투명도·좌표, 권한·출처. 미확인 허용 |
| 환경 | OS·CPU/GPU/RAM, 카메라·마이크·드라이버, 방송/외부 앱·버전·연결 방식 |
| 행동 기록 | 상대 시각, 실제 수행 단계, 기대, 결과, 막힘, 도움, 재시도, 증거 유형·위치 |
| 종료 | 완료/포기/오류/시간 제한/미착수 중 실제 상태, 마지막 완료 단계, 이유 |
| 분석 | 확인 사실, 가설, 제품 영향, 연결 PD/FR/DEC, 후속 질문·실험 |

실제 기록에서는 종료 상태를 `완료 / 포기 / 오류 / 시간 제한 / 미착수`로 통일한다. 결과를 만들기 위해 빈 양식을 채운 사례나 가상 인물을 실제 조사로 세지 않는다.

T-004의 실제 사용자 확인은 이 자기보고를 근거로 완료한다. 경험 전체의 성공을 가정하거나 미확인 장비·파일을 임의로 보충하지 않는다. 향후 기술 검증은 이 기록만으로 통과할 수 없다.
