## 1. 문서 사용 규칙

### 1.1 PRD와의 관계

PRD는 제품이 해결할 문제와 반드시 제공할 범위를 정의한다. 이 문서는 그 요구사항을 어떤 조작과 결과로 제공할지 정의한다. 제품 방향은 PRD를 따른다. 세부 동작은 별도 확정 표기가 없는 한 **설계 제안**이며, 기술 검증과 사용자 평가를 통해 조정할 수 있다.

05단계 [DEC-01~12](./planning/05-decisions.md)는 Windows 11 x64·포터블 ZIP/EXE, PNG/JPEG·PNG 폴더/2dparts, 2dsketch 저장, 고급 파츠/움직임, OBS 33.0.1·INP/Session v0.8.7, 로컬 처리·저장/동시성·단축키·성능/표본을 초기 구현 기준으로 채택했다. [스택](./planning/05-stack.md)과 [게이트 v1.0](./planning/05-release-gates.md)을 함께 따른다. 상세 스키마·API 구현과 실제 지원 보증은 구분하며, 장기 모델은 여전히 별도 연구 범위다.

이 문서가 장기 기능의 모델 구조·학습 데이터·비용을 확정하지 않는다. 특히 글 기반 생성은 자체 모델을 제작·연결한다는 방향과 공통 제작 흐름과의 접점만 정의하고, 상세 모델 기획은 후속 문서에서 다룬다.

01단계에서 [실제 사용자 경험 UR-001](./planning/01-user-research.md#ur-001)을 확인하고 [세 경로·사용 시나리오](./planning/01-product-baseline.md), [측정 정의](./planning/01-metrics.md), [DEC별 실험·증거 목록](./planning/01-decisions.md)을 고정했다. Windows·OBS Studio는 그 실제 경험을 거쳐 05 최초 대상으로 채택했으나 전체 환경의 제품 지원 검증이 끝난 것은 아니다. 세 입력 경로와 앱 실행·방송·외부 아바타 내보내기의 필수 범위는 유지한다.

### 1.2 기능 식별과 범위

02단계에서 실제 시험 입력·파츠·장비 기록·격리 실행 도구·공식 후보 조사·평가/재현 양식을 마련했다. [02 평가 기준](./planning/02-evaluation.md)의 탐색 점수와 준비 검사 결과를 제품 지원·출시 검증으로 해석하지 않는다. 추가 요구 `NFR-ART-01`은 고급 이미지의 얼굴·선·머리카락·명암·의상 디테일과 원화 인상 보존을 평가한다. 절차 제작 도형은 구조 검사에 사용하고 고품질 원화 입력을 별도로 비교한다. 실제 생성 도구의 사용은 제품 자체 모델 생성 기능을 구현한 것으로 세지 않는다.

03단계 [시제품 검증 결과](./planning/03-feasibility.md)에서 F-PAR/F-IMG/F-LYR/F-MOT 관련 최소 연결을 실제 시험했다. 공통 렌더러·수동 제어·저장·눈/입 보정·교체는 제한된 표본의 기술 검증 상태다. 제품용 52개 기능의 완료나 NFR-ART-01·초보자 완주·실시간 성능 통과를 선언하지 않는다. 가림의 불확실한 위치는 자동 제어를 보류하고, 보완 비교의 운영자 확인 4회와 원본 복원이 아닌 추정을 명시했다. 직접 OS 마우스 검수는 미수행이며 17개 Tk 위젯 검사는 별도로 기록했다.

04단계 [실제 추적·방송·외부 실행 결과](./planning/04-tracking-broadcast-export.md)는 F-TRK-001~004·F-MOT-005·F-BRD-001~002·F-EXP-002~005의 초기 기술 근거다. 실제 웹캠/기본 내장 마이크와 고급 자산을 연결하고 중립·방향/감도·손실/복귀 및 OBS의 투명 소스 수신을 확인했다. 공식 Inochi Session v0.8.7은 앱/서버 종료 후 내장 INP 동작을 독립 재생했다. 고급 640px 출력의 약 13.57FPS, RMS의 음성/소음 구분 한계, 수동 표정 영역·평면 움직임·외부 변형 손실을 명시하며 제품 기능 전체 완료·30FPS·고급 자동 리깅·외부 웹캠 바인딩의 합격으로 해석하지 않는다. 기본 데모는 PREMIUM-003이며 도형 회귀 자산을 시각 품질의 근거로 세지 않는다.

- `F-영역-번호`: 이 문서의 상세 기능 ID. 작업·테스트에서 참조한다.
- `FR-*`, `NFR-*`, `PD-*`, `AC-*`: PRD의 요구사항·방향·수용 기준 ID다.
- **초기 필수**: 초기 2D 출시의 완결성을 위해 필요한 기능이다.
- **초기 검토**: 핵심 흐름 검증 후 제공 여부와 수준을 결정한다.
- **장기 필수**: 전체 제품 범위에는 포함되지만 초기 2D 출시 완료 조건과 분리한다.
- **검증 대기**: 대상·방식·수치를 정한 뒤 구현 수준을 확정한다. 필수 기능 자체가 선택 사항으로 바뀌는 것은 아니다.

앱에서 실행해 방송에 연결하는 기능과 외부 프로그램에서 독립적으로 사용하는 내보내기는 **모두 필수**다. 정지 이미지나 자체 프로젝트 파일만 저장하는 것으로 외부 아바타용 내보내기를 대체하지 않는다.

### 2.3 공통 동선

```text
파츠 / 한 장 그림 / 분리 그림
            ↓
    공통 프로젝트와 외형 편집 ─────────→ 이미지 저장
            ↓
      움직임·표정 준비
            ├─────────────────────→ 외부 대상 검사 → 아바타 내보내기
            ↓
     장치 연결·보정 / 자동 반응
            ↓
        앱 내 실행 → 방송 출력 설정 → 외부 방송 화면 확인
```

이미지 저장에는 움직임 준비와 카메라·마이크가 필요 없다. 외부 아바타 내보내기에는 대상 형식의 필수 구조가 필요하지만 카메라·마이크 연결이 필수는 아니다. 카메라를 연결하지 않은 경우에도 지원하는 자동 동작·음성 반응·수동 표정 등 사용 가능한 기능은 유지한다.

## 3. 모든 기능에 적용하는 규칙

### 3.1 편집·저장·실행의 데이터 구분

| 구분 | 의미 | 변경 시 처리 |
|---|---|---|
| 원본 | 가져온 그림과 제공 파츠의 기준 리소스 | 직접 덮어쓰지 않음 |
| 작업본 | 사용자가 현재 편집하는 프로젝트 리비전 | 변경 시 미저장 표시, 의존 결과 재검사 |
| 명시적 저장본 | 사용자가 저장한 정상 상태 | 저장 성공 후에만 마지막 저장 상태 갱신 |
| 복구본 | 자동 저장·중요 변경 전 체크포인트 | 명시적 저장본과 구분하여 복구에 활용 |
| 실행본 | 실행 시작 또는 변경 반영 시 고정한 상태 | 검증한 변경만 안전한 시점에 반영 |
| 작업 입력본 | 분석·내보내기 작업을 시작할 때 고정한 상태 | 작업 도중 편집과 섞지 않음 |

`revision`은 편집 변화 식별자, `savedRevision`은 저장된 변화 식별자다. 리비전은 논리 버전을 뜻하며 파일 구조 버전인 `schemaVersion`과 다르다. 프로젝트가 변경되면 관련 호환 검사와 분석 결과가 어떤 리비전에 기반했는지 비교한다.

### 3.2 변경 적용과 비동기 작업

1. 분석·재생성·변환은 입력 리비전과 작업 ID를 고정하고 시작한다.
2. 처리 중 결과는 임시 영역에 둔다. 취소·실패했다고 정상 프로젝트를 되돌리거나 덮어쓰지 않는다.
3. 결과를 적용할 때 대상 프로젝트 ID와 입력 리비전을 다시 확인한다.
4. 그동안 관련 구조가 바뀌었으면 결과를 자동 덮어쓰지 않는다. 비교 후 적용, 해당 작업 재실행 또는 결과 폐기를 선택한다.
5. 최초 초안에서는 겹치는 구조 편집을 잠시 제한할 수 있다. 이때 어떤 조작이 왜 잠겼는지 표시한다.
6. 저장·내보내기 중에도 작업 입력본과 출력 위치를 고정한다. 완료 뒤 더 최신 편집이 있으면 미저장 또는 재내보내기 필요 상태를 유지한다.
7. 동일 버튼 연속 클릭이 동일 작업을 중복 시작하지 않도록 한다.
8. 프로젝트를 닫거나 전환하면 진행 중 작업의 취소·완료 대기 여부를 정한다. 이전 프로젝트의 결과가 새 프로젝트에 붙지 않게 한다.

### 3.3 취소와 오류의 공통 의미

- `취소 요청`과 `취소 완료`를 구분한다. 정리 중에는 곧바로 종료한 것처럼 표시하지 않는다.
- 취소 가능한 구간을 명시한다. 최종 저장 전환처럼 중단하면 손상될 수 있는 구간은 짧게 완료를 기다리게 하고 이유를 표시한다.
- 오류는 요약, 영향받는 기능, 보존된 상태, 해결 행동을 제공한다.
- 재시도는 가능한 최소 단계에서 시작하고 기존 보정·파일을 유지한다.
- 사용자가 확인해야 하는 것은 외형 변경, 호환 손실, 덮어쓰기 등 실제 결과에 관한 사항이다. 모든 정상 조작에 확인창을 띄우지 않는다.
- 오류창·진행률·선택선은 방송용 출력에 포함하지 않는다.

### 3.4 변경 무효화 규칙

| 변경 | 유지할 항목 | 재검사·재생성이 필요한 항목 |
|---|---|---|
| 프로젝트·부위 표시 이름 | ID 기반 연결, 외형, 움직임 | 대상 형식 이름 규칙, 결과물 표시 정보 |
| 파츠 색상 | 역할, 대부분의 움직임·표정 | 이미지·텍스처 출력, 외부 내보내기 결과 |
| 파츠 교체 | 호환 가능한 공통 매개변수와 사용자 취향 | 해당 부위 구조·표정 연결·변형, 외부 호환 검사 |
| 눈·입 위치 또는 영역 | 다른 부위의 보정 | 영향받는 변형·연결, 해당 움직임과 출력 검사 |
| 부위 역할·계층·삭제 | 영향받지 않는 다른 부위 | 참조 무결성, 표정·매핑, 실행 준비·외부 검사 |
| 움직임 범위·표정 | 외형과 원본 | 실행 반영, 관련 외부 변환·품질 확인 |
| 장치·중립 보정 | 캐릭터 구조와 외부 내보내기 | 해당 장치 입력 매핑·실행 상태 |
| 외부 대상·버전 | 원본 프로젝트 | 해당 대상 호환 검사와 내보내기 |

무효화는 원본이나 기존 정상 결과를 즉시 삭제한다는 뜻이 아니다. 오래된 결과임을 표시하고 갱신 전 사용 가능한 범위를 알려준다.

## 4. 상태와 전이

### 4.1 독립 상태 축

| 축 | 논리 상태 | 핵심 규칙 |
|---|---|---|
| 프로젝트 | EMPTY, DRAFT, READY, RECOVERY_REQUIRED | 프로젝트 존재·편집 가능 상태를 나타냄 |
| 저장 | CLEAN, DIRTY, SAVING, SAVE_FAILED | 저장 실패가 실행·이미지 미리보기 자체를 막지는 않음 |
| 제작 준비 | INPUT_READY, ANALYZING, NEEDS_FIX, EDITABLE, MOTION_READY | NEEDS_FIX의 항목별 심각도로 다음 작업 가능 여부 결정 |
| 장치 | DISCONNECTED, CONNECTING, AVAILABLE, DENIED, BUSY, FAILED | 카메라와 마이크를 각각 관리 |
| 추적 | IDLE, CALIBRATING, TRACKING, LOST, RECOVERING | 장치 연결과 얼굴 추적 성공을 구분 |
| 앱 실행 | STOPPED, STARTING, RUNNING, DEGRADED, STOPPING, FAILED | DEGRADED는 대체 동작·품질 제한 등으로 실행 중인 상태 |
| 방송 출력 | OFF, PREPARING, SOURCE_READY, FAILED | 우리 앱의 출력 상태. 외부 수신 확인과 별개 |
| 외부 수신 확인 | UNCONFIRMED, USER_CONFIRMED, AUTO_VERIFIED, STALE | 확인 방식과 대상·시각·설정 버전을 기록 |
| 대상 호환성 | NOT_CHECKED, CHECKING, PASS, WARNING, BLOCKED, STALE | 외부 대상·프로젝트 리비전별로 판정 |
| 결과 파일 | NONE, BUILDING, WRITTEN, WRITE_FAILED | 파일 생성 성공과 외부 구동 성공을 분리 |

전역 상태 하나로 모든 기능을 잠그지 않는다. 예를 들어 마이크 권한이 거부되어도 이미지 저장과 카메라 추적은 가능할 수 있다. 부위 누락도 캐릭터 전체를 무조건 차단하지 않고 해당 기능에 필요한 조건을 기준으로 판단한다.

### 4.2 장시간 작업 상태

| 현재 상태 | 사건 | 다음 상태 | 처리 |
|---|---|---|---|
| QUEUED | 실행 시작 | RUNNING | 입력 고정, 진행 단계 표시 |
| RUNNING | 취소 요청 | CANCEL_REQUESTED | 지원되는 중단 지점까지 처리 |
| CANCEL_REQUESTED | 임시 결과 정리 완료 | CANCELLED | 원래 작업본 유지 |
| RUNNING | 처리 완료 | RESULT_READY | 결과 검증 후 적용 또는 파일 확정 |
| RESULT_READY | 입력과 대상 유효 | SUCCEEDED | 결과 적용·완료 기록 |
| RESULT_READY | 대상 변경 감지 | AWAITING_REVIEW | 자동 적용 보류, 비교·재실행 안내 |
| AWAITING_REVIEW | 비교 후 선택 적용·재검증 통과 | SUCCEEDED | 최신 작업본과의 참조를 확인하고 체크포인트 생성 후 적용 |
| AWAITING_REVIEW | 결과 폐기 | DISCARDED | 작업본 유지, 임시 결과 정리 |
| AWAITING_REVIEW | 최신 입력으로 재실행 | DISCARDED 및 새 QUEUED 작업 | 기존 결과 폐기 후 최신 리비전 고정 |
| RUNNING / RESULT_READY | 오류 | FAILED | 오류 범위 기록, 정상 데이터 유지 |
| FAILED / CANCELLED | 다시 시도 | 새 QUEUED 작업 | 새 작업 ID, 재사용 가능한 단계 활용 |

성공 직전에 취소 요청이 겹쳤을 때는 결과 적용 경계에서 한 번만 판정한다. 이미 확정된 결과를 취소했다고 거짓 표시하지 않고 완료 여부와 되돌리기 방법을 안내한다. 보류 결과의 선택 적용이 재검증을 통과하지 못하면 AWAITING_REVIEW를 유지하고 수정·재실행·폐기 경로를 제공한다.

### 4.3 다음 행동의 허용 조건

| 행동 | 최소 조건 | 필수로 요구하지 않는 것 |
|---|---|---|
| 이미지 저장 | 표시 가능한 외형, 유효한 출력 설정 | 움직임 구조, 카메라·마이크 |
| 움직임 미리보기 | 필요한 부위·매개변수와 지원 변형 | 실제 추적 장치 |
| 앱 자동 반응 실행 | 지원하는 움직임 구조와 입력 대안 | 카메라 추적 성공 |
| 카메라 추적 실행 | 카메라 사용 가능, 보정·매핑 준비 | 마이크 사용 가능 |
| 방송 출력 | 유효한 실행본과 선택한 출력 방식 | 외부 아바타용 파일 내보내기 |
| 외부 내보내기 | 선택 대상의 필수 항목 충족, 경고 확인 | 우리 앱의 실시간 실행, 카메라·마이크 |

## 5. 프로젝트 기능

### F-PRJ-001. 새 프로젝트와 제작 방식 선택

**범위:** 초기 필수. **연결:** FR-PROJ-01, PD-03~05.

- **입력:** 프로젝트 이름, 제작 경로, 선택한 기본 캐릭터 또는 파일.
- **선행 조건:** 앱이 새 프로젝트를 열 수 있는 상태. 기존 미저장 변경은 보존·저장·취소 중 선택한다.
- **처리:** 고유 프로젝트 ID를 만들고 경로 유형을 기록한다. 파츠는 S-PARTS로, 그림은 S-IMPORT로 이동한다.
- **이름 규칙:** 표시 이름과 실제 저장 경로를 구분한다. 빈 이름은 임시 이름을 사용하고, 파일 이름에 사용할 수 없는 문자는 저장 단계에서 처리한다.
- **출력:** 편집 가능한 초안과 시작 안내. 입력 실패만으로 초안과 기존 프로젝트를 지우지 않는다.
- **예외:** 새 제작을 취소하면 이전 정상 화면으로 돌아간다. 미구현 3D·생성 경로를 선택 가능한 완료 기능으로 표시하지 않는다.
- **저장:** ID, 생성 시각, 경로 유형, 초안 이름, 스키마 버전.
- **완료 기준:** 세 초기 경로를 각각 시작하고 같은 프로젝트 저장·편집 체계로 이어갈 수 있다.

### F-PRJ-002. 최근 프로젝트·열기·리소스 재연결

**범위:** 초기 필수. **연결:** FR-PROJ-01, NFR-DATA-02/03.

1. 이름, 미리보기, 마지막 수정 시각, 마지막 경로를 최근 목록에 표시한다.
2. 파일을 열면 버전·필수 데이터·리소스 연결을 검사한 뒤 화면에 적용한다.
3. 더 새로운 스키마를 무리하게 읽어 다시 저장하지 않는다. 지원 불가 또는 제한 열기를 안내한다.
4. 누락 리소스가 있으면 항목별 원래 역할과 대체 파일 선택을 제공한다. 가능한 부분의 미리보기를 유지한다.
5. 최근 목록에서 제거하는 동작은 프로젝트 실제 삭제와 구분한다. 실제 파일 삭제 기능은 초기 필수로 두지 않는다.
6. 바로 실행을 선택하면 읽기 후 F-RUN-001을 수행한다. 과거 장치가 없으면 재선택하고 구조 편집을 반복시키지 않는다.

- **출력:** 검증한 작업본, 누락·버전 보고, 필요 시 복구 안내.
- **완료 기준:** 저장 후 앱을 다시 열어 외형·표정·움직임을 재현한다. 경로를 바꾼 프로젝트의 리소스를 재연결할 수 있다.

### F-PRJ-003. 저장·다른 이름으로 저장

**범위:** 초기 필수. **연결:** FR-PROJ-01/02, NFR-DATA-01.

- **입력:** 저장 리비전, 대상 위치. 처음 저장하는 프로젝트는 위치를 선택한다.
- **처리:** 필요한 리소스를 확인하고 임시 결과를 기록한 뒤, 검증된 결과를 정상 저장본으로 확정한다. 구현 수단은 기술 설계에서 정한다.
- **상태:** 저장 중 표시와 대상 리비전을 유지한다. 저장 도중 편집이 더 진행되면 그 이후 변경은 DIRTY로 남는다.
- **다른 이름 저장:** 새 위치에 저장 성공한 후 활성 저장 위치를 갱신한다. 기존 파일은 유지한다.
- **덮어쓰기:** 이미 존재하는 다른 파일을 교체할 때 대상과 영향을 확인한다. 같은 작업의 중복 저장 요청은 정리한다.
- **실패:** 공간 부족, 권한, 경로 문제를 구분하고 다른 위치 저장·재시도를 제공한다. 실패를 성공 알림으로 처리하지 않는다.
- **완료 기준:** 저장 당시 리비전이 다시 열리며, 실패 유발 시 마지막 정상 저장본을 읽을 수 있다.

### F-PRJ-004. 복제와 이동 가능한 프로젝트

**범위:** 초기 필수. **연결:** FR-PROJ-01, NFR-DATA-03.

- 복제는 새 프로젝트 ID로 만든다. 내부 부위·매개변수 참조는 일관성을 유지한다.
- 복제는 원본에 영향을 주지 않는다. 새 복제본을 활성화할지 사용자 동작에 맞게 표시한다.
- 다른 기기·폴더로 옮길 수 있도록 사용 리소스를 포함하는 저장 방식 또는 묶음 저장을 제공한다.
- 이동 전 누락 리소스와 포함할 수 없는 리소스를 알려준다. 단순 외부 경로 참조만 남기고 이동 가능하다고 표시하지 않는다.
- 기기별 장치 ID와 민감한 개인 경로를 이식 필수값으로 두지 않는다.
- **완료 기준:** 원래 위치를 사용할 수 없는 환경에서도 복사본이 동일 외형·움직임으로 열린다. 장치 설정만 필요하면 다시 선택한다.

### F-PRJ-005. 자동 저장·체크포인트·복구

**범위:** 초기 필수. **연결:** FR-PROJ-02, NFR-DATA-01/04.

- DEC-08에 따라 유휴 15초 또는 최대 60초 간격으로 새 리비전 복구본을 만들고 정상 저장 백업 5개·자동 복구 5개, 프로젝트당 복구 공간 2GiB 정책을 적용한다. 최신 유효본을 지우지 않고 부족한 공간을 안내한다. 자동 복구를 사용자 명시 저장으로 표시하지 않으며 실제 통합·실패 복구 시험을 완료 기준에 포함한다.
- 재분석, 구조 일괄 적용, 파츠 큰 변경 전에 복구 지점을 만든다. 같은 결과가 과도하게 중복 저장되지 않게 한다.
- 자동 저장은 명시적 저장본과 구분하고 대상 리비전을 기록한다.
- 재시작 시 복구 가능 상태가 있으면 원본 저장본과 시각·미리보기를 비교해 복구본 열기, 기존 저장본 열기, 판단 보류를 제공한다.
- 복구 실패가 정상 저장본을 손상시키지 않게 한다. 오래된 복구본 정리는 보관 정책에 따른다.
- 원본 저장 위치가 없거나 저장 실패 중이어도 복구 가능한 작업본을 보존하는 방법을 검토한다.
- **완료 기준:** 비정상 종료 후 복구 가능한 변경을 확인하고 선택해 재개한다. 복구 결과와 기존 파일을 구분할 수 있다.

### F-PRJ-006. 되돌리기·다시 실행·화면 이탈

**범위:** 초기 필수. **연결:** FR-PROJ-02, NFR-UX-03.

- 드래그·슬라이더의 연속 조절은 의미 있는 한 번의 편집으로 묶는다. 한 프레임마다 이력을 쌓지 않는다.
- 색 변경, 부위 위치, 역할 변경, 표정 저장, 구조 적용 등을 프로젝트 변화 단위로 취소한다.
- 분석 결과 적용은 일괄 되돌릴 수 있거나 적용 전 체크포인트로 복원할 수 있어야 한다.
- 카메라의 실시간 입력, 미리보기 재생, 화면 확대는 편집 이력에 계속 쌓지 않는다.
- 새 편집으로 기존 다시 실행 분기가 사라지는 시점을 일관되게 정의한다.
- 프로젝트 전환·앱 종료 시 미저장 변경, 실행·방송 중 상태, 진행 작업을 함께 안내한다. 취소하면 현재 작업으로 돌아온다.
- **완료 기준:** 대표 편집을 되돌리고 다시 실행했을 때 외형·참조·매개변수가 일치한다. 종료 취소로 작업이 유지된다.

## 6. 공통 입력과 처리 작업

### F-INP-001. 파일 선택·검증·원본 보존

**범위:** 초기 필수, 지원 목록 검증 대기. **연결:** FR-INPUT-01.

- **입력:** 한 장 이미지 또는 지원하는 분리 그림 소스. 파일 선택과 끌어놓기는 플랫폼에 맞게 제공한다.
- **검사:** 실제 읽기 가능 여부, 형식·버전, 이미지 크기, 투명도, 빈 이미지, 리소스 누락, 처리 자원 제한을 확인한다.
- **전처리:** 회전·방향·색상 등 읽기 단계의 변환은 편집용 사본에 적용한다. 원본에 어떤 변환을 했는지 기록한다.
- **큰 파일:** 바로 실패시키기보다 지원 범위 내 편집용 축소를 제안할 수 있다. 원본은 보존하고 출력 품질의 영향을 설명한다.
- **분리 입력:** 단일 그림 여러 장과 부위 묶음을 혼동하지 않도록 가져오기 유형을 확인한다.
- **출력:** 원본 참조·사본, 검증 보고, 편집용 미리보기. 실패 파일은 정상 리소스로 등록하지 않는다.
- **완료 기준:** 정상·손상·빈·과대 입력에서 원인을 구분하고 원본 내용을 변경하지 않는다.

### F-INP-002. 캐릭터·배경·대상 영역 선택

**범위:** 초기 필수. **연결:** FR-INPUT-01, FR-IMG-01.

1. 단일 캐릭터가 명확하면 자동 선택 결과를 미리 보여준다.
2. 복수 캐릭터이면 대상 선택을 요청한다. 지원하지 못하는 장면이면 그 이유를 알린다.
3. 배경과 캐릭터가 섞인 경우 영역·마스크를 조절하는 간단한 보정 경로를 제공한다.
4. 잘린 부위, 매우 작은 얼굴, 가려진 눈·입은 분석 전후 제한 항목으로 표시한다.
5. 원본 좌표와 자른 편집 좌표 사이의 관계를 기록해 보정 위치가 어긋나지 않게 한다.
6. 영역을 바꾸면 영향받는 분석 결과를 다시 준비하되 다른 프로젝트의 결과를 재사용하지 않는다.

- **완료 기준:** 사용자가 선택한 캐릭터를 기준으로 분석하고, 선택 변경 후 과거 영역의 결과가 잘못 적용되지 않는다.

### F-INP-003. 분석 진행·취소·재시도

**범위:** 초기 필수. **연결:** FR-INPUT-02.

- 실제 단계명, 현재 처리 중인 대상, 취소 가능 여부를 표시한다. 정량 진척을 알 수 없는 단계에 임의의 퍼센트를 표시하지 않는다.
- 실행 시간 예측은 근거가 있을 때만 제공한다. 장시간 응답 없음과 정상 처리 중을 가능한 범위에서 구분한다.
- 취소 요청 후 리소스를 정리하고 원래 작업본으로 돌아간다.
- 실패한 단계와 재사용할 수 있는 완료 단계를 기록한다. 재시도 시 전체 재분석이 필요한 경우 이유를 알린다.
- 자동 분석을 쓰지 못하는 환경이면 지원 가능한 다른 제작 경로와 장치·자원 조건을 안내한다.
- **저장:** 작업 ID, 입력 리비전, 처리 구성 버전, 단계, 결과 상태, 민감 정보를 제외한 실패 진단.
- **완료 기준:** 중복 클릭, 취소, 실패, 프로젝트 전환, 재시도에서 이중 적용이나 원본 손상이 없다.

## 7. 파츠 조합 제작

### F-PAR-001. 파츠 탐색과 호환 목록

**범위:** 초기 필수. **연결:** FR-PART-01.

- 부위 카테고리와 썸네일을 제공하고 현재 적용 파츠를 표시한다.
- 몸체·스타일·좌우 쌍·고정 위치 등 파츠가 요구하는 호환 정보를 참조한다.
- 사용할 수 없는 파츠는 이유를 표시한다. 호환 불가 파츠를 선택한 뒤 결과가 망가지는 방식으로만 알리지 않는다.
- 제공 파츠는 ID와 버전, 미리보기, 적용 부위, 허용 조절, 기본 움직임, 출처·이용 정보를 갖는다.
- 초기 파츠는 로컬 제공 가능한 구성을 우선 검토한다. 온라인 스토어나 다운로드 서비스를 이 기능의 필수 조건으로 두지 않는다.
- 검색·필터의 종류는 파츠 수에 맞게 정한다. 초기 수량과 스타일은 아트 제작 계획에서 결정한다.
- **완료 기준:** 부위별 탐색·현재 선택 확인·호환 불가 원인 확인이 가능하다.

### F-PAR-002. 파츠 적용·교체·제거

**범위:** 초기 필수. **연결:** FR-PART-01, FR-EDIT-01.

1. 선택한 파츠를 현재 캐릭터에 미리 적용한다.
2. 기본 위치, 겹침 순서, 변형 구조, 움직임을 파츠 정의에 따라 연결한다.
3. 유지 가능한 색상과 공통 매개변수 설정은 보존한다. 이전 파츠의 ID에만 의존하는 연결은 다시 검사한다.
4. 눈·입처럼 필수 역할을 제거하면 제한되는 움직임을 표시한다. 장식 제거와 같은 수준으로 취급하지 않는다.
5. 표정·추적 연결이 끊기면 해당 항목을 알리고 자동 재연결 제안 또는 수정을 제공한다.
6. 교체를 취소하거나 되돌리면 원래 파츠와 관련 설정이 함께 복원된다.

- **출력:** 변경된 캐릭터와 영향받는 기능 목록. 정상 실행본에는 검증 전 구조를 바로 덮어쓰지 않는다.
- **완료 기준:** 눈·머리·의상을 교체한 뒤 기존 표정·움직임이 유지되거나 필요한 재설정이 정확하게 표시된다.

### F-PAR-003. 색상·크기·위치·회전·좌우 조절

**범위:** 초기 필수. **연결:** FR-PART-02.

- 파츠가 허용한 색상 영역에만 색을 적용한다. 선과 음영 처리 방식은 파츠 제작 규칙에서 정의한다.
- 조절값은 현재값, 기본값, 허용 범위를 갖고 그림 위에서 결과를 확인한다.
- 좌우 쌍은 연동과 개별 조절을 선택한다. 연동 전환 시 유지할 기준값을 일관되게 정한다.
- 크기·위치를 변경할 때 인접 부위의 겹침과 극단 동작의 품질을 확인할 수 있게 한다.
- 범위 초과는 값 제한 또는 경고로 처리한다. 값이 유효하지 않으면 마지막 정상값을 유지한다.
- 기본값 복원은 선택 파츠·선택 항목·전체 조합의 범위를 구분한다.
- **완료 기준:** 변경과 복원이 재현되고, 저장·재열기 후 동일한 외형과 좌우 설정을 유지한다.

### F-PAR-004. 조합 저장과 재사용

**범위:** 초기 필수, 저장 UI 방식은 검증 대기. **연결:** FR-PART-02, FR-PROJ-01.

- 현재 조합을 재사용할 수 있어야 한다. 최초 구현은 프로젝트 저장·복제로 충족할 수 있으며 별도 프리셋 시스템을 반드시 먼저 만들 필요는 없다.
- 프리셋을 제공한다면 파츠 ID·버전, 색상·변환값, 필요한 공통 설정을 묶고 움직임 포함 여부를 명시한다.
- 존재하지 않는 파츠나 버전 충돌이 있으면 대체 선택을 안내하고 임의 파츠로 조용히 바꾸지 않는다.
- 불러온 조합을 현재 프로젝트에 적용할 때 교체 범위와 영향받는 표정을 확인할 수 있게 한다.
- **완료 기준:** 저장된 조합을 다른 작업 또는 복제본에서 재현하고 원본 조합을 유지한다.

## 8. 한 장 그림에서 움직임 준비

### F-IMG-001. 자동 부위 인식·분리·기본 구조 생성

**범위:** 초기 필수, 분석 기술과 지원 그림 조건 검증 대기. **연결:** FR-IMG-01.

- **입력:** F-INP-001/002를 통과한 그림, 대상 영역, 선택적 사용자 보정.
- **처리 대상:** 얼굴, 눈, 눈썹, 입, 머리, 기본 몸통 관계를 우선 검증한다. 모두를 항상 정확히 분리한다고 보장하지 않는다.
- **처리:** 후보 영역·역할을 찾고 앞뒤 순서와 움직임에 필요한 구조를 제안한다. 지원되는 변형 방식에 맞는 기본 제어를 연결한다.
- **불확실성:** 내부 점수·판단 근거가 있으면 보정 필요 여부에 사용한다. 근거 없는 정밀한 “정확도”를 사용자에게 표시하지 않는다.
- **출력:** 자동 부위 구조, 원본과의 위치 관계, 움직임 후보, 확인할 항목 목록, 지원 제한.
- **미리보기:** 사용 가능한 부위부터 기본 반응을 보여주되 결과가 준비 중임을 표시한다.
- **실패:** 전체 실패와 일부 부위 실패를 나눈다. 일부만 실패하면 해당 기능의 보정·제한 경로를 제공한다.
- **보존:** 원본과 기존 수동 보정은 유지하고 결과는 검토 후 적용한다.
- **완료 기준:** 지원 입력에 대해 사용자가 사전 부위 분리나 수동 리깅을 하지 않아도 기본 움직임을 확인한다.

### F-IMG-002. 가려진 부분 보완과 제한 동작

**범위:** 초기 필수인 문제 처리, 구체 보완 방식 검증 대기. **연결:** FR-IMG-02.

1. 눈 감기, 입 벌리기, 제한된 고개 움직임에서 추가 영역이 필요한지 찾는다.
2. 원본에서 보이지 않는 영역은 “원본 복원”이 아니라 추정·보완 결과로 취급한다.
3. 보완 가능한 경우 후보를 보여주고 원본 영역과 구분해 확인할 수 있게 한다.
4. 사용자는 후보 선택, 제공되는 간단 수정, 변경 취소, 움직임 범위 축소 중 가능한 방법을 선택한다.
5. 보완이 부족하면 어떤 동작에서 문제가 생기는지 보여주고 해당 동작을 제한한다.
6. 자동으로 다른 화풍이나 외형으로 크게 바꾸지 않는다. 인상이 달라지는 변경은 확인 후 적용한다.

- **저장:** 보완 영역, 출처 유형, 사용자가 확정한 결과, 허용 움직임 범위, 원본과의 연결.
- **의존성:** 장기 글 기반 생성 모델의 완성을 선행 조건으로 요구하지 않는다.
- **완료 기준:** 가려진 부위가 있는 샘플에서 보완·제한·실패를 구분하고 원본 상태로 돌아갈 수 있다.

### F-IMG-003. 단계별 간단 보정

**범위:** 초기 필수. **연결:** FR-IMG-03, NFR-UX-01/02.

- **진입:** 분석 결과의 확인 항목 또는 사용자가 선택한 “모양 고치기”.
- **표시:** 현재 부위, 필요한 이유, 한 번에 수행할 행동, 수정 후 미리보기를 제공한다.
- **위치 보정:** 눈·입 등의 표시점을 옮기고 크기·범위를 조절한다. 작은 영역은 확대해 조작할 수 있다.
- **영역 보정:** 선택 영역의 추가·제거 또는 경계 조절 등 지원하는 쉬운 조작을 제공한다. 정확한 도구 구성은 사용성 검증으로 정한다.
- **겹침 보정:** “이 머리카락을 얼굴 앞으로”처럼 결과 중심으로 앞뒤 순서를 바꾼다.
- **확정:** 부위별로 적용하고 다음 항목으로 이동한다. 관련 동작만 짧게 재처리해 확인한다.
- **건너뛰기:** 무시 가능한 경고와 해당 기능을 막는 오류를 구분하고 건너뛴 결과를 설명한다.
- **복원:** 현재 부위의 자동 결과로 복귀와 전체 보정 취소를 구분한다.
- **완료 기준:** 인식 위치가 틀린 샘플을 초보자가 안내로 수정하고 수정된 눈·입 움직임을 확인한다.

### F-IMG-004. 재분석·비교·선택 적용

**범위:** 초기 필수. **연결:** FR-INPUT-02, FR-IMG-01/03, FR-PROJ-02.

- 재분석 범위를 전체 또는 지원하는 일부 부위로 지정한다. 부분 처리가 불가능하면 전체 처리 필요를 알린다.
- 사용자 보정이 있으면 유지 가능한 항목, 재검사가 필요한 항목, 덮어쓸 항목을 구분한다.
- 새 결과를 임시 상태로 만들고 현재 결과와 비교한다. 적용 전 체크포인트를 보존한다.
- 재분석 중 작업본이 바뀌면 자동 적용을 보류한다. 최신 편집을 덮어쓴 뒤 성공 처리하지 않는다.
- 적용하면 영향받는 움직임·표정·호환 검사를 무효화하고 필요한 부분을 다시 연결한다.
- 취소·실패 시 현재 결과와 실행본을 유지한다.
- **완료 기준:** 수동 보정 후 재분석을 시도해 보정 유지·결과 교체·취소가 예측 가능하게 동작한다.

## 9. 부위가 분리된 그림 가져오기

### F-LYR-001. 분리 구조 읽기와 좌표 정리

**범위:** 초기 필수, 입력 형식 검증 대기. **연결:** FR-LAYER-01, FR-INPUT-01.

- 지원하는 레이어 소스 또는 개별 이미지 묶음에서 부위, 이름, 위치, 순서, 투명도와 그룹 정보를 가능한 범위에서 읽는다.
- 형식이 표현하지 않는 정보는 추정 또는 사용자 지정이 필요하다고 표시한다. 개별 부위 이미지에 원래 좌표가 없다면 임의로 정확한 위치를 알고 있다고 처리하지 않는다.
- 전체 캔버스 기준과 부위별 로컬 좌표를 정의하고 원본의 위치를 재현한다.
- 크기가 다른 이미지, 빈 레이어, 숨김 레이어, 동일 이름 레이어를 구분한다. 표시 이름 중복이 내부 ID 충돌을 만들지 않게 한다.
- 초기에는 사용할 수 있는 구조만 우선 가져올 수 있으나 누락되는 효과나 속성을 보고한다.
- **출력:** 부위 트리, 합성 미리보기, 보존·변환·누락 항목 보고.
- **완료 기준:** 지원 샘플의 합성 외형과 순서를 재현하고, 지원하지 않는 속성의 영향을 확인할 수 있다.

### F-LYR-002. 역할 자동 제안과 안내 연결

**범위:** 초기 필수. **연결:** FR-LAYER-01.

1. 이름, 위치, 형태 등 사용 가능한 근거로 눈·입·머리 등 역할을 제안한다.
2. 캐릭터 기준 좌우를 기본으로 표시한다. 화면 미러링은 미리보기 옵션으로 분리한다.
3. 확실한 제안은 미리 적용하고 불확실한 항목은 그림과 함께 확인하게 한다.
4. 같은 역할의 후보가 여러 개면 대표·보조·표정별 대체 등 가능한 의미를 구분한다. 잘못된 중복을 조용히 덮어쓰지 않는다.
5. 장식처럼 역할 없이 표시 가능한 부위는 미지정 상태로 둘 수 있다. 움직임이 필요한 필수 역할 누락은 따로 안내한다.
6. 연결을 확정하면 기본 움직임을 제안하고 공통 표정·추적 편집으로 이동한다.

- **완료 기준:** 이름이 불명확한 분리 그림도 안내로 역할을 지정한다. 좌우가 뒤집히거나 역할이 바뀐 경우 수정할 수 있다.

### F-LYR-003. 부위 순서·연결·누락 검사

**범위:** 초기 필수. **연결:** FR-LAYER-01, FR-EDIT-01.

- 눈·입이 얼굴 뒤로 사라지는 등 겹침 문제를 확인하고 순서를 조절한다.
- 부모·자식 연결에 순환 참조를 허용하지 않는다. 삭제된 부위를 가리키는 연결을 탐지한다.
- 누락 역할은 필요한 움직임과 함께 표시한다. 눈이 없는 디자인 등 의도된 구조는 기능 제한을 수용하고 진행할 수 있어야 한다.
- 움직임용으로 묶은 부위와 단순 화면 그룹을 구분한다. 그룹 이름 변경이 연결을 깨지 않게 한다.
- 순서·구조 변경 이후 관련 변형·표정·내보내기를 다시 검사한다.
- **완료 기준:** 누락·중복·잘못된 계층 샘플에서 다음 행동을 안내하고 유효한 구조만 실행에 반영한다.

## 10. 공통 편집과 세부 편집

### F-EDT-001. 미리보기 화면 조작과 선택

**범위:** 초기 필수. **연결:** FR-EDIT-01, NFR-UX-04.

- 캐릭터 확대·축소, 화면 이동, 전체 맞춤, 원본과 비교를 제공한다.
- 부위를 직접 선택하거나 목록에서 선택하며 선택 상태를 서로 동기화한다.
- 화면 확대·이동은 캐릭터 실제 좌표나 방송 출력 위치를 바꾸지 않는다.
- 배경 미리보기는 투명도 확인과 작업 편의를 위한 설정이다. 실제 이미지·방송 배경 설정과 구분한다.
- 편집 핸들, 보정점, 가이드 표시 여부를 조절한다. 출력 결과에는 포함하지 않는다.
- 작은 부위를 조작할 때도 현재 선택과 키보드 초점을 확인할 수 있게 한다.
- **완료 기준:** 선택·화면 조작이 출력 좌표를 바꾸지 않고, 저장·출력에는 작업 보조 UI가 포함되지 않는다.

### F-EDT-002. 부위·연결·변형 세부 편집

**범위:** 초기 필수, 세부 제어 수준 검증 대기. **연결:** FR-EDIT-01.

- 간단 편집과 같은 프로젝트의 부위 역할, 계층, 순서, 기준점, 변형 범위, 매개변수 연결을 편집한다.
- DEC-05에서 원화 텍스처·공통 삼각망/가중치·제어 곡선과 공유 GPU 렌더를 채택했다. 외부 스키마와 내부 모델을 분리하고 같은 제어의 내부/외부 변형을 비교한다. 상세 망 생성·보간과 제품 구현은 후속 작업이다.
- 값의 허용 범위와 참조 무결성을 검사하고 유효하지 않은 구조는 적용하지 않는다.
- 연결 삭제·변경 시 영향받는 표정·추적·출력 기능을 보여준다.
- 변경 전후에 최소·중립·최대 동작을 확인하고 부위별 기본값 복원을 제공한다.
- 간단 화면으로 돌아가도 세부 조정을 보존한다. 간단 조작이 세부 구조를 덮어쓰면 영향을 먼저 안내한다.
- **완료 기준:** 특정 부위의 움직임을 세부 수정하고 저장·재실행·외부 검사까지 이어가며 다른 부위 설정은 유지한다.

## 11. 표정·반응·움직임

### F-MOT-001. 공통 매개변수와 기본 움직임

**범위:** 초기 필수. **연결:** FR-MOTION-01.

- 캐릭터 매개변수를 장치 값과 분리한다. 매개변수는 고유 ID, 표시 이름, 기본값, 최소·최대값, 영향 부위를 갖는다.
- 초기 핵심은 눈 열림·깜빡임, 입 열림, 제한된 고개 움직임이다. 세부 축·범위는 캐릭터와 추적 기술 검증 후 확정한다.
- 범위를 벗어난 입력은 제한하고, 계산 불가능한 값이나 끊긴 입력은 정상값으로 사용하지 않는다.
- 움직임 강도·부드러움과 기본 자세를 조절하고 극단값에서 외형을 확인한다.
- 모든 캐릭터가 모든 매개변수를 가져야 하는 것은 아니다. 실제 가능한 기능 목록을 캐릭터 구조에서 산출한다.
- 장식·머리카락 보조 흔들림은 초기 검토 기능이다. 제공한다면 흔들림 초기화와 급격한 입력 처리 규칙을 추가한다.
- **완료 기준:** 장치 없는 수동 값 입력으로 핵심 움직임을 재현하고 허용 범위 밖에서 심한 구조 오류가 발생하지 않는다.

### F-MOT-002. 예제 동작·단일 동작·전체 미리보기

**범위:** 초기 필수. **연결:** FR-MOTION-01, FR-IMG-03.

- 눈 감기, 입 열기, 좌우·상하 움직임 등 지원 동작을 개별 시험한다.
- 조절 막대 또는 예제 재생으로 최소·중립·최대 상태를 확인한다. 실제 카메라가 필요하지 않다.
- 여러 동작을 함께 재생해 겹침과 표정 충돌을 확인할 수 있게 한다.
- 재생 중 편집값을 바꾸면 적용된 범위를 명확히 하고, 중지 후 기본 자세로 복귀한다.
- 테스트 입력과 실제 추적 입력을 구분하며 미리보기 재생이 저장된 기본값을 임의로 바꾸지 않는다.
- **완료 기준:** 카메라 없이 눈·입·고개 동작과 복합 상태를 확인하고 중지·반복 재생할 수 있다.

### F-MOT-003. 표정 만들기·저장·전환

**범위:** 초기 필수. **연결:** FR-MOTION-02.

- 표정 이름, 대상 매개변수 값, 적용 부위, 전환 방식을 정의한다.
- 현재 미리보기 상태에서 표정을 만들되 일시적인 추적 잡음이 원치 않게 저장되지 않도록 저장 범위를 확인한다.
- 표정 만들기·복제·이름 변경·삭제·기본 표정 복귀를 제공한다.
- 전환은 즉시/부드러운 전환 등 검증한 방식을 지원하고 전환 시간은 허용 범위를 둔다.
- 초기 동시 수동 표정은 하나를 기본안으로 한다. 다중 표정 합성은 별도 검증 없이 지원한다고 약속하지 않는다.
- 부위 삭제나 파츠 교체로 참조가 깨진 표정은 영향 항목을 표시하고 재연결한다.
- **완료 기준:** 여러 부위가 포함된 표정을 저장·재열기·전환하고 해제하면 정상 추적 또는 기본 상태로 돌아간다.

### F-MOT-004. 제어 우선순위와 충돌 해결

**범위:** 초기 필수, 아래 우선순위는 설계 제안. **연결:** FR-MOTION-02/03.

| 순서 | 제어 | 적용 규칙 |
|---|---|---|
| 최우선 | 안전 제한·입력 유효성 | 최종값이 허용 범위 밖으로 나가지 않게 제한 |
| 상위 | 편집용 단일 동작 테스트 | 테스트 대상으로 지정한 매개변수만 임시 제어 |
| 상위 | 수동 표정의 고정 항목 | 표정이 소유한 부위만 추적·자동 제어에서 제외 |
| 기본 | 카메라 / 마이크 매핑 | 선택한 입력 정책에 따라 값 생성 |
| 보조 | 자동 깜빡임·대체 동작 | 해당 부위의 유효 입력이 없고 고정 표정도 없을 때 적용 |
| 기본값 | 중립 자세 | 다른 유효 제어가 없는 항목에 적용 |

- 표정이 고정하지 않은 고개·입 등은 계속 추적할 수 있다. 표정 하나가 캐릭터 전체 입력을 무조건 잠그지 않는다.
- 입 입력은 카메라 우선, 마이크 우선 등 명시적 모드를 제공한다. 초기 임의 가중 합산은 기본안으로 두지 않는다.
- 표정 해제 시 최신 입력 상태로 부드럽게 복귀한다. 표정 시작 당시의 오래된 추적값으로 돌아가지 않는다.
- 입력이 끊기면 대체 정책을 적용하고 복구 후 급격한 튐을 줄인다.
- **완료 기준:** 눈 고정 표정 중 고개 추적이 유지되고, 해제 후 눈 입력으로 복귀하며 입 입력 충돌이 선택 정책대로 동작한다.

### F-MOT-005. 마이크 반응과 감도 조절

**범위:** 초기 필수. **연결:** FR-MOTION-03.

1. 사용할 마이크를 선택하고 권한·입력 상태와 레벨을 표시한다.
2. 조용한 상태의 기준과 반응 감도를 조절한다. 주변 소음에서 입이 계속 움직이는지 미리 확인한다.
3. 소리 크기를 입 움직임 값으로 변환하고 반응 강도·부드러움을 적용한다.
4. 카메라 입 추적과 함께 쓸 경우 F-MOT-004의 모드를 명시한다.
5. 입력이 끊기면 입을 닫거나 정한 대체값으로 복귀한다. 마지막 큰 입력으로 계속 벌어지지 않게 한다.

- **개인정보:** 기본 동작은 반응 분석이며 음성을 녹음하거나 방송 오디오를 송출하는 기능이 아니다.
- **제외:** 초기 음소 인식·대사 인식·음성 합성은 필수로 두지 않는다.
- **완료 기준:** 조용할 때·말할 때·소음·연결 해제에서 입 반응과 감도 조절이 의도대로 동작한다.

## 12. 카메라 추적과 입력 복구

### F-TRK-001. 카메라 목록·권한·연결

**범위:** 초기 필수, 지원 장치 범위 검증 대기. **연결:** FR-TRACK-01.

- **입력:** 카메라 선택, 미리보기 표시 여부, 지원하는 입력 설정.
- **표시:** 장치 존재, 연결 중, 권한 거부, 사용 중, 읽기 실패, 프레임 수신 여부를 가능한 범위에서 구분한다.
- **연결:** 장치 열기 성공과 얼굴 검출 성공을 별개로 판정한다. 연결되었다고 추적 성공으로 표시하지 않는다.
- **장치 변경:** 이전 장치 자원을 해제하고 새 입력을 연결한다. 실행 중에는 정해진 대체 동작을 유지한다.
- **복수 얼굴:** 기존 대상 유지·대상 선택 등 정책을 제공한다. 단순히 얼굴 수가 바뀌었다고 다른 사람에게 임의 전환하지 않는다.
- **개인정보:** 카메라 원본은 사용자용 화면에서만 확인한다. 방송 캐릭터 소스에 포함하지 않는다.
- **예외:** 운영체제나 드라이버가 정확한 원인을 제공하지 않으면 추정 원인을 확정 사실로 표시하지 않는다.
- **완료 기준:** 연결·권한 거부·장치 점유·장치 변경에서 상태와 다음 행동을 확인하고 다른 기능의 데이터가 유지된다.

### F-TRK-002. 중립 자세와 움직임 범위 보정

**범위:** 초기 필수. **연결:** FR-TRACK-01.

1. 정면을 보고 편한 자세를 취하도록 안내하고 입력이 안정되었는지 확인한다.
2. 보정 시작 시 관련 표정·테스트 입력이 결과에 영향을 주지 않도록 구분한다.
3. 유효한 입력 구간에서 중립 기준과 필요한 범위를 계산한다. 얼굴이 사라지면 부정확한 기준을 확정하지 않는다.
4. 캐릭터의 좌우·상하 반응을 확인하고 방향·세기를 조절한다.
5. 보정 성공 시 해당 장치·입력 설정과 연결해 저장한다. 재보정 실패 시 마지막 정상 보정값을 유지한다.

- **미러링:** 카메라 미리보기 좌우 반전과 캐릭터 회전 방향을 다른 설정으로 취급한다.
- **부담:** 전문 장비, 신체 치수, 수학적 좌표 입력을 기본 절차로 요구하지 않는다.
- **완료 기준:** 중립 자세에서 캐릭터가 의도한 기본 자세를 유지하고, 재보정 취소·실패에서 기존 정상값이 남는다.

### F-TRK-003. 입력과 캐릭터 매개변수 매핑

**범위:** 초기 필수. **연결:** FR-TRACK-01/02, FR-MOTION-01.

- 추적값의 유효 범위를 캐릭터 매개변수의 허용 범위로 변환한다.
- 부위별 사용 여부, 방향, 강도, 부드러움, 필요한 입력 기준을 제공한다. 초보자에게는 기본 프리셋을 먼저 적용한다.
- 수신되지 않는 매개변수는 이전 값을 무한 유지하지 않고 대체 정책을 따른다.
- 과도한 떨림, 순간적인 극단값, 유효하지 않은 수치에 대한 필터·제한을 적용한다. 구체 알고리즘은 기술 설계에서 정한다.
- 카메라를 바꿔도 캐릭터 구조와 표정은 유지한다. 새 입력에서 보정이 필요한 부분만 안내한다.
- 추적 기술이 제공하지 않는 값을 실제 추적 중이라고 표시하지 않는다.
- **완료 기준:** 중립·최소·최대 입력, 끊김, 잘못된 값이 안전하게 캐릭터 값으로 변환된다.

### F-TRK-004. 추적 손실·대체 동작·재연결

**범위:** 초기 필수, 시간 임계값 검증 대기. **연결:** FR-TRACK-02, FR-BROAD-03.

| 사건 | 제어 화면 | 캐릭터 동작 제안 |
|---|---|---|
| 짧은 얼굴 미검출 | 추적 불안정 | 마지막 정상 자세를 짧게 유지 |
| 미검출 지속 | 추적 없음 | 중립 자세·자동 깜빡임 등 정한 대안으로 전환 |
| 카메라 해제 | 연결 끊김, 재연결 버튼 | 유효한 마이크·수동 표정은 유지 |
| 유효 얼굴 재검출 | 복구 중 | 최신 입력으로 부드럽게 복귀 |
| 보정이 크게 어긋남 | 다시 맞추기 제안 | 기존 안전 범위 유지 후 사용자 보정 |

- 짧은/긴 손실의 기준 시간과 복귀 방식은 실제 입력으로 조정한다.
- 마이크는 별도 상태를 유지한다. 카메라 손실이 유효한 음성 반응까지 불필요하게 중단하지 않게 한다.
- “추적 다시 맞추기”, “장치 다시 연결”, “기본 자세로”를 구분한다.
- 자동 재연결을 제공한다면 반복 간격·상한·중지 방법을 정의한다. 무한 재연결로 사용자를 방해하지 않는다.
- 복구 알림·오류는 방송 소스에 표시하지 않는다.
- **완료 기준:** 얼굴 가림과 장치 분리 후에도 캐릭터 출력이 정의된 상태를 유지하고 재연결 뒤 정상 제어로 복귀한다.

## 13. 앱 내 실행과 방송 중 변경

### F-RUN-001. 실행 준비 검사

**범위:** 초기 필수. **연결:** FR-RUN-01, FR-EDIT-01.

- 현재 프로젝트의 외형, 리소스, 부위 연결, 매개변수, 표정 참조를 검사한다.
- 선택한 실행 모드에 필요한 장치만 검사한다. 자동 반응이나 수동 모드에 카메라를 무조건 요구하지 않는다.
- 실행을 막는 오류와 일부 기능만 제한하는 경고를 구분한다.
- 문제가 있으면 해당 편집·장치 화면으로 이동할 수 있게 한다. 수정 뒤 전체 제작 과정을 반복시키지 않는다.
- 검사 결과를 대상 리비전과 함께 저장하고 구조가 바뀌면 다시 검사한다.
- **완료 기준:** 준비된 프로젝트는 바로 실행하고, 손상된 참조는 문제 위치를 알려주며, 장치가 없는 대체 모드는 가능한 범위에서 실행한다.

### F-RUN-002. 실행 시작·일시 제어·중지

**범위:** 초기 필수. **연결:** FR-RUN-01, FR-BROAD-03.

1. 실행 시작 시 검증된 리비전으로 실행본을 구성한다.
2. 필요한 장치를 연결하고 표정·추적 입력과 캐릭터 상태를 S-RUN에 표시한다.
3. 실행 중 기본 자세 복귀, 표정 변경, 추적 재보정을 제공한다.
4. 동작 일시 고정, 캐릭터 숨김, 실행 중지는 서로 다른 행동으로 구분한다. 일시 고정 제공 여부는 검증하되 숨김과 중지는 초기 제공한다.
5. 중지 시 출력에 미치는 영향을 알리고 정해진 순서로 출력·실행·장치 자원을 정리한다.
6. 프로젝트와 미저장 편집은 유지한다. 다시 시작하면 마지막 적용한 상태를 재사용할 수 있다.

- **실패:** 시작 실패는 정상 편집 상태를 유지하고 실패한 장치·구조만 표시한다.
- **완료 기준:** 저장 프로젝트를 바로 실행하고 중지·재시작할 수 있으며 반복 실행이 중복 장치 연결이나 데이터 손실을 만들지 않는다.

### F-RUN-003. 실행 중 편집 반영과 프로젝트 전환

**범위:** 초기 필수, 즉시 반영 범위 검증 대기. **연결:** FR-RUN-01.

| 변경 유형 | 초기 반영 정책 제안 | 사용자에게 표시 |
|---|---|---|
| 표정 전환·추적 강도 | 검증 후 실행본에 반영 | 적용 상태 |
| 외형 색상·단순 표시값 | 안전하게 교체 가능할 때 반영 | 즉시 적용 또는 적용 버튼 |
| 텍스처·부위 위치·변형 | 새 실행본 검증 후 교체 | 대기 중 변경과 영향 |
| 파츠 구조·계층·입력 원본 | 초기에는 수동 반영 또는 재시작 | 방송에 미치는 영향, 기존 실행 유지 선택 |
| 실행 프로젝트 변경 | 새 프로젝트 검사 후 명시적 전환 | 출력 중단·전환 여부 |

- 최초 구현에서 구조 변경의 실시간 교체가 어렵다면 작업본만 수정하고 실행본은 유지한다.
- 변경 반영 실패 시 기존 정상 실행본으로 계속 실행하거나 안전하게 중지한다. 반쯤 적용된 상태를 방송에 내보내지 않는다.
- 실행 중 저장과 내보내기는 각각 기준 리비전을 표시한다. 작업본과 실행본이 다르면 어느 결과를 사용했는지 구분한다.
- **완료 기준:** 방송 중 구조를 수정해도 명시적 반영 전 기존 실행이 유지되고, 적용·취소·실패의 결과가 분명하다.

### F-RUN-004. 단축키와 빠른 조작

**범위:** 초기 필수, 전역 입력 지원 검증 대기. **연결:** FR-MOTION-02, FR-BROAD-03.

- 표정 전환·해제, 기본 자세, 추적 재보정, 캐릭터 숨김 등에 버튼과 단축키를 연결한다.
- 앱 안에서만 작동하는 키와 다른 앱 선택 중에도 작동하는 키를 구분해 표시한다.
- 중복 키, 예약 키, 등록 실패를 알려준다. 실제 확보하지 못한 키를 사용 가능으로 표시하지 않는다.
- 텍스트 입력·키 설정 중에 의도치 않은 실행 명령이 발생하지 않도록 한다.
- 토글·누르는 동안·단발 동작 중 지원하는 방식을 명시한다. 숨김과 표정 해제 상태를 화면에서 확인한다.
- 프로젝트별 동작 연결과 기기별 키 등록 상태를 구분한다.
- **완료 기준:** 앱 초점 안팎의 검증 조건에서 약속한 동작만 실행되고 충돌·등록 실패를 재설정할 수 있다.

## 14. 방송 출력과 실제 연결

### F-BRD-001. 방송용 렌더링과 출력 설정

**범위:** 초기 필수, 전달 방식·지원 대상 검증 대기. **연결:** FR-BROAD-01.

- **입력:** 실행본, 지원 출력 방식, 해상도·프레임 설정, 캐릭터 위치·크기·잘림 범위, 배경 설정.
- **출력 내용:** 캐릭터 영상만 전달한다. 편집 UI, 카메라 영상, 파일 경로, 진단, 도움말을 전달하지 않는다.
- **투명도:** 투명 배경 경로를 검증한다. 사용자용 체크무늬가 실제 영상 배경으로 출력되지 않게 한다.
- **미리보기:** 실제 출력 범위와 캐릭터 가장자리, 잘림, 크기를 확인한다. 편집기 확대와 출력 크기를 분리한다.
- **방식:** 창 캡처·전용 전달·가상 장치 등은 후보일 뿐 확정 지원이 아니다. 선정한 방식별 설치·권한·배경 처리 제약을 명시한다.
- **변경:** 해상도·전달 방식 변경이 출력 재시작을 요구하면 사전에 알리고 기존 설정을 복원할 수 있게 한다.
- **상태:** OFF → PREPARING → SOURCE_READY를 관리한다. SOURCE_READY는 외부 수신 확인을 뜻하지 않는다.
- **완료 기준:** 선정한 방식으로 캐릭터와 투명도가 전달되고 사용자용 UI가 외부 소스에 섞이지 않는다.

### F-BRD-002. 방송 프로그램 연결 안내와 확인

**범위:** 초기 필수. **연결:** FR-BROAD-02, AC-09.

1. 지원하는 방송 프로그램·버전과 사용 중인 출력 방식에 맞는 안내를 선택한다.
2. 소스 추가, 대상 선택, 배경·크기 확인, 움직임·표정 확인을 순서대로 안내한다.
3. 앱 출력 준비와 외부 화면 확인을 별도 단계로 표시한다.
4. 자동 수신 검증이 가능하면 그 범위와 결과를 기록한다. 불가능하면 사용자가 외부 미리보기를 보고 확인한다.
5. 확인에는 대상·버전·출력 설정 버전·시각·확인 방식을 기록한다.
6. 대상이나 주요 출력 설정이 바뀌면 이전 확인을 과거 기록으로 남기고 재확인을 요청한다.

- **완료:** 공개 방송 시작을 요구하지 않는다. 실제 방송 프로그램의 미리보기에서 캐릭터가 보이고 움직이면 연결을 확인할 수 있다.
- **제외:** 방송 플랫폼 계정 로그인·송출 키·채팅 관리·음성 송출 전체를 필수로 요구하지 않는다.
- **완료 기준:** 초보자가 안내로 외부 화면에서 캐릭터를 확인하고, 확인이 사용자 판단인지 자동 검증인지 구분한다.

### F-BRD-003. 방송 중 제어·진단·출력 복구

**범위:** 초기 필수. **연결:** FR-BROAD-03, FR-TRACK-02.

- 실행·출력·추적 상태와 주요 빠른 조작을 한 화면에서 제공한다.
- 캐릭터 숨김은 캐릭터 소스만 비우거나 정한 방식으로 숨긴다. 카메라 원본이나 작업 화면을 대신 출력하지 않는다.
- 소스 미표시, 배경 불투명, 캐릭터 잘림, 움직임 정지, 프레임 저하를 구분하는 점검 흐름을 제공한다.
- 외부 수신을 직접 관찰할 수 없는 경우 “현재 방송에서 보이지 않음”을 자동 확정하지 않고 확인을 요청한다.
- 입력 손실은 F-TRK-004, 출력 실패는 출력 방식 재시도, 높은 부하는 F-SET-002로 연결한다.
- 출력 재시작이 필요하면 기존 장면에 미치는 영향을 알린다. 실패 중에도 프로젝트 저장·복구 기능을 유지한다.
- 캐릭터가 숨겨진 상태를 사용자가 쉽게 알아볼 수 있게 한다. 편집 UI를 노출하지 않으면서 복귀할 수 있어야 한다.
- **완료 기준:** 방송 연결 이후 장치 손실·숨김·출력 재시도에서 안전한 화면을 유지하고 정해진 조작으로 복구한다.

## 15. 이미지와 외부 아바타 내보내기

### F-EXP-001. 정지 이미지 저장

**범위:** 초기 필수. **연결:** FR-EXPORT-01, AC-13.

- **입력:** 표시 가능한 캐릭터 외형, 선택 표정·자세, 배경 포함 여부, 지원 이미지 형식, 크기, 저장 위치.
- **조건:** 움직임 구조나 장치 연결이 없어도 외형을 저장할 수 있다.
- **미리보기:** 실제 출력 크기·잘림·투명 배경을 보여준다. 편집 UI와 현재 선택 표시는 제외한다.
- **기준 상태:** 기본은 작업본의 선택 상태다. 실시간 움직임을 캡처할 경우 프레임을 고정해 어떤 모습을 저장하는지 확인한다.
- **검사:** 유효 크기, 최대 출력 제한, 쓰기 가능 경로, 기존 파일 덮어쓰기를 확인한다.
- **실패:** 불완전한 파일을 완료 결과로 표시하지 않고 다른 위치·설정으로 재시도한다.
- **완료 기준:** 선택한 외형·표정·배경·크기의 이미지가 저장되고, 아바타 내보내기와 구분된다.

### F-EXP-002. 외부 대상 프로필 선택

**범위:** 초기 필수, 대상 선정 검증 대기. **연결:** FR-EXPORT-02/03.

- 외부 프로그램·버전·형식 조합을 대상 프로필로 관리한다.
- 프로필에는 필수 구조, 지원 매개변수·표정, 파일 묶음 규칙, 텍스처·이름 제한, 변환기 버전, 검증 상태를 포함한다.
- 실제 검증 대상과 실험·미지원 대상을 구분한다. 초기에는 최소 하나의 검증 대상이 필요하다.
- 대상 선택 시 이전 사용 설정을 불러오되 현재 프로젝트에 다시 검사한다.
- 선택한 대상이 저장 프로젝트와 다른 기능을 표현한다는 점을 이해하기 쉽게 설명한다.
- **완료 기준:** 대상과 버전을 명확히 선택하고 그 대상에 필요한 검사·변환 규칙을 적용한다.

### F-EXP-003. 호환성 검사·경고·수정 이동

**범위:** 초기 필수. **연결:** FR-EXPORT-03, AC-12.

| 판정 | 의미 | 다음 행동 |
|---|---|---|
| PASS | 현재 검사 항목을 충족 | 내보내기 가능. 외부 실제 구동 검증과는 별개 |
| WARNING | 파일 생성은 가능하지만 손실·대체·제한 존재 | 영향과 대체 결과를 확인한 뒤 진행 |
| BLOCKED | 대상 필수 조건 미충족 | 관련 부위·설정 수정 또는 대상 변경 |
| STALE | 검사 후 프로젝트·대상 조건 변경 | 최신 상태로 재검사 |

- 검사 항목은 리소스 존재, 참조 무결성, 필수 역할, 매개변수 범위, 표정 지원, 텍스처·이름·파일 구조 제한 등 대상 프로필에서 정한다.
- 결과마다 문제 ID, 영향 부위, 원인, 손실 내용, 자동 보정 가능 여부, 수정 화면을 제공한다.
- 자동 변환·축소·이름 정규화는 변환 사본에 적용하고 원본 프로젝트를 조용히 바꾸지 않는다.
- 경고 확인은 프로젝트 리비전·대상·경고 집합에 연결한다. 결과가 바뀌면 과거 확인을 무조건 재사용하지 않는다.
- 내보내기 시작 시 검사 입력과 현재 입력이 같은지 확인한다.
- **완료 기준:** 필수 누락은 차단하고 표현 손실은 설명한다. 검사 뒤 파츠를 바꾼 경우 과거 통과 결과로 바로 내보내지 않는다.

### F-EXP-004. 파일 변환·리소스 묶음·저장

**범위:** 초기 필수. **연결:** FR-EXPORT-02/03, AC-11.

1. 대상 프로필과 확정한 프로젝트 리비전을 작업 입력본으로 고정한다.
2. 해당 대상이 표현할 수 있는 부위·변형·매개변수·표정으로 변환한다.
3. 필요한 텍스처·설정·부속 파일을 임시 위치에 생성한다.
4. 파일 구조와 리소스 참조를 검사한다. 내부 구조 검사만으로 외부 구동 검증을 대체하지 않는다.
5. 결과를 지정 위치에 확정한다. 기존 결과 교체 시 교체 범위와 파일을 명확하게 한다.
6. 기준 리비전, 대상·변환기 버전, 생성 파일 목록, 경고, 완료 시각을 보고한다.

- **취소:** 불완전한 출력과 임시 리소스를 정리하고 기존 정상 결과를 유지한다.
- **경로:** 프로젝트 원본과 충돌하는 위치를 감지한다. 대상 폴더에 있는 무관한 파일을 내보내기 정리 대상으로 삼지 않는다.
- **편집 중:** 내보내기 입력본과 더 최신 작업본을 구분하고 재내보내기 필요 상태를 표시한다.
- **완료 기준:** 출력 폴더만 옮겨도 필요한 리소스가 함께 있으며 검증 대상이 직접 읽을 수 있는 결과가 생성된다.

### F-EXP-005. 외부 구동 확인·재내보내기

**범위:** 초기 필수. **연결:** FR-EXPORT-02/03, PD-11/12.

- 결과 화면에서 저장 위치, 파일 구성, 대상 프로그램 가져오기 방법, 알려진 제한을 제공한다.
- `파일 생성 완료`와 `외부 구동 확인`을 구분한다. 후자는 외형·텍스처·핵심 움직임·표정을 대상에서 실제 시험한다.
- 확인 시 대상 프로그램·버전, 결과물 버전, 확인 방식과 시각을 기록한다. 사용자 확인을 자동 시험 결과처럼 표시하지 않는다.
- 외부 구동 실패는 파일 생성 실패와 구분하고 누락 파일·지원 버전·변환 제한 점검을 안내한다.
- 프로젝트 변경 후 같은 대상에 다시 내보낼 때 이전 설정을 재사용하고 호환성은 재검사한다.
- 이전 외부 확인은 새 결과물의 확인으로 승계하지 않는다. 이전 기록은 남기고 최신 확인 상태를 새로 표시한다.
- **독립성:** 내보낸 캐릭터의 사용에 우리 앱의 실행·카메라 연결을 필수로 요구하지 않는다. 대상 프로그램 자체의 입력·설정은 별개다.
- **완료 기준:** 대상에서 직접 로드·구동하고, 프로젝트 수정 후 재내보낸 최신 결과도 구분해 확인할 수 있다.

## 16. 환경 설정·성능·자산 정보

### F-SET-001. 장치·저장·개인정보 설정

**범위:** 초기 필수. **연결:** NFR-UX-04, NFR-DATA-01, PRD 18.4절.

- 프로젝트 설정과 기기·사용자 환경 설정을 분리한다. 기본 장치, 저장 위치, 자동 저장 정책, 단축키 등록 상태를 관리한다.
- 카메라·마이크의 현재 사용 여부를 표시하고 사용 중지·장치 해제를 제공한다.
- 기본 카메라 영상·음성 저장과 학습 활용은 하지 않는 방향을 따른다. 별도 기능이 필요하면 목적·범위·동의부터 설계한다.
- 서버 전송이 필요한 기능은 대상 데이터·처리 위치·보관·삭제 방식을 설명하고 로컬 기능과 구분한다.
- 진단 전송·모델 학습 활용 동의는 장치 접근 동의와 구분한다. 하나를 허용했다고 나머지를 허용한 것으로 해석하지 않는다.
- 개발 중에는 완전한 오프라인 실행이나 로그인 불필요를 검증 없이 약속하지 않는다. 필수 네트워크·계정 여부는 별도 결정한다.
- **완료 기준:** 어떤 장치·데이터를 쓰는지 확인·중지하고, 프로젝트 이동 후 과거 기기 설정 때문에 열기를 실패하지 않는다.

### F-SET-002. 성능 상태·품질 조절·진단 기록

**범위:** 초기 필수인 수동 조절·진단, 자동 조절은 초기 검토. **연결:** FR-BROAD-03, PRD 18.2절.

- 프레임·처리 지연·사용 자원 등 실제 측정 가능한 지표만 표시한다. 측정 구간과 추정 여부를 구분한다.
- 출력 크기, 프레임, 보조 효과 등 검증한 품질 옵션을 제공한다. 장비·캐릭터·방송 동시 실행 조건에서 영향을 측정한다.
- 품질을 바꾸어도 원본 텍스처와 편집 프로젝트는 보존한다.
- 자동 조절을 제공하면 조건, 조절 대상, 현재 적용값, 사용 중지·복원 경로를 정의한다.
- 진단 기록에는 앱·구성요소 버전, 작업·상태, 민감 정보 없는 오류 재현 자료를 우선 포함한다.
- 진단 파일 내보내기 전 포함 항목을 알리고 원본 그림·음성·카메라 프레임·개인 경로를 기본 포함하지 않는다.
- **완료 기준:** 높은 부하에서 지원하는 품질 조절로 대응하고, 데이터가 보존된 진단 자료를 만들 수 있다.

### F-SET-003. 지원 범위·버전·자산 출처

**범위:** 초기 필수. **연결:** NFR-COMPAT-01/02, FR-PART-01.

- 앱·프로젝트 구조·추적·분석·변환 구성요소 버전을 필요한 범위로 표시한다.
- 지원 입력, 기준 장비, 방송 연결, 외부 내보내기 대상과 검증 버전을 확인할 수 있게 한다.
- 제공 파츠·사용 자산의 제작자·출처·사용 조건을 프로젝트와 연결한다.
- 사용자 파일을 가져올 때 사용 권한을 확인하도록 안내하되 프로그램이 권리를 자동 보증한다고 표시하지 않는다.
- 종속 요소 변경 후 영향받는 기능과 호환 회귀 검증 대상을 관리한다.
- **완료 기준:** 현재 프로젝트·결과물의 사용 자산과 검증된 환경을 식별하고 문제 재현에 필요한 버전을 확인한다.

## 17. 필수 장기 확장: 그림 기반 3D

이 절은 후속 기능의 사용자 접점과 데이터 경계를 정의한다. 3D 복원 모델·모델링 엔진·리그 생성 방식·구체 지원 형식은 별도 연구 단계에서 정한다. 평면 그림에 고개 변형을 적용하는 것과 입체 캐릭터 제작을 구분한다.

### F-3D-001. 참고 그림·기존 캐릭터 입력과 입체 제작

**범위:** 장기 필수. **연결:** FR-3D-01/02/07/08.

- 한 장 또는 복수의 참고 그림과 기존 캐릭터 외형 정보를 활용한다. 실제 허용 입력과 추가 자료의 필요 여부는 검증한다.
- 기존 프로젝트에서 시작하면 원본 2D와 연결된 별도 파생 결과를 만든다. 2D 편집 구조를 3D 결과로 덮어쓰지 않는다.
- 보이는 영역과 추정해야 하는 깊이·옆면·뒷면을 구분한다.
- 처리 단계, 자원 요구, 취소·재시도와 실패 범위를 안내한다.
- 입체 형상·재질·움직임 준비 상태를 각각 기록한다. 형상만 생성되었다고 방송 준비 완료로 표시하지 않는다.
- **완료 기준:** 입력에서 입체 후보를 만들고 원본 2D를 보존하며 미완성·실패·보완 필요 영역을 식별한다.

### F-3D-002. 다각도 검토와 쉬운 형태 보정

**범위:** 장기 필수. **연결:** FR-3D-02/03/04/08.

- 정면·측면·후면을 확인하고 원화 인상과 다른 부분을 비교한다.
- 초보자는 주요 형태·비율·색상 등 결과 중심 조작으로 수정할 수 있어야 한다.
- 추정 영역의 선택·보정, 기본값 복원, 변경 전후 비교를 제공한다.
- 표정과 고개·몸 움직임에서 변형 품질을 확인하고 필요한 영역을 다시 보정한다.
- 수정이 3D 움직임 구조나 텍스처를 무효화하면 해당 부분만 다시 준비한다.
- **완료 기준:** 전문 모델링 도구를 먼저 배우지 않고 기본 외형을 수정하며 정면뿐 아니라 측면·표정 상태도 확인한다.

### F-3D-003. 3D 실행·방송·외부 내보내기

**범위:** 장기 필수. **연결:** FR-3D-05/06/07.

- 3D용 움직임 구조·표정을 추적 입력에 연결한다. 공통 장치 화면과 실행 조작은 가능한 범위에서 재사용한다.
- 카메라 입력 실패·표정 충돌·기본 자세 복귀 등 공통 운영 규칙을 적용한다.
- 3D 렌더링 결과의 투명 배경과 실제 방송 프로그램 연결을 별도로 검증한다.
- 외부 3D 대상·버전을 선정하고 형상·텍스처·리그·표정의 호환 검사와 변환을 제공한다.
- 2D와 3D 내보내기 프로필을 구분한다. 같은 대상에서 둘 다 지원한다고 추정하지 않는다.
- **완료 기준:** 앱에서 3D 캐릭터를 실행해 방송 화면에 표시하고, 선정한 외부 3D 대상에서 독립적으로 구동한다.

## 18. 필수 장기 확장: 자체 모델 글 기반 생성

### F-GEN-001. 설명 입력과 결과 선택

**범위:** 장기 필수, 구체 생성 UX는 후속 설계. **연결:** FR-GEN-01/02/04.

- 사용자는 원하는 외형을 자연어로 설명하고 결과를 검토한다. 초기 입력 항목·결과 개수·지원 언어는 미정이다.
- 생성 요청과 결과의 관계를 유지하고 설명을 바꿔 다시 시도해도 선택했던 결과를 잃지 않는다.
- 선택 결과와 원래 설명, 생성 시점, 모델 버전을 필요한 범위로 기록한다.
- 결과 채택 후 공통 외형 편집에 들어갈 수 있고, 생성 결과를 그대로 확정하도록 강제하지 않는다.
- **완료 기준:** 설명 입력·결과 검토·선택·수정 흐름이 이어지고 사용자가 선택한 결과를 프로젝트에서 재확인한다.

### F-GEN-002. 자체 모델 처리·상태·데이터 통제

**범위:** 장기 필수, 모델 상세 설계 보류. **연결:** PD-07, FR-GEN-04/06/07/08.

- 자체 모델을 제작·연결하는 제품 방향을 따른다. 외부 생성 API를 호출하는 구현을 이 기능의 완료로 처리하지 않는다.
- 자체 개발 범위, 기반 모델 활용 여부, 데이터 권한, 학습·추론 장비와 비용은 별도 검증·결정 항목으로 유지한다.
- 로컬 또는 자체 운영 서버에서 실행하는 경우 필요한 환경, 데이터 이동, 대기·처리·실패·취소 상태를 제공한다.
- 대기 시간과 처리 제한은 실제 운영 조건에 맞게 설정한다. 재시도와 모델 버전 변경을 기록한다.
- 사용자 원본·설명·결과를 학습에 쓰려면 추론 처리와 구분한 정책·명시적 동의·권한 검토가 필요하다.
- **완료 기준:** 확정된 자체 모델 정의를 충족하고 작업·실패·취소가 처리되며 데이터 이동과 학습 활용을 사용자가 이해한다.

### F-GEN-003. 생성 결과를 캐릭터 제작으로 연결

**범위:** 장기 필수. **연결:** FR-GEN-02/03/05.

- 결과 유형을 정적 이미지, 분리된 부위, 기타 구조화 결과 등 실제 제공 유형에 맞게 구분한다.
- 정적 이미지는 한 장 그림 제작 경로로, 분리된 구조는 해당 입력 경로로 합류하는 방식을 우선 검토한다.
- 생성된 외형과 자동 움직임 준비의 완료 상태를 분리한다. 그림 생성 성공만으로 리깅·추적·방송 사용 완료를 표시하지 않는다.
- 사용자는 생성 후에도 외형·표정·움직임을 수정하고 앱 실행·방송·외부 내보내기를 이용한다.
- 생성 과정의 참조 정보는 보존하되 공통 프로젝트가 특정 추론 실행에 영구 의존하지 않도록 설계한다.
- **완료 기준:** 채택 결과가 공통 편집에 합류해 지원 범위의 움직임과 실제 사용 흐름으로 이어진다.

## 19. 논리 데이터 명세

이 절은 저장해야 할 정보와 관계를 정의한다. 05에서 `.2dsketch` v1 ZIP·`project.json`/`manifest.json`·해시 상대 자원·원본/파생 분리와 major/minor 읽기/이전 정책을 채택했다. 07에서 [공통 모델 1.0의 실제 스키마/참조/좌표·파일 검사](./architecture/project-model.md)를 구현했다. 지원되는 이전 버전이 아직 없으므로 임의 자동 이전은 제공하지 않으며 ZIP 저장/복구·UI 연결은 후속 작업이다. 필드 이름은 논리 계약이며 사용자에게 JSON 수기 작성이나 이 구조의 학습을 요구하지 않는다.

| revision / savedRevision | 현재 변화 / 저장된 변화 | 저장 중 추가 편집을 식별 |

| derivedProjects | 3D 등 파생 관계 | 원본 보존, 원본 부재 시에도 가능한 범위 명시 |

| 필드 | 의미 | 규칙 |

| assetId | 리소스 ID | 경로·파일명 변경으로 연결이 끊기지 않도록 사용 |

| colorSpace / alphaMode | 색·알파 해석 | 원본 바이트·straight/sRGB 파생·GPU/INP premultiplied 표현을 구분하고 변환 결과를 원본에 덮어쓰지 않음 |

| origin | 가져오기·기본 제공·자동 보완·수동 수정·생성 | 추정 영역 확인에 활용 |
| version | 파츠·처리 결과 버전 | 재현·호환 검사 |
| attribution / usageInfo | 제작자·출처·이용 정보 | 확인 가능한 정보와 미확인 정보 구분 |

원본 파일의 절대 경로를 공유·진단 데이터에 그대로 포함하지 않는 방향을 따른다. 사용자 기기에서 리소스 재연결에 필요한 정보는 노출 범위를 통제해 저장한다.

| 필드 | 의미 | 규칙 |

### 19.4 Parameter / Binding — 움직임과 입력 연결

| 데이터 | 주요 필드 | 규칙 |
|---|---|---|
| Parameter | ID, 이름, 기본·최소·최대값, 의미, 단위 | 의미가 다른 값을 이름 유사성만으로 합치지 않음 |
| PartBinding | 매개변수 ID, 부위 ID, 변형·표현 규칙 | 삭제·교체 영향 추적 |
| InputBinding | 입력 소스, 입력 항목, 매개변수 ID, 방향·강도·보정·필터 | 기기 입력과 캐릭터 값을 분리 |
| FallbackPolicy | 입력 누락 조건, 대체값·동작, 복귀 방식 | 카메라·마이크 및 부위별 정책 |
| Expression | ID, 이름, 대상값, 고정 항목, 전환·해제 방식 | 표정 해제 후 최신 입력으로 복귀 |
| HotkeyBinding | 동작, 키 조합, 동작 방식, 적용 범위 | OS 등록 상태는 기기별 관리 |

예를 들어 눈 열림을 0~1로 정규화할 수 있지만, 실제 매개변수 단위와 범위는 기술 설계에서 결정한다. 모든 고개 축이나 외부 형식에 동일 수치를 강제로 적용하지 않는다.

### 19.5 Task / Report — 작업과 검증 기록

| 데이터 | 필수 정보 | 규칙 |
|---|---|---|
| ProcessingTask | 작업 ID·유형, 프로젝트 ID, 입력 리비전, 구성 버전, 단계·상태 | 결과 적용 전 대상·리비전 확인 |
| Checkpoint | 대상 리비전, 이유, 시각, 복구 참조 | 사용자 명시적 저장본과 구분 |
| ReadinessReport | 실행 모드, 리비전, 오류·경고 | 특정 실행 조건에 대한 판단 |
| CompatibilityReport | 대상·버전, 리비전, 검사기 버전, 항목별 판정 | 변화 후 STALE 처리 |
| ExportRecord | 대상·변환기 버전, 입력 리비전, 결과 파일 목록, 경고·시각 | 실제 결과물 버전 식별 |
| VerificationRecord | 결과·출력 설정 버전, 수신 대상, 확인 방식·시각·결과 | 사용자 확인 / 자동 확인 구분 |
| DiagnosticRecord | 구성 버전, 작업·상태, 오류·재현 정보 | 민감 리소스 최소 수집 |

보고서에는 전체 요약만 남기지 않고 문제가 있는 부위·매개변수·수정 위치를 연결한다. 과거 보고서는 이력으로 남길 수 있으나 최신 상태의 통과 판정처럼 사용하지 않는다.

### 19.6 좌표·좌우·기본값 규칙

- 원본 픽셀 좌표, 편집용 그림 좌표, 부위 로컬 좌표, 화면 확대 좌표, 방송 출력 좌표를 구분한다.
- 각 좌표 간 변환을 일관되게 유지한다. 화면 확대·출력 해상도 변경이 원본 보정점 자체를 바꾸지 않는다.
- 좌우 역할은 캐릭터 기준으로 저장하고, UI에는 기준을 명시한다. 미러 미리보기는 표시 변환으로 처리한다.
- 초기 부위 위치·파츠 기본값·사용자가 저장한 기본 자세를 구분한다. “기본값” 버튼이 되돌릴 범위를 구체적으로 표시한다.
- 부위·매개변수 이름 변경은 고유 ID 참조를 변경하지 않는다. 삭제 시 관련 참조를 검사한다.

## 20. 작업 동시성·자원·출력 일관성

### 20.1 대표 동시 작업 정책

| 동시 상황 | 제안 정책 | 보호해야 할 상태 |
|---|---|---|
| 분석 중 관련 부위 편집 | 최초에는 잠금 또는 결과 적용 전 충돌 확인 | 최신 사용자 보정 |
| 분석 중 다른 부위 편집 | 안전하게 분리 가능하면 허용 | 입력 리비전과 결과 영향 범위 |
| 내보내기 중 편집 | 고정 입력본으로 변환 계속, 최신 편집 별도 유지 | 결과물 기준 리비전 |
| 저장 중 편집 | 저장 시작본 확정, 이후 변경은 미저장 유지 | savedRevision의 정확성 |
| 실행 중 구조 편집 | 작업본만 변경, 검증된 반영 시점에 실행본 교체 | 정상 방송 출력 |
| 실행 중 내보내기 | 자원이 허용하면 고정본으로 수행 | 실행 프레임과 장치 접근 |
| 실행 중 무거운 분석 | 높은 부하 경고·보류 선택, 초기에는 제한 가능 | 방송 안정성 |
| 장치 변경 중 출력 | 대체 동작 유지 후 새 입력 연결 | 영상 소스의 안전한 상태 |
| 앱 종료 중 파일 확정 | 손상 위험 없는 경계까지 완료 후 종료 | 마지막 정상 파일 |

지원하지 못하는 동시 작업은 명시적으로 비활성화하고 이유와 대안을 알려준다. 임의로 실패한 것처럼 보이게 하지 않는다. 동시 작업을 지원한다고 선언하기 전에 기준 장비에서 방송 동시 실행을 검증한다.

### 20.2 자원 해제와 중복 방지

- 카메라·마이크·출력·작업별 자원의 소유와 해제 시점을 정한다.
- 연결·시작 버튼 연타가 같은 장치를 중복 열지 않게 한다.
- 실행 종료·장치 변경·프로젝트 전환·취소 후 불필요한 작업과 자원이 남지 않게 한다.
- 미리보기와 방송용 영상은 같은 유효 실행 상태를 사용하되 렌더링 해상도·표시 UI는 분리한다.
- 프레임 처리 지연이 누적될 경우 오래된 입력을 계속 재생해 지연을 늘리지 않는 정책을 검토한다.
- 작업 중 임시 리소스는 정해진 범위에서만 관리하고 원본·무관한 사용자 파일을 정리하지 않는다.

### 20.3 파일 확정과 검증 경계

저장·이미지·아바타 내보내기는 임시 생성 → 내용·참조 확인 → 결과 확정 → 완료 표시의 순서를 따른다. 파일이 생성되었다고 읽기 검증이나 외부 구동이 완료된 것으로 표시하지 않는다. 파일 묶음 교체의 실패 복구 방식은 대상 파일 시스템에서 검증한다.

### 20.4 05에서 채택한 실행·작업 경계

`SceneSnapshot`은 project/revision·renderer/schema·asset hash·망/상태/곡선의 완성된 불변 묶음이고, `ParameterFrame`은 source/sequence/monotonic time·다섯 정규화 값·유효/손실 상태를 갖는다. 입력 경로에 따라 렌더러를 나누지 않고 앱/OBS에서 같은 평가/셰이더 버전을 쓴다. 장치 프레임/PCM·분석 중간 구조를 방송 페이지로 보내지 않는다.

분석/내보내기/저장 결과는 projectId/inputRevision/jobId/취소 세대·프로토콜/처리 버전을 검사한다. 08/T-076~077에서 같은 프로젝트의 stale 준비 결과는 자동 적용을 막고 AWAITING_REVIEW로 보관하도록 구체화했다. cross-project·세대 불일치·취소/중복 결과는 적용하지 않고 정상 편집/실행을 보존한다. 구조 변경은 현재 실행을 유지하며 준비 후 명시 적용, 시각 변경은 준비된 스냅샷을 프레임 경계에서 교체한다. 내보내기는 시작 리비전을 고정하고 이후 편집으로 완료 결과의 리비전을 바꾸지 않는다. 이전 05 정책/실험은 당시 기록으로 보존한다.

Electron main이 파일/worker/출력 권한을 소유하고 renderer는 제한된 preload API만 사용한다. Python worker와는 버전/길이/스키마 검사가 있는 프로세스 메시지로 통신한다. 31개 정책 모델 검사는 실제 제품 IPC/저장·단축키 통합 시험을 대신하지 않는다. 구현/기능 완료는 [M0 환류](./planning/05-m0-review.md)와 아래 기능 검증을 거친다.

## 21. 오류·경고 명세

### 21.1 알림 구조

모든 알림은 논리 코드, 심각도, 요약, 영향 범위, 현재 보존 상태, 재시도 가능 여부, 권장 행동을 갖는 방향으로 설계한다. 사용자 화면은 쉬운 한국어를 우선하고 상세 진단 코드는 확장 정보로 제공한다.

| 심각도 | 의미 | UI 행동 |
|---|---|---|
| INFO | 현재 작업·상태 안내 | 작업을 가리지 않는 상태 표시 |
| WARNING | 제한·손실 또는 복구 가능한 문제 | 영향 설명, 계속 가능한 조건 표시 |
| BLOCKING | 현재 요청의 필수 조건 미충족 | 해당 작업만 차단, 수정 경로 제공 |
| FATAL_FOR_SESSION | 현재 실행·작업을 안전하게 유지할 수 없음 | 안전하게 중지, 저장·복구 가능 범위 안내 |

### 22.1 초기 출시 차단 조건

- 파츠 조합·한 장 그림·분리 그림의 세 초기 입력 경로 중 하나라도 정의한 지원 범위에서 공통 편집·저장·재개·실행·방송·외부 내보내기로 이어지지 않음.
- 지원 그림에서 첫 움직임을 얻기 위해 전문 리깅 작업을 필수로 요구함.
- 실제 방송 프로그램에서 투명 배경·움직임을 검증하지 못함.
- 외부 아바타 대상에서 독립 구동 가능한 내보내기를 제공하지 못함.
- 원본·마지막 정상 저장본의 손실, 다른 프로젝트로 분석 결과 오적용 등 중대한 데이터 오류가 남아 있음.
- 방송 출력에 카메라 원본·편집 UI·개인정보가 의도치 않게 노출됨.
- 확정한 기준 장비·연속 실행·기능 기준을 충족하지 못함.

목표 수치와 샘플 수는 PRD의 검증 전 제안을 바탕으로 별도 확정한다. 지원 밖 입력도 최소한 실패 이유·대안을 안내하는지 검증한다.

### 24.3 06단계 기반과 기능 완료의 경계

실제 `apps/desktop`, `apps/renderer`, `worker`와 `packages`에 제품 개발 기반을 구성했다. [모듈/포트 규약](./architecture/foundation.md)은 입력·분석·편집·움직임·실행·출력·변환의 책임과 버전/ID/리비전·취소 결과 검사를 정의한다. 현재 포트 중 기능 구현이 없는 항목은 계약만 존재한다. 공유 WebGL2의 고급 샘플 표시와 실제 INP 구조 검사, worker 시작/모델 로드/종료는 확인했지만 완성된 리깅·추적·OBS 전달·제품 내보내기는 아니다.

개발/시험/release 프로필, TypeScript/Ruff·8개 Node/3개 Python 검사 그룹, 민감 원문을 제외하는 공통 로그와 새 개발 설치 재현을 확인했다. release는 개발 배지와 DevTools를 노출하지 않으며 준비 중 제작 버튼은 비활성이다. 사용자 합의에 따라 같은 PC의 한글/공백 경로·개발 도구 PATH 제거·빈 프로필에서 번들 EXE를 두 번 실행했다. 새 Windows·호스팅 CI 실행·장치/실제 프로젝트 통합은 미검증이다. [06 완료 근거](./planning/06-foundation.md)와 [패키지 감사](../evidence/phase06/package-audit.json)를 따른다. T-061 이후 기능과 M0-R01~05는 완료로 변경하지 않는다.

### 24.4 07단계 공통 모델과 연결 범위

Project/Asset/CharacterPart/Parameter/Binding/Expression 및 runtime/broadcast/export·기기 설정의 실제 타입/스키마를 구현했다. 리비전·출처 DAG·캐릭터 좌우·부모/그룹·동일 순서의 ID 기준·상태/변환 범위·입력 보정/대체를 검사한다. `coordinates`는 원본/편집/부위 로컬/프로젝트/화면/출력 사이를 변환하고 preview adapter는 실제 GPU 배치와 crop에 같은 행렬을 사용한다. `project-io`는 호스트 전용으로 파일/해시/내용 변경·이동·같은 내용 재연결을 제공한다.

새 minor는 원문/미지 필드를 보존하는 읽기 전용, 새 major는 차단한다. 프로젝트 안 기기 식별자는 거부하고 별도 MachineSettings에 둔다. 이전 준비 결과 세 개와 고급 샘플을 모델 1.0으로 구성해 25개 검사 그룹·400개 affine 왕복·실제 GPU 이동/자르기·동일 PC release 실행을 확인했다. [07 근거](./planning/07-common-model.md)를 따른다. 이 단계는 후속 생성/재연결 UI·안전 저장/복구·비동기 상태·전체 변형/추적/방송/외부 호환 완료를 대신하지 않으며 M0 HOLD를 유지한다.

### 24.5 08단계 작업/변경 제어 구현 상태

[Workflow](../packages/workflow/index.ts)는 상태 축·행동 조건, 요청 시점 불변 입력·식별자/처리 버전, 큐/실제 단계 진행·취소 요청/정리/완료·순수 단계 재시도를 구현한다. Transaction은 ID/필드 단위 before/current/after 비교와 리비전 CAS·전체 참조 재검증으로 최신 보정을 보호한다. 보류 결과는 안전한 항목의 선택 적용·재검증·폐기·최신 입력 재실행을 제공하고 적용 전 메모리 체크포인트를 보관한다.

의존 세대로 영향받은 결과만 stale/재검사하며, 검증된 실행 스냅샷은 명시적 프레임 경계에서 교체한다. 전환/종료는 세대를 회수한 뒤 자식 프로세스와 소유 임시 파일 정리를 기다린다. 고정 입력과 실제 앱 UI·프로세스/파일 소유권을 포함한 45개 검사 그룹 및 release 시험 버튼 비노출을 [08 근거](./planning/08-async-workflow.md)에 기록했다. 모의 저장/내보내기 receipt·메모리 체크포인트를 실제 파일 저장·영구 복구로 해석하지 않는다. 실제 분석/저장 통합 검사는 T-268/271, 생성/저장 UI는 T-081 이후로 남기고 M0 HOLD를 유지한다.

## 25. 기능 구현 완료 판정과 변경 관리

개별 기능은 화면에 버튼이 나타나는 것으로 완료되지 않는다. 해당 기능의 정상 처리, 입력 검증, 예외·취소·복구, 데이터 보존, 다른 기능에 미치는 영향과 완료 기준을 확인해야 한다. 외부 의존 기능은 검증 대상·버전과 증거를 함께 기록한다.

기능 작업에는 상세 기능 ID, 연결 PRD ID, 현재 상태, 실제 지원 범위, 미지원 항목, 검증 결과를 남긴다. 구현 상태는 `미착수 / 기술 검증 / 구현 중 / 검증 중 / 완료 / 제한 있음` 등으로 관리할 수 있다. 이 문서는 전체 제품 기능의 설계 기준이며, 03~04 시제품의 제한된 기술 검증과 실제 외부 사용 증거를 별도로 연결했다. 시제품 통과만으로 제품용 기능 전체를 완료 처리하지 않는다.

PRD의 확정 방향을 변경해야 한다면 기능 명세만 조용히 축소하지 않는다. 변경 이유와 실제 사용자 흐름에 미치는 영향을 정리하고 PRD와 함께 갱신한다. 세부 동작만 조정할 때는 관련 기능·데이터·검증 항목·대응표를 함께 고친다.
