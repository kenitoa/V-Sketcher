# 이미지 저장·대상 사전검사 계약

앱 0.19.0 · 프로젝트 1.9 · [사용법/검증 범위](../planning/24-file-output.md).

메인의 FileOutputs가 원래 앱 main frame만 허용하는 PNG/사전검사 IPC를 소유한다. ProjectSession.captureFileInput은 작업본 또는 공개 완료된 실행본을 ID/리비전/지문으로 확인하고 프로젝트 사본과 해시 검증 자산을 고정한다. 저장·연속 편집·활성 작업은 경계에서 거부한다. 읽기 후에도 같은 입력인지 확인한다. 누락 자산은 사전검사의 식별 가능한 차단 항목이 되며 PNG에 필요한 자산 누락은 렌더 시작 전에 차단한다.

ImageExportService는 요청 UUID·세대·AbortController와 자산 grant를 소유한다. 한 번에 이미지 티켓 하나만 유지하고 오래된 release/완료는 새 티켓을 회수하지 못한다. 전용 image-export.html은 preload/Node 없이 sandbox/contextIsolation/webSecurity와 외부 네트워크 차단을 유지한 숨은 창에서 공통 AvatarRenderer로 그린다. 별도 sRGB 2D canvas에 투명 또는 지정 배경을 합성하고 PNG를 인코딩한다. 그래픽 오류/중지는 창·컨텍스트를 정리하고 유효 티켓을 만들지 않는다. 이미지에는 UI/체크무늬/카메라 원본을 그리지 않는다.

미리보기 URL은 메인이 가진 PNG 바이트를 제공한다. 저장은 티켓 ID로 같은 바이트를 사용하며 입력 지문을 파일 선택 전후에 확인한다. 준비/쓰기 중지와 변경 세대는 늦은 결과를 무효화한다. writePNG는 기존 프로젝트 저장의 잠금/죽은 PID 회수 규약을 재사용하고, PNG 헤더·다시 읽은 SHA-256·대상 해시·취소 경계를 검사한 뒤 원자적 rename으로 확정한다. 실패에 이전 파일을 삭제하는 fallback을 사용하지 않는다. 정상 IPC/로그에는 개인 경로·원시 오류 문자열을 넣지 않고 저장 결과에는 선택 파일명/바이트/SHA/기준본만 반환한다.

CompatibilityService는 같은 입력 캡처를 사용하되 이미지 생성과 독립이다. 대상 프로필/옵션·검사/변환 버전과 입력 지문을 함께 해시한다. 구조·자원·제어/표정·어댑터 제한과 변환 가능성을 판정하고, 사본의 정수 ID·이름·중심 좌표·z·원본 관계/표시/연결·표정 정책·텍스처 인코딩 규약을 별도 자료로 만든다. 원본 프로젝트/자산을 수정하지 않는다. 결합 변형/보간/색상/범위 등 검증되지 않은 핵심 표현은 차단한다. 사본/사전검사는 실제 INP 직렬화나 대상 구동을 대체하지 않는다.

검사 verify/acknowledge는 현재 입력뿐 아니라 요청의 예상 옵션도 비교한다. WARNING 확인은 검사 ID/내용 서명/경고 집합에 묶고 BLOCKED 확인은 거부한다. 새 검사·다른 옵션·리비전/대상/검사 버전은 예전 결과를 사용할 수 없다. 프로젝트별 설정은 기존 exportProfiles 필드에 새 리비전으로 기록하고 일반 저장/복구/되돌리기 규약을 따른다.

이미지와 검사 grant는 서로 다른 네임스페이스이며 임의 파일 경로를 받지 않는다. 완료/취소/대화상자 종료/앱 종료에 자기 자산과 GPU를 정리한다. 실행 중 큰 이미지/파일 입력은 한도와 중지 대안을 안내하며 프로젝트 실행·방송/장치 자원의 소유권을 회수하지 않는다.

검증 도구는 scripts/verify-file-output.mjs, file-output-package-check.mjs, file-output-pixels.py, file-output-audit.py다. 실제 PNG를 별도 디코드하고 정상·정적·실행 고정 입력 및 세 경로의 사전검사/설정 왕복/오래됨/경고 확인을 시험한다. 과거 evidence/experiments는 동결하며 재현은 별도 작업공간과 새 출력 폴더를 사용한다. 실제 외부 파일/대상 구동·T-190/T-209·M0 HOLD는 유지한다.
