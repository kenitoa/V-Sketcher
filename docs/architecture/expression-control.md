# 표정·입력 제어 계약 — 모델 1.8 / 앱 0.13.0

2026-11-17. [DEC-05/12](../planning/05-decisions.md), F-MOT-002~004, F-RUN-004의 장치 연결 전 구현이다. 실제 장치의 검출·보정·매핑은 19~20단계에서 이 계약으로 합류한다.

## 저장과 실행

`Project.expressions`에 이름, 선택한 매개변수/값/고정 여부, 확인한 대상 부위 ID(`partIds`), 전환/해제 시간과 해제 방식을 저장한다. `expressionSettings`에는 입의 우선 입력·대체 허용·자동 깜빡임·앱 안 단축키 슬롯을 저장한다. 장치 식별자·영상·음성·활성 표정·현재 입력·시각·소유자·전환 진행률은 여기에 넣지 않는다.

`expression-edit`는 엄격한 입력 검사 → 세션/리비전 확인 → 복구 지점 → 재확인 → 기존 편집 트랜잭션 순서다. 저장/복제/삭제/수선/정책 변경은 undo/redo·프로젝트 복사·ZIP 왕복에 포함된다. 숫자의 범위 밖 값·중복 매개변수·빈 저장 범위·알 수 없는 단축키 표정·위조한 대상 ID는 적용하지 않는다. 생성은 최대 64개, 표정당 최대 128개 값이다.

편집 초깃값은 저장된 정의 또는 매개변수 중립값이다. 입력은 미리보기만 바꾼다. **선택한 항목의 현재 값 가져오기**는 체크한 범위만 명시적으로 복사하며, 다시 **저장**해야 영속화된다. 정책을 바꾸어도 작성 중인 표정 초안은 유지한다. 새 표정 버튼은 초안을 초기화한다.

## 소유권과 최종값

각 매개변수에서 독립적으로 아래 순서로 하나의 값을 결정한다. 마지막에는 항상 유한값·최소/최대 안전 제한을 적용한다.

| 높은 순서 | 소유자 | 범위/조건 |
|---|---|---|
| 1 | 편집 시험 | 슬라이더로 실제 선택한 제어 또는 재생 중인 제어만 |
| 2 | 수동 표정 고정 | 활성 표정의 체크한 고정 값만 |
| 3 | 선택된 실시간 입력 | 유효한 카메라 입력, 입은 선택된 카메라/마이크 정책 |
| 4 | 자동 깜빡임 | 켠 경우, 연결된 눈에 4초 주기/160ms 닫힘 구간, 위 소유자 없음 |
| 5 | 고정하지 않은 표정 | 다른 입력이 없을 때 사용하는 표정 기본값 |
| 6 | 기본 자세 | 저장된 기본 자세 또는 매개변수 중립값 |

고정은 부위를 움직이는 매개변수에 적용한다. 여러 부위에 연결된 하나의 매개변수는 그 연결 전체를 제어한다. 한 눈만 고정하려면 그 눈의 독립 매개변수만 선택한다. 표현에 사용한 실제 대상 부위는 저장 시 기록한다. 미연결 이름만으로 동작 지원을 주장하지 않는다.

중립 유지 해제는 이전 표정의 대상 매개변수만 중립으로 유지한다. 해당 범위에서 실시간·자동·고정하지 않은 기본값보다 우선하며 시험 입력은 계속 우선한다. **입력 다시 받기** 또는 다른 표정 적용으로 유지가 끝난다. 중립 유지는 실행 상태라 저장되지 않는다.

## 입 입력과 유효성

입은 **카메라 우선** 또는 **마이크 우선**을 명시적으로 고른다. 가중 합산하지 않는다. 우선 입력의 값이 없거나 패킷이 300ms보다 오래되었을 때만, 대체를 켰다면 반대 입력의 유효한 입 값 하나를 사용한다. 둘 다 없으면 자동/표정 기본값/기본 자세 규칙을 따른다. 대체를 끄면 우선 입력 이외는 사용하지 않는다. 마이크는 입 이외를 소유하지 않는다.

입력 API는 이미 매개변수 단위로 매핑된 값·단조 증가 순번·측정 시각만 받는다. NaN/무한대·알 수 없는/지원하지 않는 ID는 버린다. 순번/시각이 역행하거나 너무 오래된 패킷은 거부한다. 일부만 유효하면 그 패킷의 유효 항목만 대체하며, 누락 값을 이전 패킷에서 몰래 이어받지 않는다. 미래 시각의 패킷은 그 시각 전까지 유효하지 않다. 잘못된 패킷으로 마지막 정상 값의 수명을 늘리지 않는다. 이 단계의 고정 300ms는 장치 지연·평활화·성능 승인 근거가 아니다.

## 전환과 복귀

활성 수동 표정은 하나다. 전환과 해제는 각각 **0ms 즉시, 1~3000ms smoothstep**이다. 레거시 표정의 10000ms 필드는 읽되 실행/새 편집에서는 3000ms로 제한한다. 프레임 수가 아닌 단조 증가 시간으로 진행하고 종료 시 목표에 정확히 도달한다. 이전 시각은 진행을 되감지 않는다.

다른 표정으로 전환하면 현재 계산 결과에서 시작해 새 표정 범위와 이전 범위를 함께 잇는다. 이전 범위는 최신 하위 입력으로 돌아간다. `live-input` 해제도 **매 프레임 최신 하위 입력을 다시 계산**한다. 표정을 켰던 시점의 추적 스냅샷을 복원하지 않는다. 편집 시험은 전환 중에도 최상위다. 적용 중인 표정을 수정/삭제하면 현재 결과에서 저장된 전환/해제 시간으로 새 정의/하위 입력을 잇는다.

문서/세션을 바꾸면 입력·활성 표정·중립 유지·전환·합성 입력을 초기화한다. 같은 문서에서 화면만 바꾸거나 시험을 중지하면 표정과 입력은 유지한다. 미리보기 추가 화면은 주 편집기의 계산 결과만 관찰하므로 시간을 두 번 진행하지 않는다.

## 참조 손상과 수선

`partIds`는 추가 연결이 아니라 마지막으로 검토한 대상 집합이다. 삭제된 ID도 수선 근거로 보관하므로 존재 여부를 프로젝트 스키마 오류로 만들지 않는다. 연결된 부위가 없으면 `unbound`, 현재 대상 집합이 달라지면 `changed`다. 손상된 값만 실행에서 제외하고 나머지 값/다른 표정은 유지한다. 전부 손상되면 적용 버튼을 막는다.

사용자는 현재 부위를 확인해 **현재 부위에 다시 연결**하거나 **이 값 제거**를 선택한다. 손상 정의를 저장하는 동작이 자동 재연결을 겸하지 않는다. 한 장 그림을 교체/재분석할 때 기존 매개변수 ID·표정·정책은 보존하고 새 부위 ID는 재확인을 요구한다. 기존 ID를 유지하는 파츠의 질감 교체는 의미 연결을 유지한다. 연결/계층/대상 부위가 바뀌면 영향을 재평가한다. 매개변수 자체를 임의 삭제한 손상 파일은 기존 엄격한 프로젝트 참조 검사를 통과하지 못한다.

이전 형식에서 대상 기록이 없는 표정은 현재 연결로 평가한다. 한 번 표정 변경을 저장하면 현재 대상을 명시적으로 고정한다. **고급 예제 다시 넣기**는 전체 예제 정의를 바꾸는 기존 명령으로 복구 지점/undo를 제공하며, 이전 정책 슬롯도 초기화한다. 일반 파츠 교체와 구분한다.

## 명령과 범위

`Ctrl+Alt+Shift+1~3`은 저장한 슬롯의 표정, `...+0`은 해제다. 현재 앱의 편집 화면에서만 동작한다. 입력/선택/편집 가능한 텍스트·IME 조합·반복키·모달/inert에서는 실행하지 않는다. OS 전역 키 등록이나 다른 앱으로의 키 전송은 없다. 전역 키와 실제 OBS 초점은 후속 통합에서 별도 검증한다.
