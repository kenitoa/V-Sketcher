# 부위 보정·재분석·선택 적용

공통 모델 1.5의 `structure.corrections`는 최초 자동 보고서와 부위별 보정 값을 저장한다. 눈/입의 선택 캔버스 px 영역·사각형 추가/제외·앞뒤 순서·확인/건너뛰기/차단·가림·재분석 보호를 포함한다. 원본 파일 좌표는 기존 original asset의 `sourceToEdited` 역변환으로 얻으며 EXIF·크기 축소·대상 crop을 무시하지 않는다. 화면 확대/이동은 뷰 상태로만 관리한다.

영역 경계는 원본 좌표의 이진 사각 마스크다. 원래 영역 밖을 추가하면 bounding box를 넓히되 새 box 전체를 움직이지 않고 기존 영역+추가 사각형만 복원한다. 제외 영역은 움직이는 눈/입 패치에서 alpha를 빼고 원화 바탕에 남긴다. 머리카락 가닥을 원화 앞에 보존하는 방법이며 머리 의미 분리/자유 레이어 편집으로 표시하지 않는다. 잘못 겹친 눈/입 영역은 적용 전 차단하고 위치 수정을 안내한다.

`CorrectionSession`은 Workflow `preview` 작업으로 고정 입력·처리 버전 1.1.0·두 단계 준비를 수행한다. 전체/부분 재분석은 얼굴 추론을 전체 선택 그림에서 수행하고, 지정한 부위의 패치만 재생성한다. 보정 보호 항목은 기본 유지하며 덮어쓸 범위를 명시한 경우만 새 자동 후보로 바꾼다. 전체 구조화 버튼으로 보호를 우회하지 못한다.

준비 후보와 현재 프로젝트는 별도다. 비교 뒤 체크한 부위만 적용할 때 입력 리비전/세션/취소 세대를 다시 확인하고 영구 checkpoint를 만든다. 선택한 결과와 현재 미선택 부위를 합친 공통 바탕을 다시 생성해 구멍과 표현이 엇갈리지 않게 한다. 원본/이전 자산은 보존하고 하나의 EditHistory 변경으로 적용한다. 늦은 결과·새 편집·프로젝트 전환·worker 실패·취소는 현재 정상 결과를 덮어쓰지 않는다.

선택 부위의 ID와 유효한 연결을 유지하고 해당 텍스처/기준점/망을 갱신한다. 미선택 부위의 ID·자원·망과 매개변수/표정·입력/감도·기본 자세를 유지한다. 부위 차단으로 고개 제한이 바뀌면 관련 고개 망도 갱신한다. 실제로 바뀐 망의 part ID에 따라 참조/표정/호환/내보내기 검사를 무효화하며 무관한 부위의 개별 검사 결과를 일괄 삭제하지 않는다. 이 상태는 전체 외부 내보내기 검사 완료를 뜻하지 않는다.

자동 결과 복원은 최초 자동 보고서의 해당 부위 또는 전체 범위를 새 후보로 준비한다. 이번 입력 취소는 아직 준비하지 않은 화면 입력만 되돌리고, 후보 폐기는 현재 적용 상태를 유지한다. 이미 적용한 변경은 undo/redo와 복구본으로 돌아간다. 보정/보호/원본 연결·제한은 저장/복제/재열기에 포함된다.

생성 검증기는 CSP를 지키는 정적 JavaScript와 타입 선언/작은 TypeScript export로 분리했다. 확장된 대형 생성 TypeScript가 기존 파일의 문맥 타입 추론 오류를 유발하는 것을 격리 기준본과 비교해 확인했다. strict 검사는 유지하고 생성 원본 일치·런타임 import·실제 앱/패키지 검증을 수행한다. 동적 코드 생성·eval·실행 정책 우회는 사용하지 않는다.

비동기 UI 검사는 프로젝트 화면의 반영된 sequence와 최신 수신 sequence가 일치하고 버튼이 활성화된 것을 확인한 같은 JavaScript 실행 구간에서 조작한다. 이후 새 작업 ID와 비교 상태를 기다려 이전 화면의 이벤트 처리기로 최신 리비전을 잘못 요청하지 않게 한다. 작은 창의 이전 시간 초과 실행은 [실패 기록과 당시 소스·패키지 해시](../../evidence/phase15/runs/20261117-054855-compact-timeout/context.json)로 보존하며 통과 횟수에 포함하지 않는다.

구조화·재분석의 처리 프로세스 제한은 한 번에 120초이며 기존 파일 읽기·대상 선택은 60초를 유지한다. 시간 초과는 `E_INPUT_TIMEOUT`으로 구분하고 자식 프로세스 종료와 임시 자원 정리를 실제 중단 프로세스로 검사한다. 분석과 표정 준비가 연속 실행되는 UI 검사는 두 처리와 자원 저장을 포함해 최대 300초 기다린다. 실제 실패 상태는 즉시 실패로 처리하고 비교 상태·원화 보존·GPU 품질 기준을 유지한다. [이전 65초 대기 실패](../../evidence/phase15/runs/20261117-060600-aggregate-timeout/context.json)는 두 번째 단계가 진행 중인 상태로 보존한다. 이 대기 한도는 M0 성능 통과 기준이 아니다.

사용법·검증·후속 범위는 [15 완료 기록](../planning/15-corrections.md)을 따른다.
