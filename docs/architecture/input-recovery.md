# 마이크·입력 손실·복구 계약

앱 0.15.0, 프로젝트 모델 1.9 유지. F-MOT-005·F-TRK-004, T-191~200. [기존 추적 계약](./camera-tracking.md)·[표정 우선순위](./expression-control.md) 위에 연결한다. T-190 실제 카메라 재검증과 M0 HOLD·5 OPEN은 별개로 남는다.

## 마이크 경로와 개인정보

명시적 연결 버튼 이후 같은 앱 창의 audio 권한만 허용한다. 카메라 권한과 별도 플래그이며 어느 한쪽의 중지가 다른 권한/프로세스를 끄지 않는다. `getUserMedia`는 audio만 요청하고 echoCancellation·noiseSuppression·autoGainControl은 false를 요청한다. 실제 OS/장치가 적용한 처리에 따라 레벨은 달라질 수 있다.

MediaStream → MediaStreamAudioSourceNode → 같은 출처의 AudioWorklet이다. worklet은 약 50ms의 채널별 제곱 평균으로 RMS·peak를 계산한다. 반대 위상 스테레오를 더해서 무음으로 만들지 않는다. 출력 채널은 항상 0이고 스피커에 원음을 재생하지 않는다. renderer에 보내는 것은 RMS·peak·단조 프레임 순번·오디오 시각뿐이다. PCM·음성 파일·대사·원음은 IPC, 프로젝트, 기본 로그에 넣지 않는다. 방송 오디오 송출 기능도 아니다.

첫 콜백에서 현재 AudioContext 시각과 앱 단조 시계를 한 번 대응시킨다. 엔진 준비 지연을 포함하지 않고 현재 엔진 시각을 쓰므로 이미 쌔인 오래된 처리 메시지도 새 입력으로 바꾸지 않는다. 이후에는 기준 시각을 자동으로 재설정하지 않고 150ms를 넘긴 메시지·역행 순번·비정상 숫자/필드는 버린다. module 준비는 5초, resume는 3초 제한이다. 권한 거부·장치 없음·열기 실패·분석 실패·입력 끊김을 정제한 코드와 다음 행동으로 안내한다. OS가 제공하지 않은 점유 원인을 단정하지 않는다. 새 입력이 계속 오는 0레벨은 유효 무음이다. mute된 track의 콜백은 유효 입력으로 세지 않는다.

입력이 1.5초 넘게 오지 않으면 별도 감시가 입력을 중단한다. UI 스케줄러가 500ms 넘게 지연됐으면 쌓인 콜백을 처리할 250ms 유예를 **한 손실 구간에 한 번만** 준다. 반복 지연으로 무한 유예하지 않는다. 카메라도 영상 관찰 지연 후 읽기 실패를 확정하기 전 한 번 다음 관찰을 기다린다. 제어값의 150/300ms 유효 시간은 늘리지 않는다.

## 소음 기준과 감도

초기 바닥값은 0, 추가 여유는 0.005다. 고정 0.015를 보편적인 마이크 기준으로 채택하지 않는다. 사용자가 조용한 구간을 약 2초 제공하면 새 시각의 20개 이상 표본에서 90백분위 RMS를 후보로 만든다. RMS 0.2 초과·5초 내 표본 부족은 실패한다. **새 기준 적용** 전까지 이전 기준을 바꾸지 않고 취소/실패에서도 보존한다. RMS만으로 말소리와 키보드/손뼉을 식별하지 못하므로 잘못된 무음 안내 수행을 자동 판별한다고 주장하지 않는다.

입력 바닥값+추가 여유를 뺀 값에 감도 0.1~10·세기 0~2를 적용하고 0~1로 제한한다. 시간 기반 지수 평활은 0~500ms, 변화율은 초당 8, dt는 최대 100ms다. 사용자가 작성한 입 기본 자세에서 최대값까지 매핑한다. 보완 원화가 있는 입의 실제 카메라/마이크 입력은 기본 자세에서 남은 범위의 65%로 제한해 편집 시험의 보수적 제한을 유지한다. 사용자가 명시한 기본 자세나 고정 표정은 덮어쓰지 않는다. NaN·무한대·역행/범위 밖 RMS는 입력으로 쓰지 않는다. VAD·음소 인식·약한 발화/큰 소음의 보편적 품질 보증은 아니다.

## 우선순위와 손실 전이

공유 ExpressionController에서 입력을 선택한다. 입 카메라/마이크는 합산하지 않는다. 프로젝트에 저장된 우선 모드와 다른 유효 입력 사용 여부를 따른다. 유효 무음도 마이크 소유자이므로 카메라 입으로 임의 전환하지 않는다.

| 입력 상태 | 동작 |
|---|---|
| 카메라 마지막 유효 값부터 300ms 이내 | 짧게 유지 |
| 마이크 마지막 유효 값부터 150ms 이내 | 최신 매핑 사용 |
| 우선 입 입력 만료 | 허용한 다른 유효 입 입력 선택 |
| 유효 대체 없음 | 500ms 동안 현재 기본 동작으로 완화 |
| 새 유효 입력/소유자 복구 | 250ms 동안 최신 입력으로 완화 |
| 고정 표정·편집 시험 | 기존 우선순위로 해당 제어를 덮어씀 |

완화는 고정된 과거 목표가 아니라 매 프레임 최신 입력·기본 자세/자동 깜빡임/비고정 표정을 평가한다. 숨은 실시간 입력은 고정 표정 중에도 갱신하며 표정 해제는 최신 입력으로 돌아간다. 다른 매개변수는 계속 유효 입력을 사용한다. 마지막 큰 마이크 값이나 고개 값을 무한 유지하지 않는다.

ProjectDesk의 공통 표시 시계가 제어를 평가하고 각 미리보기는 스냅샷을 그린다. 원본 비교·텍스처 로딩·다른 미리보기의 중단이 입력 평가 시계를 소유하지 않는다. UI가 정지했다가 돌아오면 절대 시각으로 만료를 반영한다. 최소화/백그라운드 방송의 지속 출력·전체 실행 수명/성능은 후속 실행·방송 단계에서 검증한다.

카메라 대상 소유권의 500ms 관찰 손실·2초 관찰 공백·겹침 재선택 정책은 그대로다. 장치 연결과 얼굴 검출 성공을 구분한다. T-190의 실제 얼굴 검출 미달을 이 입력 엔진의 자동 검사로 해소하지 않는다.

## 재연결과 저장 경계

자동 재연결은 제공하지 않는다. 장치 목록 갱신은 연결 시도가 아니며, 사용자 재선택 후 연결 버튼을 눌러야 한다. 중지는 모든 track·port·node·watchdog를 정리하고 AudioContext 종료를 기다린다. 이전 종료 작업이 진행 중이면 새 연결이 그 완료를 기다린다. 늦은 결과는 세대 토큰으로 버린다. 프로젝트/세션 전환도 장치들을 해제한다. 창 종료 때 renderer와 브라우저가 장치 자원을 해제한다.

PC의 `machine/microphone.json`에 최대 32개 장치 기준/튜닝을 원자적으로 보관한다. 키는 앱의 불투명 장치 ID+실제 sampleRate+계약 버전의 SHA-256이다. 파일에 장치 이름·ID 원문·개인 경로를 넣지 않는다. 손상된 파일은 기본값과 경고로 열되 기존 파일을 조용히 덮어쓰지 않는다. 저장 실패는 현재 정상 기준을 유지한다.

프로젝트에는 기존 입 우선 모드·대체·표정만 저장하며 마이크 장치 기준·튜닝을 넣지 않는다. 따라서 새 프로젝트 스키마를 만들지 않는다. 재연결은 외형·원화·표정 구조를 다시 생성하지 않는다. 기존 프로젝트의 저장·복제·undo/redo 경로를 유지한다.

## 검증 범위

[20단계 기록](../planning/20-input-recovery.md)의 소스 해시·gate·세 경로 자동 UI·같은 PC의 패키지 검사를 함께 본다. 합성 음량의 실제 AudioWorklet·검은 얼굴 입력의 실제 추적기·track ended 이벤트·수신 AudioContext suspend를 이용한 복합 시험은 실제 사람 발화나 USB 분리로 표기하지 않는다. 실제 마이크 레벨 확인도 조용히/말하기/소음 세 구간의 사람 확인과 별개다. M0와 실제 장치 호환성 승인으로 확대하지 않는다.

**26단계 시계 보완 — 2026-11-18:** 고정된 최초 UI/audio epoch는 실행 중 두 시계가 다르게 멈추면 정상 입력도 계속 오래된 것으로 판단할 수 있었다. 매 수신 시 현재 AudioContext 시각과 처리 패킷 시각의 차이를 150ms 신선도 기준으로 검사하고 `performance.now()`로 대응시킨다. 중복 처리 시각·역행 매핑·실제 지연 패킷은 제외하며 AudioContext 중지와 입력 watchdog은 유지한다. 관련 실패·별도 회귀와 최신 전체 검증은 26단계 근거에 구분해 남긴다.
