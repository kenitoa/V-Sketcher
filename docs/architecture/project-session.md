# 프로젝트 파일·편집 세션

`packages/project-storage`는 ZIP 읽기/쓰기, 자원 캐시, 안전 파일 교체와 복구 catalog를 소유한다. `packages/project-session`은 편집 가능한 Workflow·이력·저장 위치·dirty·복구와 이탈 결정을 관리한다. Electron main만 파일 경로와 네이티브 dialog를 취급한다. preload는 제한된 명령·조회·상태 구독만 공개한다.

## 파일 계약

`.2dsketch` 1.0은 `manifest.json`, `project.json`, `resources/<sha256>.png|jpg`를 담는다. manifest에 프로젝트/자원 경로·크기·SHA-256과 스냅샷 종류·리비전·시각이 들어간다. 수동 저장은 해당 입력의 savedRevision을 ACK하고 자동 복구/체크포인트는 ACK하지 않는다. 모델의 원본/파생 관계·표정/바인딩·프로필·출처는 그대로 직렬화한다.

ZIP 중앙 목록을 먼저 검사하고 허용한 엔트리만 크기 한도 내에서 순서대로 읽는다. 중복/대소문자 충돌·경로 탈출·암호화·symlink·미지원 압축·과대 엔트리를 거부한다. CRC32와 manifest SHA-256을 둘 다 확인한다. UTF-8·스키마/참조·자원 해시를 검증하며 임의 폴더에 ZIP을 추출하지 않는다. PNG는 헤더/크기와 해시를, JPEG는 시그니처와 해시를 검사한다. 전체 이미지 디코더의 보안 검증을 대신하지 않는다.

새 minor는 원문을 host에 보존하고 편집/저장을 차단한다. 새 major는 열기를 거부한다. 누락/변조 자원은 부분 열기에서만 허용하고 정상 자원으로 표시 가능한 부위를 유지한다. 재연결은 같은 fingerprint의 바이트만 허용한다. 부족한 묶음이나 복구본은 새 파일로 저장한다.

## 저장 경계

저장 시 프로젝트와 리소스 입력을 고정한다. 같은 폴더의 독점 임시 파일을 write/fsync한 후 다시 열어 검사하고, 기존 정상 파일을 검증된 복구 저장소에 백업한 뒤 rename으로 교체한다. 이전 파일을 먼저 지우는 대체 경로는 없다. 이전/직전 대상 SHA를 대조해 외부 변경을 감지하고 프로세스 내 writer 집합과 PID/nonce 잠금 파일로 중복 writer를 막는다. 종료한 PID의 인식 가능한 잠금만 회수한다. 알 수 없는 잠금은 지우지 않는다.

교체가 성공한 뒤의 부가 기록 실패를 저장 실패로 오인하지 않는다. 저장 당시 리비전만 ACK하므로 저장 도중 편집한 내용은 dirty로 남는다. 다른 이름 저장은 파일 확정 뒤 활성 경로를 바꾼다. 복제는 새 projectId를 만들고 내부 식별자와 참조를 유지한다. 동일 OS의 일반 로컬 Windows 파일에서 시험했으며 네트워크/클라우드 폴더의 원자성·전원 상실 내구성은 보증 범위 밖이다.

## 복구와 이력

프로필 내부 snapshots는 자급 ZIP이며 catalog에 파일 해시·크기·정상/자동/중요 변경 출처·리비전·확인 여부를 기록한다. write/fsync·재열기 검증을 마친 snapshot이 catalog에 오르기 전에 종료되더라도 재시작에서 발견한다. 알 수 없거나 손상된 파일을 유효 복구본으로 제시하지 않는다. 정리는 소유 UUID 파일과 해시가 일치하는 기록만 삭제한다. 재시도 실패는 30초 간격으로 물러나며 저장 공간 실패를 무한 루프로 재시도하지 않는다.

정상 백업 5개와 자동/체크포인트 5개를 구분하고 프로젝트당 2GiB에서 최신 유효 백업·복구를 보호한다. 파일 교체 성공 전에는 기존 최신본을 보호한 채 용량을 검사한다. 복구본과 원본은 각각 검증한 실제 모델·렌더 scene으로 비교하며 복구 결과는 새 파일에 저장한다.

이력은 의미 있는 변경의 불변 before/after 모델을 최대 100개 보관한다. 연속 조절은 begin/end 토큰으로 한 항목에 묶고 취소는 시작 내용으로 복원한다. redo는 새 확정 편집 시 제거한다. 편집/undo/redo의 리비전은 단조 증가하며 별도의 내용 해시로 저장 내용과 같아졌는지 판정한다. 실시간 프레임/장치 값은 이력과 분리한다. 중요한 구조 변경은 이력과 별도로 영구 checkpoint를 먼저 만든다.

## 화면과 권한

화면에는 basename과 opaque 최근/복구 ID를 전달한다. 프로젝트 이미지 URL은 세션 토큰과 해시로 제한해 검증 캐시 바이트만 읽으며 임의 경로 읽기 IPC를 두지 않는다. 프로젝트 전환 시 이전 token을 회수한다. 복구 비교 token도 다음 비교에서 회수한다. 정상 진단에는 파일 경로·원본 바이트·임의 오류를 넣지 않는다.

새 제작/열기/닫기/창 X/앱 종료는 dirty를 검사해 저장·버리기·계속 편집 중 결정한다. 저장 취소/실패는 전환하지 않는다. 저장/복구와 worker 종료를 기다린 뒤 앱을 끝낸다. [19개 새 검사 및 실제 UI/패키지 근거](../planning/09-project-lifecycle.md)를 따른다. 이후 분석·추적·출력의 전체 통합 시험은 별도다.
