# 실행본 교체·입력 소유권·고정 입력 계약

22단계 · 앱 0.17.0 / 프로젝트 1.9. [사용법·검증 범위](../planning/22-runtime-changes.md).

`packages/execution/changes.ts`는 변경 분류·전환 의도·동시 작업 정책·64MiB 한도·고정 입력 기준을 정의한다. 알려진 제어 필드만 즉시 반영 대상으로 취급한다. 나머지 외형은 수동, 프로젝트/편집 세션과 의미가 달라지는 구조는 실행 상태 재시작을 요구한다. 21단계의 전체 편집 잠금은 이 정책으로 대체한다. 준비 단계의 초기 실행 잠금은 유지한다.

## 실행본 트랜잭션

1. main의 ProjectSession은 실행 소유자·기존 실행 ID·작업 세션/리비전·후보 ID를 확인한다. 현재 작업·연속 조절·저장과 리소스 해시를 검사해 불변 후보와 별도 grant를 만든다. 같은 실행에는 후보 하나만 허용한다.
2. RunSurface는 후보를 별도 canvas/WebGL 컨텍스트에서 로드하고 중립·혼합·극단 입력을 그려 확인한다. 현재 렌더러와 화면은 유지한다. 제어만 바뀌면 기존 텍스처를 그대로 사용한다.
3. 커밋 직전에 main이 작업본 세션/리비전과 기존 실행 ID를 다시 확인한다. 구조 변경은 재시작 확인도 요구한다. 늦은 결과·외부 소유자·새 편집이 있는 후보는 거부한다.
4. 클라이언트는 조작 키를 보류하고 다음 프레임 경계에서 모델·입력 매핑·완성된 canvas를 한 번에 교체한다. 장치 연결은 유지하며, 실행 상태 재시작은 제어·선택 대상을 초기화하고 이전 시각의 입력을 배제한다.
5. 화면 교체 후 이전 grant를 해제한다. 이 확인 전 실행 입력본 캡처는 보류한다. 공개 실패 시 main의 보관 실행본으로 롤백한다. 중지 시 소유자 전체를 해제해 커밋 중인 요청도 남지 않게 한다.

후보와 실행본에는 각각 고유 grant를 사용한다. 편집 프로젝트의 활성화/폐기가 실행 grant를 삭제하지 않는다. 이전 grant는 공개 확인까지만 유지하며 다음 후보 준비는 그 해제를 기다린다. 취소와 중지는 후보 세대를 바꾸어 늦은 이미지 로드/검사 결과를 무효화한다. 오래된 해제 요청은 새 실행을 중지하지 않는다.

## 렌더러와 장치의 수명

RunRuntime 진입점은 `run-runtime.ts`, 제어기는 `run-controller.ts`다. RunSurface와 표시 시계는 실행 소유이며 실행 대화상자를 닫아도 계속 평가한다. React의 RunCanvas는 표시 위치만 바꾼다. 교체/취소/실패/중지에 텍스처·버퍼·프로그램·WebGL 컨텍스트를 정리한다. 검증 후보를 활성 canvas에 덮어 그리지 않는다.

main의 InputOwnership은 편집기와 실행 소유자의 카메라/마이크 권한을 구분한다. 현재 모드에 필요한 입력만 실행 소유자가 확보할 수 있다. 오래된 편집기의 end/frame이나 다른 소유자의 정리는 현재 실행 입력을 회수하지 못한다. 장치 중지 완료를 기다린 후 다시 연결하고, 실행본 교체는 같은 스트림을 새 매핑으로 연결한다. 재시작 경계 이전의 얼굴/음량 표본은 버린다. 장치 손실의 완화/복구 시간은 20단계 계약을 그대로 사용한다.

## 저장·전환·파일 입력

저장은 시작 시 작업본을 고정하고 나중 편집은 미저장으로 남긴다. 작업본/저장본/실행본 리비전과 이름을 UI에서 구분한다. 후속 파일 어댑터는 `InputBasis {source, projectId, revision, fingerprint}`를 명시한다. `runtimeInputBasis`는 선택한 기준을 확인하고 `captureRuntimeInput`은 해당 프로젝트와 해시 검증한 자산 사본을 고정한다. 이후 편집이나 실행 전환이 고정 입력을 최신 내용으로 바꾸지 않는다. 실제 이미지/아바타 내보내기는 24단계 이후다.

프로젝트 전환은 실행 유지/검사 후 전환 의도를 받은 경로만 허용한다. 파일 대화상자 전의 실행 소유자와 미저장 처리 시점의 작업본을 확인한다. 대기 중 실행 세대가 바뀌면 오래된 전환은 실패하며 최신 편집과 새 실행을 보존한다. native 파일/저장 확인 대화상자는 중첩 깊이로 단축키를 보류하고 마지막 대화상자가 닫힌 뒤 복구한다.

미저장 확인에서 저장을 선택했더라도 저장 도중 새 편집이 생기면 전환을 보류한다. 저장한 리비전 이후 편집을 버리지 않고 현재 프로젝트의 미저장 상태로 남긴다. 전환 처리 중에는 화면 편집 입력과 전환 버튼을 잠가 대기하던 명령이 새 프로젝트에 적용되지 않게 한다.

무거운 분석/가져오기/텍스처 준비는 실행 중 보류하며 취소·안전한 편집·작은 파일 저장/열기는 허용한다. 한도와 작업 상태를 main에서 다시 확인해 비활성 버튼 외의 경로도 보호한다. 입력 처리·파일 변환·시각 품질·방송 성능은 별도 계약이며 이번 동시성 통과가 M0나 실제 OBS 지원 승인을 뜻하지 않는다.
