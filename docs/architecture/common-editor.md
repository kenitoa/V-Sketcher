# 공통 편집 화면과 보기 상태

화면은 S-HOME의 세 경로/최근 작업과, 같은 ProjectSession을 사용하는 중앙 편집 작업실로 나뉜다. 준비·외형·저장 전 확인은 같은 프로젝트의 패널이며 화면 전환 자체가 새 프로젝트를 만들지 않는다. 단계 완료는 실제 자료, 명시적 외형 확인 리비전, 현재 입력 리비전의 파일 검사/저장 상태로 표시한다. 이동한 사실만으로 완료로 표시하지 않는다.

## 좌표와 선택

`packages/editor-view`의 viewport 행렬은 프로젝트의 pixel-corner 좌표를 표시 영역에 contain 맞춤한 뒤 배율·이동을 적용한다. CSS canvas 변환과 선택용 역변환이 같은 행렬을 사용한다. 휠 확대는 커서 아래의 프로젝트 점을 보존한다. 보기 상태는 renderer의 로컬 상태이고 Project·편집 이력·방송/내보내기 프로필에 저장하지 않는다.

`AvatarRenderer.hitTest`는 실제 로드한 HTMLImageElement에서 후보 픽셀 알파를 읽는다. GPU와 같은 z/ID 순서를 거꾸로 확인하며 현재 눈/입 상태, 크롭, source-to-edited/부위/계층 변환과 불투명도를 반영한다. 투명한 텍스처 바깥 사각형이 아래 부위 선택을 가로채지 않는다. 선택선·중심/경계 가이드는 별도 SVG이며 GPU scene과 분리한다. 원본 비교는 검증한 첫 원본 자원의 전체 바이트를 같은 프로젝트 캔버스에 맞춘 별도 scene이다.

그림 로드 세대와 준비 여부를 함께 확인해 원본/편집본 전환 중 이전 ready 상태로 새 텍스처를 그리지 않는다. 로드 중 폐기된 renderer는 뒤늦게 GPU 자원을 만들지 않는다. 이전 원본이 없으면 비교를 해제하고 버튼을 제한한다.

## 작업과 상태 전달

ProjectSession은 현재 Workflow의 제한된 JobView를 전달하고 실제 로컬 자원 확인·작업 취소·재시도를 허용한다. 파일 확인은 동결한 입력 모델의 자원 캐시 해시/크기를 읽으며 카메라·마이크·외부 네트워크를 사용하지 않는다. 진행률 숫자가 내부에 있더라도 공통 TaskCard는 측정 단위가 제공되지 않으면 indeterminate로 표시한다. 임의 ETA를 만들지 않는다. 고정 입력 개발 시험과 실제 파일 검사를 화면에서 구분한다.

상태 응답에는 host가 만든 단조 증가 sequence를 포함한다. IPC 변경 이벤트가 더 최신 invoke 응답 뒤에 도착해도 화면이 과거의 저장 중/프로젝트 상태로 돌아가지 않는다. 편집 명령은 renderer 큐와 현재 리비전으로 적용하고 실제 변경/저장은 기존 세션의 보존 계약을 따른다. sequence와 보기 상태는 프로젝트 파일의 일부가 아니다.

## 안내와 키보드

오류 코드의 안내 모델은 심각도·원인 요약·영향·보존 상태·권장 행동을 제공한다. 기술 코드는 접힌 상세에 두고 원시 예외·개인 경로는 표시하지 않는다. 알려진 오류는 다른 위치 저장/다른 파일/부위 설정/자원 연결로 안내한다. 모르는 원인을 임의로 권한 오류 등으로 바꾸지 않는다.

공통 Modal은 portal로 root 밖에 표시하고 배경을 inert로 둔다. 초기 초점·Tab/Shift+Tab 경계·Escape·호출 위치 복귀를 관리한다. 새 문서로 화면이 바뀌면 현재 단계 제목으로 초점을 보낸다. 모달 안에서는 작업실의 저장/열기 전역 키를 처리하지 않는다. 주요 작업은 native button/input/select를 사용하며 색과 함께 문자·체크·현재/완료 상태를 제공한다. skip link와 미리보기 키보드 대체를 제공한다.

대비 수식/표본 검사·실제 화면/패키지·한계는 [10 완료 근거](../planning/10-common-editor.md)를 따른다. 전체 보조공학·초보자·출시 접근성 검증은 후속이다.
