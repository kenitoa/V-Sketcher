# 비동기 작업·변경 트랜잭션·상태 관리

`packages/workflow`는 공통 모델 1.0 위에서 동작하는 실제 작업/편집 제어기입니다. `packages/workflow-host`는 호스트 전용 자식 프로세스와 임시 파일 소유권을 구현합니다. renderer에는 호스트 파일/프로세스 API를 노출하지 않습니다. 입력 분석·파일 저장 어댑터의 실제 제품 연결은 후속 작업이며, 이번에는 고정 입력과 모의 작업 및 실제 자식 프로세스로 제어 규칙을 검증했습니다.

## 상태와 입력 고정

project/save/preparation, camera/microphone, tracking/runtime/output, external/compatibility/files는 독립 상태입니다. `can`은 행동별 최소 조건을 검사합니다. 마이크 거부나 저장 실패가 카메라·이미지·내보내기 판단을 일괄 차단하지 않습니다. 상태 값은 실제 장치 동작을 대신하지 않으며 현재 장치 어댑터는 연결하지 않았습니다.

`start`는 실행 시점이 아닌 **요청 시점**의 프로젝트와 설정을 복사해 깊게 freeze합니다. 작업 식별자는 protocol 1, jobId, projectId, inputRevision, generation, processingVersion입니다. 작업 단계도 ID/버전/캐시·취소 정책을 고정합니다. 결과는 이 식별자를 모두 검사한 후 사용합니다. UI나 이전 작업의 편집이 입력본에 섞이지 않습니다.

동일 종류/operation key의 진행·보류 작업은 중복 생성하지 않습니다. 같은 요청은 기존 ID를 반환하고, 입력 리비전·설정·처리/단계 버전이 달라진 요청은 `E_JOB_ACTIVE_CHANGED`로 구분합니다. 준비·저장·내보내기·검사·미리보기 종류별로 한 실행을 진행하고 같은 종류의 다음 작업은 대기합니다. 무거운 분석과 방송의 실제 자원 경쟁을 검증한 동시 실행 보증은 아닙니다.

## 진행·취소·재시도

QUEUED → RUNNING → RESULT_READY → SUCCEEDED를 사용합니다. 각 단계의 실제 시작과 단조 증가 진행값을 표시하며, 결과 검증/정리 전에는 완료로 표시하지 않습니다. 종료된 단계의 지연 progress는 무시합니다. 단계 하나의 JSON 결과/설정은 최대 256KiB, 결과 합계는 1MiB, 단계는 32개·기억하는 작업은 32개까지입니다. 영상/이미지 바이트를 이 제어 데이터에 넣지 않습니다.

취소는 CANCEL_REQUESTED를 먼저 알리고, 지원되는 경계에서 중단한 다음 소유 자원을 정리해 CANCELLED로 바꿉니다. 중단 불가 단계에서는 AbortSignal과 중간 checkpoint로 작업을 끊지 않고 단계 종료를 기다립니다. 결과 적용 직전 취소를 다시 판정합니다. 이미 커밋된 SUCCEEDED는 뒤늦게 취소로 바꾸지 않습니다.

어댑터는 `checkpoint`, AbortSignal, `own(cleanup)` 계약을 지킵니다. 정리는 역순이며 성공한 정리 함수는 반복하지 않습니다. 정리 실패는 `E_RESOURCE_CLEANUP`으로 남기고 실패 핸들을 보존합니다. `retryCleanup`으로 정리를 재시도할 수 있으며 자원이 남은 작업을 정상 취소 완료로 표시하지 않습니다. 종료도 정리 실패를 전파하며 해결 후 다시 완료할 수 있습니다. 응답 없는 비협조적 Promise를 강제로 종료했다고 표시하지 않습니다. 프로세스 어댑터는 취소 시 자식을 종료하고 close까지 기다립니다.

재시도는 새 jobId로 시작합니다. 동일 프로젝트·세대·입력 리비전·처리 버전에서 완료된 **순수 JSON 캐시 단계의 연속 앞부분**만 재사용하고 실패 단계부터 다시 실행합니다. 입력이 바뀌었으면 최신 입력으로 처음부터 시작합니다. 파일/프로세스 소유권이나 임시 파일 경로를 캐시로 재사용하지 않습니다. 실제 분석 중간 파일의 재사용/승격은 후속 어댑터가 추가 검증해야 합니다.

## 원자적 편집과 결과 검토

`transaction(before, after)`는 안정된 컬렉션 ID와 필드별 before/after 슬롯으로 변경 단위를 만듭니다. 프로젝트 ID·생성 시각·입력 경로·스키마·저장 리비전은 일반 결과 패치로 바꿀 수 없습니다. 적용은 expectedRevision의 CAS와 전체 참조/스키마 재검증을 통과한 복사본을 한 번 교체합니다. 실패하면 현재 모델을 바꾸지 않습니다.

같은 프로젝트/세대이지만 입력 리비전이 달라진 준비 결과는 **AWAITING_REVIEW**에 둡니다. 다른 프로젝트/세대·취소·위조 식별자의 결과를 현재 프로젝트에 적용하지 않습니다. 05의 단순 stale 폐기 정책은 T-076/077·Function 3.2/4.2의 구체 요구에 따라 “자동 적용 차단 후 보류”로 상세화했습니다. 이전 실험/정책 파일은 당시 기록으로 보존합니다. `packages/jobs`의 06 packet gate는 새 준비 결과 제어 경로에서 사용하지 않습니다.

비교는 각 변경을 safe/conflict/already로 나눕니다. 현재 값이 입력 전 값과 같으면 안전하게 적용하고, 이미 결과와 같으면 중복 편집하지 않습니다. 사용자 보정과 겹친 값은 강제로 덮어쓰지 않습니다. 사용자는 안전한 항목만 선택 적용·재검증·폐기·최신 입력 재실행할 수 있습니다. 삭제 참조 등 전체 검증 실패이면 보류를 유지합니다. 비교 후 다시 편집됐으면 적용을 거부하고 최신 비교가 필요합니다. 적용 버튼 중복 호출도 한 번만 허용합니다.

적용 직전 정상 프로젝트를 최대 5개의 메모리 체크포인트로 보존합니다. 이 체크포인트는 09의 영구 복구/undo 기록이 아닙니다. 취소/정리 대기 중 생긴 추가 편집도 적용 직전 다시 검사합니다. 저장/내보내기의 고정 입력 완료 메타데이터는 최신 편집 리비전으로 바꾸지 않습니다. 이번 저장/내보내기 시험은 **고정 모의 receipt**이며 실제 파일 확정 성공을 입증하지 않습니다.

## 의존 결과와 실행본

`DerivedRegistry`는 `domain:entityId` 및 `domain:*`의 변경 세대를 보관합니다. 이름은 외부 이름/결과 메타데이터, 역할·부모는 해당 부위/자식의 구조·연결·실행/호환, 이미지 내용은 관련 자산/파생/부위, 표정은 관련 표정/실행/외부 검사에 영향을 줍니다. 장치·입력 보정은 내보내기 외형을 무효화하지 않고, 방송/외부 대상 설정은 해당 프로필 검사에만 영향을 줍니다. 경로만 이동하면 리소스 확인을 갱신합니다.

이전 정상 결과를 삭제하지 않고 STALE로 표시합니다. 검사 작업은 시작 당시의 의존 세대를 결과에 연결하므로 처리 중 변경된 내용을 새 PASS처럼 등록하지 않습니다. `refreshStaleChecks`는 등록된 검사 중 stale 항목만 다시 실행합니다. 최초 미검사 항목은 명시적으로 시작합니다.

편집본과 `runtimeSnapshot`은 분리됩니다. 편집·실패·보류가 실행본을 바꾸지 않습니다. 검증한 현재 입력으로 `stageRuntime`한 뒤 실제 프레임 경계에서 `publishAtFrameBoundary`를 호출합니다. 그 사이 편집되면 대기본을 폐기하고 정상 실행본을 유지합니다. 프로젝트 전환은 먼저 적용 세대를 회수한 다음 작업/정리를 기다리며 실행본을 keep/stop할 의도를 명시합니다. 기본 고급 샘플도 이 실행 스냅샷을 사용합니다. 완전한 SceneSnapshot/망·장치/OBS 통합은 후속입니다.

호스트 ScratchLease는 전용 새 폴더와 직접 만든 파일만 소유합니다. 상대 파일명·실제 범위를 확인한 후 소유 파일만 unlink하고, 폴더는 비었을 때만 rmdir합니다. 재귀 삭제나 무관한 사용자 파일 정리를 하지 않습니다. 알 수 없는 파일이 남으면 정리 실패로 안내합니다. 분석 결과의 임시 자원을 영구 리소스로 승격하는 기능은 아직 없습니다.

## 검증과 다음 연결

`tools/dev.cmd run check`는 기존 포함 42개 Node/3개 Python 검사 그룹을 실행합니다. `node scripts/verify-workflow.mjs`는 같은 검사와 실제 Electron의 고정 입력 비교/선택 적용/취소 UI, GPU/worker/실행 스냅샷을 확인해 phase08 증거를 남깁니다. 개발/시험 빌드의 “작업 상태 시험”은 독립된 샘플 복사본을 사용하며 기본 release에는 표시하지 않습니다. 실제 분석·파일 저장이 아니라는 안내를 표시합니다.

실제 준비/저장/장치/출력 어댑터와 통합한 취소·재시도·전환·지연 응답은 T-268, 디스크 공간/권한/경로 오류와 마지막 정상본 보존은 T-271로 남깁니다. T-080의 완료로 이 작업들을 체크하지 않습니다. M0 HOLD와 기존 5개 추가 검증을 유지합니다.
