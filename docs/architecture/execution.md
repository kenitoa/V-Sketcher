# 실행본·준비 검사·단축키 계약

21단계 · 앱 0.16.0 / 프로젝트 1.9. [사용법과 검증 범위](../planning/21-execution.md).

`packages/execution`은 모드·차단/경고·문제 위치·PC 설정의 엄격한 계약을 정의한다. ProjectSession이 세션/리비전 CAS와 진행 작업을 검사하고 사용 텍스처의 크기/해시를 다시 읽은 뒤 실행 lease를 발급한다. 비동기 검증 중 취소하면 세대 번호가 바뀌어 오래된 lease는 발행되지 않는다. 실행본 JSON은 복제·동결하며 고유 grant로 리소스를 읽는다. 다른 요청의 해제는 무시한다. 모든 편집 명령과 파일 드롭은 준비/실행 lease 중 `E_RUN_ACTIVE`로 거절하며, 22단계의 동시 편집 기능을 선행 완료로 세지 않는다.

`RunRuntime`은 편집용과 별도의 MotionPlayer·CameraRuntime·MicrophoneRuntime을 소유한다. 시작 전 편집 입력을 정리하고 실행본의 실제 GPU 로드를 기다린 뒤 필요한 장치만 연결한다. 별도 표시 시계가 추적 콜백 없이도 입력 만료·복구를 평가한다. 시작·정상·제한·종료·실패 상태는 실제 리소스 상태와 연결하며 보정/얼굴 없음·수신 만료·경고가 있으면 제한으로 표시한다. 유효 마이크 무음은 입력 실패가 아니다. 숨김은 alpha 0이며 장치 정지가 아니다. 렌더 실패·시작 취소·장치 실패는 중지와 동일한 정리를 거친다. 늦은 완료는 요청 세대로 제외한다.

기본 자세 고정은 매개변수의 작성된 pose/neutral을 공통 제어 평가의 시험 계층에서 강제한다. 저장 표정 선택을 삭제하지 않는다. 자동 눈 깜빡임은 실행 평가 옵션이며 프로젝트 설정을 수정하지 않는다. 실행본 표정 슬롯은 프로젝트의 기존 설정을 사용한다.

Electron main만 `globalShortcut`을 소유한다. 전역 등록은 활성 lease·활성 동작·명시적 PC 전역 허용·해당 바인딩의 전역 선택을 모두 요구한다. register 결과와 isRegistered를 확인한다. 자신이 확보한 키만 해제하며 `unregisterAll`을 호출하지 않는다. 등록 예외도 안전한 상태 코드로 처리한다. IPC는 원본 주 창의 sender만 허용하며 실행 활성 동작은 renderer 제출 값이 아닌 서버 lease에서 계산한다.

앱 전용 키는 renderer의 실제 초점/입력 대상/IME/반복/키 설정 검사를 거친다. 전역 콜백은 요청 ID와 동일한 보호 조건을 다시 검사한다. main의 텍스트/IME 보류는 주 창 초점일 때 적용하고 키 설정·native 저장 확인은 초점에 관계없이 보류한다. key-edit 화면은 main 보류 응답을 기다린 후 연다. 단축키 내용은 일반 로그에 기록하지 않는다. PC 설정 `machine/execution.json`은 16KiB 상한·엄격한 필드·8개 고정 동작·원자적 교체를 사용한다.

자동 UI의 KeyboardEvent·합성 MediaStream·등록 API 상태와 실제 OS 키 배달은 별도 근거다. live 키 시험은 주 창 밖 시험 창 초점과 실제 전역 콜백 뒤 숨김/앱 전용 기본 자세 미발동·중지 후 소유 키 해제를 계측한다. 키 입력 원문·카메라 프레임·PCM·개인 경로·원시 오류는 정상 로그나 근거 JSON에 저장하지 않는다.
