# 장애·복구·보안 문제 대응

현재는 비공개 로컬 시험판이며 공개 지원 창구·상시 대응 인력이 지정되지 않았다. 이번 시험을 안내한 프로젝트 담당자가 접수·재현을 맡고, 출시 결정 담당자가 수정 후보·고지·배포 여부를 별도로 검토한다. 담당자가 정해지지 않은 역할을 자동 시스템이나 가상의 연락처로 대신하지 않는다. 자동 전송은 없다.

## 접수할 정보

기록 동의를 먼저 확인한다. 익명 사건 번호, 앱 버전, 제작 경로, 단계, 화면 오류 코드, 증상 종류, OS 빌드·아키텍처·GPU 업체·장치 종류·OBS/외부 실행기 버전만 정상 기록에 넣는다. 정확한 장치 ID·PC 이름·연락처·프로젝트 이름·개인 경로·로컬 방송 주소·인증정보·원본 오류 문자열·얼굴 프레임·음성 PCM은 넣지 않는다. 알 수 없는 값은 미상으로 남기고 환경별 실패율의 분모에서 삭제하지 않는다.

[피드백 양식](feedback.md)을 사용한다. 환경 설정의 최소 진단도 내용을 먼저 확인한 뒤 직접 전달한다. 원본 프로젝트가 재현에 꼭 필요하면 담당자가 목적·범위·보관·삭제·비공개 전달 경로를 정하고 별도 동의를 받은 후에만 받는다. 비공개 채널이 지정되기 전 민감 파일을 접수하지 않는다. 공개 이슈에 비밀을 적지 않는다.

## 심각도와 우선 조치

| 등급 | 기준 | 조치 |
|---|---|---|
| P0 | 정상 저장본 손실·원본 덮어쓰기·개인정보/보안 노출 | 관련 시험/배포를 즉시 보류하고 원본을 보존한다. 장치·로컬 출력을 해제하고 노출 범위를 확인한다. 공개 로그/화면에 민감 자료를 더 복사하지 않는다. 필요한 인증정보 변경은 사용자가 해당 계정에서 수행한다. |
| P1 | 앱 시작·저장·지원 경로 사용·방송·내보내기 차단, 얼굴 검출 불가 | 영향 경로/버전/환경을 고정하고 지원 제외와 임시 우회를 알린다. 배포 차단 여부를 출시 담당자가 검토한다. |
| P2 | 성능 저하·제한된 입력 반응 등 우회 가능한 기능 문제 | 재현 조건·부하·측정 범위를 기록하고 품질/FPS를 낮춘 비교나 장치 없는 실행을 시험한다. 측정하지 않은 전체 지연을 추정하지 않는다. |
| P3 | 용어·안내·시각적 혼동 | 막힌 과제·안내 변경·같은 과제 재관찰을 연결한다. 개발자 대신 조작을 성공으로 세지 않는다. |

이는 우선순위 정책이다. 24시간 지원이나 응답 시간 보증을 뜻하지 않는다. 데이터 손실/보안 문제를 단순 안내 문제로 낮추지 않는다.

## 저장본과 업데이트 복구

1. 원본과 마지막 정상 저장본을 먼저 보관한다. 공간·쓰기 권한을 확인하고 **다른 이름/다른 폴더의 사본**으로 재시도한다.
2. 앱을 재실행해 복구본과 원본을 비교한다. 확신이 없으면 복구 결정을 미루고 원본을 삭제하지 않는다. 강제로 캐시나 앱 데이터를 지우지 않는다.
3. 업데이트는 종료 후 새 버전을 **다른 폴더**에 압축 해제한다. 기존 앱 폴더에 덮어쓰지 않는다. 손상되거나 불완전한 ZIP을 실행 후보로 선택하지 않는다.
4. 새 버전에서 이전 프로젝트 **사본**을 확인한다. 실패하면 이전 앱 폴더와 **변경 전 원본 백업**으로 돌아간다. 새 버전이 저장한 파일을 이전 앱에서 읽을 수 있다고 보장하지 않는다.
5. 현재 검증한 조합은 0.21.0 → 0.22.0, 공통 프로젝트 스키마 1.9다. 미래 minor는 읽기 전용, 미래/다른 major는 차단한다. 원본을 조용히 낮은 버전으로 변환하지 않는다.

## 재현부터 종료까지

`NEW → TRIAGED → REPRODUCING → MITIGATED/FIX_VERIFIED → RELEASE_REVIEW → RELEASED → CLOSED`로 기록한다. 재현 불가·자기보고·미확인을 구분하고 실패한 실행도 보관한다. 알려진 카메라 검출 0명 문제는 해결되지 않았다. 장치 없이 작업하는 우회는 수정 완료를 뜻하지 않는다.

수정 검증에는 정확한 빌드/ZIP 해시·프로젝트 리비전·입력/장치·외부 프로그램 버전, 수정 전 재현, 영향받은 제작 경로/외부 대상의 재시험, 회귀 검증이 필요하다. 데이터/보안 수정은 저장본 보존과 정상 기록의 민감 값 제외도 재검증한다. 릴리스 안내와 복구 절차가 준비돼야 출시 검토에 올린다. 전체 출시 게이트가 HOLD이면 배포 상태로 바꾸지 않는다. 실제 배포하지 않은 수정을 ‘업데이트 제공 완료’로 표시하지 않는다. 배포 후 사용자 또는 동일 재현에서 확인한 다음 종료하며 재발 시 다시 연다.

현재 저장소 규칙은 로컬 작업에서 게시·서명·배포를 금지한다. 이 절차 문서와 로컬 점검은 운영 중 사고 접수·실제 수정 배포의 대체 증거가 아니다.
